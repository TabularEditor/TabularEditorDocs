## Improvements in 3.27.1.0

- The [AI Assistant](https://docs.tabulareditor.com/en/features/ai-assistant.html) and agents connected through the [MCP server](https://docs.tabulareditor.com/en/features/mcp-server.html) now receive the DAX errors in your model and in open documents:
  - the new `get_model_messages` tool lists the errors, warnings and Analysis Services messages that the **Messages** view shows
  - the new `get_document_messages` tool lists the errors and warnings of an open DAX query, DAX script, C# script or Pivot Grid, and the active document is part of the assistant's context
  - after a C# script runs, the result lists the errors the script introduced or resolved

  Error text returned by Analysis Services can contain model data, and it's shared only when the **Model data** permission is set to **Read**. See the [MCP tool reference](https://docs.tabulareditor.com/en/features/mcp-server.html#tool-reference).
- **DAX Query** and **Pivot Grid** documents now stay open when you open a different model, and they connect to the new model. A DAX query keeps its text and unsaved changes. A Pivot Grid keeps its layout and drops fields the new model doesn't have. Turn this off with **Keep DAX Queries open when a different model is opened** and **Keep Pivot Grids open when a different model is opened** under **Tools > Preferences > Data Browsing**. See [DAX queries: switching models](https://docs.tabulareditor.com/en/features/dax-query.html#switching-models) and [Pivot Grids: switching models](https://docs.tabulareditor.com/en/features/pivot-grid.html#switching-models).
- **Model > Deploy...** has a new **Deploy Linguistic Metadata (Q&A Synonyms, AI Instructions and AI Data Schema)** option, selected by default. Clear it to keep the AI instructions, AI data schema and Q&A synonyms already set up on the destination semantic model. See [Deployment options](https://docs.tabulareditor.com/en/features/deployment.html#deployment-options).
- Right-click a server in the **Server** list of **File > Open > Model from DB...** or the deployment wizard to **Pin**, **Unpin** or **Delete** it. Pinned servers stay at the top of the list and aren't removed by **Clear recent servers**. See [Recent and pinned servers](https://docs.tabulareditor.com/en/how-tos/xmla-as-connectivity.html#recent-and-pinned-servers).
- The window title now starts with the model name. The **Model source detail** preference under **Tools > Preferences > Tabular Editor > User Interface** replaces **Hide model source details** and sets how much of the model's location the title bar, status bar, tab tooltips and recent lists show. The status bar shows the connection as `<database>@<server>`. See [User Interface preferences](https://docs.tabulareditor.com/en/references/preferences.html#tabular-editor--user-interface) and [Tabular Editor 3 user interface](https://docs.tabulareditor.com/en/features/views/user-interface.html#basic-user-interface-elements).
- The **Messages** view has a **Caused by** column that names the object causing a cascading error, and the error that causes others shows **+N dependent errors**. Right-click an error to clear **Show Cascading Errors** or to choose **Go to Root Cause**. See [Cascading errors and root causes](https://docs.tabulareditor.com/en/features/views/messages-view.html#cascading-errors-and-root-causes).

## Bugfixes in 3.27.1.0

- Fixed an issue where setting a calculation item's **Ordinal** to move it toward the end of its calculation group placed it one position too early.
- Fixed an issue where **File > New > Model...** applied the chosen name to the model only and left the database named `SemanticModel`.
- Fixed an issue where an invalid culture name was accepted for a model's **Culture** and a translation's **Language** property. These values are now rejected with an error such as `'en US' is an invalid culture specifier`.
- Fixed an issue where comparing two models failed with `Object reference not set to an instance of an object` when they differed in role members, query groups or other unnamed collection elements.
- Fixed an issue where a non-standard whitespace character in a DAX expression, such as a no-break space, wasn't reported. It's now reported as an error that names the character and tells you to run **Format DAX**.
- Fixed issues in the **Metadata Translation Editor**:
  - clearing a translation cell had no effect; it now removes the translation
  - the **Display folder** cell of a table, a hierarchy level, a perspective or the model was editable and the value was discarded; these cells are now read-only
  - the column header context menu offered **Show Auto Filter Row**, which didn't work on translation columns
- Fixed an issue where closing the **Import Table Wizard** while it listed tables could show an error report dialog or leave objects missing from the tree.
- Fixed an issue where cancelling the **Load Semantic Model from Database** dialog or the data source credentials prompt could close Tabular Editor and lose unsaved work.
- Fixed issues where **Debug this value** on a **Pivot Grid** value ignored or reversed some of the grid's filters, so the debugger showed a different value than the grid.
- Fixed an issue where a document opened by an MCP client while Tabular Editor wasn't the active window showed the previous document's toolbar and menu. Reported in [GitHub discussion #1590](https://github.com/TabularEditor/TabularEditor3/discussions/1590).
- Fixed an issue where duplicating or pasting a measure, column or hierarchy shown in several display folders put the copy in one folder named after all of them, such as `folder_01;folder_02`. The copy now appears in every display folder of the original.
- Fixed issues in the **DAX Query** editor where running one of several queries in a document used the first query's `DEFINE` block, and executing a selected column in an `ORDER BY` clause failed with `A single value for column ... cannot be determined`.
- Fixed an issue where the **Messages** view stopped listing the errors of documents that stayed open after a different model was opened.
- Fixed issues that could close Tabular Editor 3 unexpectedly or show an error dialog:
  - while the **Properties** view showed a measure, or when its selected object was deleted
  - when opening a semantic model, with a "Cannot access a disposed object" error
  - after an edit that deleted an object with a DAX expression and renamed or added another object
  - while you edited a DAX expression, with an "Index was outside the bounds of the array" error
- Fixed an issue where a legacy data source using a version-specific OLE DB provider name, such as `Provider=MSOLEDBSQL19.1`, was reported as not installed and the **Data Link Properties** dialog opened without the original provider. The issue was introduced in 3.25.0.
- Fixed an issue where **VertiPaq Analyzer > Collect Stats** returned no statistics when the model's data couldn't be scanned. Statistics are now collected from model metadata with a warning, and clearing **Read statistics from data** under **Tools > Preferences > File Formats > VertiPaq Analyzer** skips reading data.

## Coming from Tabular Editor 2.x?

For a tour of the main features in Tabular Editor 3, watch [this video](https://youtu.be/O4ATwdzCvWc). To get started, see the [onboarding guide](https://docs.tabulareditor.com/onboarding/index.html).

**Main features of Tabular Editor 3:**
- Customizable IDE with multi-monitor and Hi-DPI support and themes
- DAX code editor with auto-complete, syntax checking, code folding and formatting
- *Workspace mode, which saves your changes to disk and synchronizes model metadata to Analysis Services at the same time
- *Preview table data with infinite scrolling, create PivotGrids or write DAX queries to browse the model or test calculation logic
- *Schedule data refreshes
- Update table schema on both provider and structured data sources, including M queries
- Create data model diagrams
- Create DAX scripts to edit multiple measures or other calculated objects in a single document
- Record C# scripts and save them as macros (formerly "Custom Actions")
- VertiPaq Analyzer integration
- DAX debugger
- DAX Optimizer integration
- Code Actions to refactor your DAX

*=Only while connected to an instance of Analysis Services or Power BI
