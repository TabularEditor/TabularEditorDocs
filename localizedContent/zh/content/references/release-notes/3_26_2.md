## 3.26.2 中的改进

- 在 TOM Explorer 中，表格的右键菜单新增了 **移动到组** 子菜单。该子菜单会列出现有的表格组、用于根据所选表格创建新组并打开名称编辑器的 **（新建...）** 项，以及用于移除表格组分配的 **（无）** 项。

- AI Assistant 偏好设置中的模型预设已更新为最新发布版本，用户无需输入自定义模型 ID，即可选择当前模型。新增了 Anthropic 的 `claude-fable-5` 和 `claude-opus-4-8`，以及 OpenAI 的 `gpt-5.5`/`gpt-5.5-pro` 和其他当前的 GPT-5 变体。已移除弃用条目（例如较旧的 Codex 变体），默认 OpenAI 模型现为 `gpt-5.5`。

- **Semantic Analyzer 改进**
  - 新增了对 DAX UDF 中带默认表达式的可选参数的支持。
  - 当调用 UDF 时传入的参数与其声明类型不匹配（例如向 `TABLEREF` 参数传递标量值等）时，Semantic Analyzer 现在会发出相应的警告或错误信息
  - 语义分析器现在会在 `IGNORE` 未直接作为 `SUMMARIZECOLUMNS` 的表达式参数使用时报告错误，与引擎行为保持一致。
  - 语义分析器现已支持 Power BI Desktop 2026 年四月版为 `NAMEOF` 函数引入的新可选组件参数和转义参数。有效的组件关键字为 `TABLE`、`COLUMN`、`MEASURE`、`CALENDAR`、`FULL`、`SELF`、`PARENT`；有效的转义关键字为 `ESCAPED`、`UNESCAPED`、`MINIMALLYESCAPED`。返回类型保持不变（标量字符串）。例如，`EVALUATE { NAMEOF([MyMeasure], TABLE, MINIMALLYESCAPED) }` 会返回完全限定度量值引用中的表名部分。 <br/><br/>

- **Semantic Bridge 改进**
  - 导入 Databricks Metric View 现在会将该视图的元数据一并带入语义模型。
    - `comment` 会成为模型、维度和度量值的描述。
    - `display_name` 会成为 TOM 模型中面向用户显示的“名称”；如果未定义 `display_name`，则回退为 `name`。
    - 度量值和维度的 `format` 会转换为 TOM FormatString，并根据该格式推断生成的列或度量值的 DataType（货币、百分比、日期等）。对于没有明确 TOM 对应项的格式规范，系统会回退到合理的默认值，并发出警告。
  - SQL 到 DAX 的翻译已改进：行数统计（`COUNT(*)`）、`MEASURE(name)` 度量值引用、二元运算、字面量（包括 `NULL` -> `BLANK()`）、将 `/` 映射为可安全处理空白值的 `DIVIDE`，以及括号的运算优先级等，现在都能正确转换。
    - 不在已识别范围内的表达式仍会回退为原始 SQL，并附带警告。
    - 翻译后的 DAX 仅供参考——部署前先检查并验证。
  - 新增对带嵌套联接的雪花架构的支持。
  - YAML 反序列化现在在顶层同时接受 `fields:` 和 `dimensions:`：Databricks v1.1 规范将它们视为别名。往返转换会保留源 YAML 使用的关键字。在 TE3 中创建的视图（没有源 YAML）对于 v1.1 及更早版本默认使用 `dimensions:`：`fields:` 这一别名是在 v1.1 规范发布后才引入的，因此我们保持与面向原始 1.1 规范的工具兼容。当 v1.1+ 视图使用 `dimensions:` 时，会显示反序列化警告（该规范在 v1.1+ 中将 `fields:` 标记为首选）；同样地，当 v1.1 之前的视图使用 `fields:` 时，也会显示对应的警告。
    - C# Script 脚本接口将 `Dimension` 重命名为 `Field`（`view.Fields`、`view.AddField`、`Dimension` -> `Field`、`MakeValidationRuleForDimension` -> `MakeValidationRuleForField`、`ctx.DimensionNames` -> `ctx.FieldNames`）。
    - 旧名称仍作为已弃用的转发项保留，可继续编译和运行，但会显示弃用警告，因此现有脚本以及诸如 `Model.Dimensions["x"]` 之类的已保存路径仍可正常使用。
  - 窗口度量值（包括 v1.1 的 `offset:` 字段）在 YAML 反序列化和序列化之间往返时都会保留。对于规范标记为实验性的功能，我们暂不进行翻译；YAML 往返会保留这些内容，避免丢失。
  - 在更新后的 v1.1 规范中，联接现已支持两个新属性：
    - 支持 `rely:` 映射
    - `cardinality:` 字段在往返过程中会保留两种规范值（`many_to_one`、`one_to_many`）以及省略该字段的形式。遇到未知值时，会回退为 `many_to_one` 并发出警告。
      - 声明为 `cardinality: one_to_many` 的联接仍会被导入，但会刻意跳过与源表的关系——v1.1 规范将这类联接视为在源粒度上分别聚合的独立事实源。
        仍会创建联接后的表，使其出现在生成的 TOM 模型中，但不会定义任何关系。每个受影响的联接都会显示一条警告，说明这一差异。

## 3.26.2 缺陷修复

- 修复了 AI 聊天在 Anthropic Claude Opus 4.7+ 和 Fable 5 上因不再支持 `temperature` 采样参数而失败，并显示 `BadRequest` 错误（“temperature is deprecated for this model”）的问题。用于在未显式指定 temperature 时自动重发请求的重试逻辑，现在除了此前已处理的情况外，也能识别该提供商的措辞。

- 在 `NAMEOF` 和 `TABLEOF` 函数的自动补全建议中，除了表、列和度量值外，现在也会显示日历。其中也包括尚未配置时间单位列的日历（例如刚添加、尚未配置的日历），这些日历此前会被遗漏。输入带引号的前缀（例如 `'My Cal`）后，现在会像表一样，将建议范围缩小到匹配的日历。

- 表 **数据预览** 中的排序和分页现在在各种存储模式下都更加可靠：

- 按没有属性层次结构的列排序时，不会再以错误的顺序返回行。在可能的情况下，分页现在会使用 `WINDOW` 函数（适用于支持该函数的引擎，以及具有主键的表）；否则，预览将显示前几行，并提示无法滚动。

- 属性层次结构的可用性现在直接从服务器读取，因此即使模型在 Tabular Editor 之外处理过，相关信息也依然准确。

- DirectQuery 表现在会正确显示前几行（DirectQuery 不支持分页），并附带一条信息。

- 预览元数据会在当前会话期间缓存，只有在你点击 **刷新** 时才会更新，从而避免不必要的服务器往返请求（包括重复的行数查询）。

- 当无法根据模型解析所属表时，DAX 格式化程序不再从 `DEFINE MEASURE` 块中移除表限定符。此前，这可能会把有效的 `MEASURE 'Sales'[Amount] = ...` 变成无效的 `MEASURE [Amount] = ...`，导致该语句失效。

- 当筛选器移除函数（`ALL`、`ALLSELECTED`、`REMOVEFILTERS` 或 `ALLCROSSFILTERED`）用作 DAX 用户定义函数的顶层主体表达式时，语义分析器不再误报错误；例如 `FUNCTION F = () => REMOVEFILTERS('Sales')`。这类 UDF 在作为 `CALCULATE` 的筛选器参数调用时是有效的。无效用法仍会在调用位置报出，而关系修饰符（`CROSSFILTER` / `USERELATIONSHIP`）和 `KEEPFILTERS` 作为 UDF 主体时仍然无效，这与引擎行为一致。

- 当重命名在 `NAMEOF` 函数调用中被引用的表时，公式修复功能现在会正确更新该表引用。

- 当 `TABLEOF(...)` 作为表引用参数传递给 `ALL`、`ALLEXCEPT`、`ALLSELECTED`、`ALLNOBLANKROW`、`ALLCROSSFILTERED` 或 `REMOVEFILTERS` 时，语义分析器不再误报错误。

- 在同时选中多种对象类型时调用 **更新表架构** 操作，或在表格组上调用该操作时，现在都能正确执行。

## 从 Tabular Editor 2.x 迁移过来？

**Tabular Editor 3 主要功能概览：**

- 完全可自定义的 IDE，支持多显示器、Hi-DPI 和主题切换
- 全新的强大 DAX 代码编辑器，具备自动完成、语法检查、代码折叠等众多功能
- \*工作区模式，可将更改保存到磁盘，并同时将模型元数据同步到 Analysis Services
- \*通过无限滚动预览表数据，创建 PivotGrid，或编写 DAX 查询来浏览模型或测试计算逻辑
- \*设置数据定时刷新
- 同时更新 Provider 和 Structured数据源的表架构（没错，连 M 查询也支持！）
- 创建 Data model 图
- 创建 DAX 脚本，使您能够在单个文档中编辑多个度量值或其他计算对象
- 录制 C# Script 并保存为宏（以前称为“自定义操作”）
- VertiPaq分析器集成
- DAX调试器
- 集成 DAX优化器
- 代码操作：轻松重构你的 DAX 代码。

\*=仅在连接到 Analysis Services 或 Power BI 实例时可用
