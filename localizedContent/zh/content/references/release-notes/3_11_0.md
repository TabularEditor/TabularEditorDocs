### 先决条件

Tabular Editor 3.3.0（及更高版本）使用 .NET 6。在启动 Tabular Editor 3.3.0（或更高版本）之前，你可能需要先安装[适用于桌面的.NET 6.0 运行时](https://dotnet.microsoft.com/en-us/download/dotnet/6.0/runtime)。从 3.3.1 开始，如果缺少这些先决条件，Tabular Editor 3 安装程序会自动下载并安装它们。

## 3.11.0 新增功能

查看我们的[发布博客](https://blog.tabulareditor.com/2023/09/25/september-release-tabular-editor-3-11-0/)，快速了解此版本最重要的更新内容。

- 正如我们在[上个月的发布说明](xref:release-3-10-1)中提到的，此前 Tabular Editor 无法从零开始创建 [Direct Lake Dataset](https://learn.microsoft.com/en-us/power-bi/enterprise/directlake-overview)。现在已支持！唯一的前提是：模型尚未定义任何表或显式数据源，且其兼容模式设置为 PowerBI。如需了解更多，请参阅我们的[DirectLake 博客文章](https://blog.tabulareditor.com/2023/08/23/fabric-direct-lake-dataset/)。

> [!WARNING]
> 一旦你通过 XMLA endpoint 对 Direct Lake Dataset 进行任何更改，你将[无法再在 Fabric 的 Web 建模功能中打开该 Dataset](https://learn.microsoft.com/en-us/power-bi/enterprise/directlake-overview#enable-xmla-read-write:~:text=Direct%20Lake%20datasets%20created%20or%20modified%20by%20using%20XMLA%2Dbased%20tools%20cannot%20be%20opened%20in%20the%20Web%20modelling%20feature.)。

## 3.11.0 改进内容

- 我们现已使用最新版本的 [AMO/TOM](https://www.nuget.org/packages/Microsoft.AnalysisServices.NetCore.retail.amd64/) 和 [TMDL](https://www.nuget.org/packages/Microsoft.AnalysisServices.Tabular.Tmdl.NetCore.retail.amd64)，其中包含多项缺陷修复和稳定性改进。

> [!NOTE]
> TMDL 仍处于预览阶段，因此该功能在 Tabular Editor 3 中也属于预览功能。务必备份 Model.bim / Database.json 的模型元数据，以免丢失工作成果。

- 我们的 DAX 解析器和自动补全现已支持 [`MINX`](https://dax.guide/minx)/[`MAXX`](https://dax.guide/maxx) 新增的第三个参数。此外，我们现在也为 [`MATCHBY`](https://dax.guide/matchby) 函数提供自动补全建议，该函数可作为窗口函数的可选参数使用。
- 从 Databricks 导入时，只要指定了目录 catalog，“表导入向导”的“原生查询”选项就可用。

## 3.11.0 问题修复

- 使用 `$system.discover_keywords` DMV 更新了 DAX 中的保留表名列表。这样一来，我们的内置 DAX 格式化程序现在能够正确地为某些同时也是保留字的表名添加引号。例如，现在对名为 `status` 的表的引用将始终被加上引号。参见 [#991](https://github.com/TabularEditor/TabularEditor3/issues/991)。
- 自动补全现在会为诸如 [`RANK`](https://dax.guide) 等 DAX 窗口函数的 _&lt;Skip&gt;_ 参数建议正确的关键字。
- 批量重命名现已支持文件夹，详见 [#797](https://github.com/TabularEditor/TabularEditor3/issues/797)。
- 修复了与自定义布局相关的一些问题，参见 [#711](https://github.com/TabularEditor/TabularEditor3/issues/711)。还修复了一个问题：对内置菜单的自定义无法正确保存。
- 修复了 Deployment Wizard 中的一个问题：当模型包含一个没有分区的增量刷新表时会出错。在这种情况下，Deployment Wizard 界面不允许用户跳过此表的分区部署，因此会生成无效的 TMSL（即该表没有任何分区）。
- 修复了一个问题：运行 DAX 查询时，如果 [`EVALUATE`](https://dax.guide) 与后续表达式之间没有空白字符，会导致错误。
- 修复了 DAX调试器的多个问题。参见 [#954](https://github.com/TabularEditor/TabularEditor3/issues/954)、[#971](https://github.com/TabularEditor/TabularEditor3/issues/971) 和 [#984](https://github.com/TabularEditor/TabularEditor3/issues/984)。

## 正在从 Tabular Editor 2.x 迁移？

观看[此视频](https://www.youtube.com/watch?v=pt3DdcjfImY)，快速了解 Tabular Editor 3 的新功能。另外，也别忘了查看我们的 [入门指南](https://docs.tabulareditor.com/getting-started/index.html)。

**Tabular Editor 3 主要功能概述：**

- 完全可自定义的 IDE，支持多显示器、Hi-DPI 以及主题
- 全新强大的 DAX 代码编辑器，提供自动补全、语法检查、代码折叠等更多功能
- \*工作区模式：可将更改保存到磁盘，并同时将模型元数据同步到 Analysis Services
- \*可无限滚动预览表数据，创建 PivotGrid 或编写 DAX 查询，以浏览模型或测试计算逻辑
- \*计划数据刷新任务
- 在 Provider 数据源和 Structured数据源上更新表架构（是的，甚至包括 M 查询！）
- 创建 Data model 图表
- 创建 DAX脚本，让你在一个文档中编辑多个度量值或其他计算对象
- 录制 C# Script 并将其保存为宏（以前称为“Custom Actions”）
- VertiPaq分析器集成
- DAX调试器

\*=仅在连接到 Analysis Services 或 Power BI 实例时适用
