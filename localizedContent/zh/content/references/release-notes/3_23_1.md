## 3.23.0 新增功能

请访问我们的 [发布博客](https://blog.tabulareditor.com/)，快速了解本次发布最重要的更新。

- Tabular Editor 3 现已支持 **DAX 用户自定义函数（UDF）**。这是一个重大且关键的功能，几条要点远不足以讲清楚。如需了解更多信息，请参阅[专门的文档章节](xref:udfs)。
- 此外，本次发布还新增了对**日历**的支持，包括 DAX 解析器和编辑器对 8 个与基于周的时间智能相关的新 DAX 函数的支持。同样，如需了解更多信息，请参阅[专门的文档章节](xref:calendars)。

## 3.23.1 的改进

- 我们在 **新建模型** 对话框的下拉列表中新增了兼容级别 1700（SQL Server 2025）。此外，Power BI 模型的默认兼容级别已更新为 1702（这是 UDF 和日历所必需的）。

## 3.23.1 的错误修复

- 与 3.23.0 相比，这次更新修复了多个与 UDF 和日历相关的问题。主要与我们内置的 DAX 解析器有关，但也包括对自动完成、格式设置等功能的多项调整和稳定性改进。
- 我们已将 MSAL（Microsoft.Identity.Client）库的版本降级到 [4.72.1](https://www.nuget.org/packages/Microsoft.Identity.Client/4.72.1)，因为该库的较新版本（用于上一版 Tabular Editor 3）与 AS 客户端库配合不佳，[会导致在使用 Microsoft Entra ID 身份验证选项时应用挂起](https://github.com/TabularEditor/TabularEditor3/issues/1485)。
- 我们移除了对计算表格列执行的 **Duplicate** 和 **Cut/Copy/Paste/Delete** 操作，因为这些对象无法在表中手动添加或移除；强行操作会在将更改保存到 Analysis Services / Power BI 时引发问题。你应该改为修改该计算表格的 DAX 表达式。
- 选择 **Fabric 镜像数据库** 选项时，表导入向导 UI 现在也会显示镜像的 Azure Databricks 目录。
- 修复了一个问题：打开由旧版 Power BI Desktop 创建的模型时，会出现“The given key 'Extended Properties' was not present in the dictionary”错误。
- 修复了一个错误：在 DAX 脚本对象属性中无法使用前向引用。即。如果某个度量值的 `FormatString` 属性引用了脚本中稍后定义的度量值，就不会再报错了。

## 从 Tabular Editor 2.x 升级过来？

观看 [此视频](https://youtu.be/O4ATwdzCvWc)，快速了解 Tabular Editor 3 的主要功能。另外，记得查看我们的[入门指南](https://docs.tabulareditor.com/onboarding/index.html)。

**Tabular Editor 3 主要功能概览：**

- 完全可自定义的 IDE，支持多显示器、高 DPI 和主题
- 全新强大的 DAX 代码编辑器，具备自动补全、语法检查、代码折叠等众多功能
- \*Workspace 工作区模式：在将更改保存到磁盘的同时，将模型元数据同步到 Analysis Services
- \*支持无限滚动预览表格数据，可创建 PivotGrids 或编写 DAX 查询来浏览模型或测试计算逻辑
- \*支持计划数据刷新
- 在 Provider 数据源和 Structured数据源上更新表架构（没错，连 M 查询也支持！）
- 创建 Data model 关系图
- 创建 DAX 脚本，在单个文档中编辑多个度量值或其他计算对象
- 录制 C# Script 并保存为宏（此前称为“Custom Actions”）
- 集成 VertiPaq分析器
- DAX调试器
- DAX优化器集成
- 使用“代码操作”轻松重构 DAX。

\*=仅在连接到 Analysis Services 或 Power BI 的实例时
