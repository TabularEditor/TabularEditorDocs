## 3.27.0.0 版本新增内容

查看我们的[发布博客](https://tabulareditor.com/blog/tabular-editor-3-september-2026-release)，简要了解本次发布中最重要的更新。

### MCP 服务器

Tabular Editor 3 现在可以作为 MCP（Model Context Protocol，模型上下文协议）服务器运行，因此你正在使用的代理工具（Claude Code、GitHub Copilot、VS Code 代理模式、Codex、Cursor 等）也能像 AI 助手一样，针对你当前打开的模型使用相同的功能，而且无需在 Tabular Editor 中配置任何 AI 提供方或 API 密钥。如果你一直对基于 Agent 的语义模型开发感兴趣，但不想再多订阅一个 AI 服务，或者你只是更喜欢用自己的 Agent 工作，这就是一个很好的切入方式。

Agent 通过 MCP 服务器直接操作你在 Tabular Editor 3 中看到的模型，并使用与 AI 助手相同的对象模型、脚本引擎和安全检查机制。它执行的所有操作都会反映到你当前的 Tabular Editor 会话中，你可以检查、撤销，并在确认满意后保存。选择 **工具 > MCP 服务器...**，点击 **启动服务器**，然后把现成的配置粘贴到你的 Agent 工具中一次即可；状态栏指示器会显示服务器是否正在运行。

你可以在服务器启动前，在服务器对话框中设置五项 AI 权限（**模型元数据**、**模型数据**、**Best Practice Analyzer**、**文档** 和 **宏**），预先决定通过 MCP 连接的 Agent 可以执行哪些操作。任何不在你授权范围内的工具都不会提供给 Agent，因此你在工作时不会遇到权限确认弹窗。同一组权限也适用于 AI 助手聊天，并且可以在任一处进行修改。更改会在下次启动服务器时生效，已连接的 Agent 必须重新连接后才能看到这些更改。

在 **模型元数据 > 写入** 模式下，代理会通过由 Tabular Editor 编译、进行安全检查并以原子方式执行的 C# Script 来更改你的模型。你始终可以按一次 **Ctrl+Z**，撤销代理所做的全部更改。如果代理试图使用 Tabular Editor 在模型之外进行更改（文件、网络、外部程序集），系统将一律禁止执行，并改为以 C# Script 的形式打开供你审查。

详情请参阅新的 @mcp-server 一文；权限模型在 [权限和同意](xref:ai-assistant#permissions-and-consent) 中说明。

### AI 助手正式发布

**AI 助手**现已正式发布。安装程序默认选中 **AI 功能** 组件，因此标准安装完成后，助手和 MCP 服务器即可直接使用（你仍可取消勾选；如果 IT 管理员已禁用 AI 功能，则它仍将不可用）。你可以自带 OpenAI、Anthropic 或 Azure OpenAI 的 API 密钥，也可以将其指向任何兼容 OpenAI 的端点（包括本地模型），或者干脆不填密钥，直接使用 MCP 服务器配合你已有的代理。

现在，助手可以直接执行你要求的模型更改，而不再只是为你编写一个供你运行的脚本。要启用此功能，请在 **工具 > 偏好 > AI 功能 > AI 助手** 下勾选 **允许 AI 助手直接运行 C# Script**。这要求在 **工具 > 偏好 > AI 功能 > 权限** 下将 **模型元数据** 设置为 **写入**。只有修改模型本身的脚本才会以这种方式运行；任何访问文件、网络或外部程序集的脚本，仍会以脚本文档形式交给你查看。每次运行都会作为一个单独的撤销步骤记录；如果脚本中途失败，模型将保持不变；并且仍会遵循 **预览更改**，因此你可以在更改生效前查看变更，并通过 **取消** 还原。

我们还简化了在 AI 助手中选择模型的方式。 **AI 模型名称** 下拉列表和面板中的模型选择器现在都从在线列表获取，因此无需等待 Tabular Editor 更新，也能选择新模型。现在，上下文用量条、对话触发压缩的阈值以及回复最大长度，都会根据当前所用模型的实际限制来确定，而不再使用一个固定值；另外，在 **Azure OpenAI** 中，模型字段会像 Azure 一样标记为 **部署**。感谢 [edhans](https://github.com/edhans) 在我们的 [GitHub 创意论坛](https://github.com/TabularEditor/TabularEditor3/discussions/1580) 上提出模型选择器的建议。

现在会根据每条指令的说明来选择要应用的自定义指令；一旦助手选用某条指令，该指令将在本次对话的其余部分持续生效。如果你维护自己的指令文件，请确保每个文件的 `description` 准确且具体；`triggers` 部分会被忽略，可以删除。输入 `/instruction-id` 仍可显式加载某条指令。

此外，Tabular Editor 3 企业版还会在本地记录助手和 MCP 服务器执行过的操作（请求过的权限及其答复、使用过的工具及其结果，以及代理运行过或交给你的任何脚本的完整文本）。它绝不会记录提示词、回复或数据值，并且所有记录都只保存在你的本地。可通过打开 **工具 > 偏好 > AI 功能** 下的审计文件夹找到它。管理员可设置的策略见下方的企业版策略部分。

详情请参阅 @ai-assistant 以及 [允许助手更改你的模型](xref:ai-assistant#letting-the-assistant-change-your-model)。

### 未保存更改指示器

**TOM Explorer** 和 **属性** 窗格新增了一项功能，可在整个编辑器中标记存在未保存更改的对象，让你一眼就能看出自上次保存以来修改过哪些内容。在 **TOM Explorer** 中，新添加的对象会以绿色高亮并带有 **+** 标记，已删除对象会以红色高亮并带有 **−** 标记，已编辑对象则会以橙色高亮并带有圆点标记。**属性** 窗格也会以相同方式标记已更改的行；此外，这两个窗格都新增了一个工具栏切换开关，用于仅显示发生更改的内容。这些标记适用于任何未保存的更改，无论是手动、通过脚本还是由 AI 代理做出的；当模型被保存、重新加载，或通过撤销恢复到已保存状态时，这些标记会立即清除。

你也可以选择性地还原更改：右键单击带标记的属性并选择 **还原**，即可将该属性及其下所有内容恢复到上次保存时的状态；也可以只还原单个属性。

这项功能还意味着，已删除对象不再只是从模型中直接消失。在模型保存之前，它们会保留在原来的位置，并以删除线显示；右键单击并选择 **恢复**，即可将对象精确恢复到删除前一刻的状态。在 **工具 > 偏好 > TOM Explorer > 未保存的更改** 中，你可以关闭这些标记；将某个容器下已删除的对象汇总到一个 **已删除对象** 节点中；并设置已删除对象保持可见的时长。 C# Script 也可以使用该功能新增的函数：`Revert()`、`HasUnsavedChanges`、`DeletedObjects`、`Selected.Deleted`，并提供相应的 `Restore()`。

详情请参阅新的 @unsaved-changes 文章。

### 从磁盘自动重新加载

Tabular Editor 现在可以检测到它已加载的模型元数据文件是否在应用外部被更改（例如由 AI 代理、脚本或其他编辑器更改），并将这些更改同步到当前打开的模型中，无需你再使用 **文件 > 从磁盘重新加载**。从 `.bim` 文件加载的模型会监视该文件；从文件夹加载的模型会监视模型根目录下的每个 `.json` 或 `.tmdl` 文件。

当你没有未保存的更改时，模型只会在后台重新加载。如果你有未保存的更改，则会出现 **检测到外部更改** 提示，询问你是要 **重新加载**（丢弃本地更改）还是 **忽略**（保留本地更改）。

该行为默认启用，可在 **工具 > 偏好 > 杂项** 下通过新增的 **从磁盘自动重新加载（热加载）** 复选框将其关闭。详情请参阅新的 @auto-reload 文章。

### Snowflake 密钥对身份验证

Snowflake 连接现已支持 **密钥对** 身份验证，以配合 Snowflake 针对服务账户推行 MFA 的路线图。在 Snowflake 连接对话框中，选择 **密钥对** 作为身份验证方式，输入用户名，浏览并选择 RSA 私钥文件；如果密钥已加密，还需输入其密码短语。支持未加密的 PKCS#1/PKCS#8 密钥，以及使用密码短语加密的 PKCS#8 密钥（即 Snowflake 文档所述密钥生成步骤生成的格式）。详情请参阅 [密钥对身份验证](xref:connect-snowflake#key-pair-authentication)。

### AI Assistant 和 MCP 服务器的企业策略

管理员现在可以通过为五项 AI 权限分别设置策略，来决定 AI Assistant 和 MCP 服务器在任何用户的计算机上可以访问哪些内容、执行哪些操作。如果某项限制适用，那么 **工具 > 偏好 > AI 功能 > 权限** 下的选项以及 **工具 > MCP 服务器...** 对话框中只会显示允许的内容；AI Assistant 也不会再请求无法授予的权限；而当模型元数据被禁止访问时，任何有关当前打开模型的信息都不会被共享。

AI 提供程序、端点、模型或部署名称，以及 OpenAI 的组织和项目，也可以用同样的方式锁定，或限制为提供程序和端点主机的允许列表。管理员还可以为整个组织发布一个“自定义指令”文件夹（并排除用户自留的那些），决定 MCP 服务器向已连接的代理提供哪些工具，并固定服务器端口号。

这些策略需要 Tabular Editor 3 企业版。设置这些策略后，其他版本将无法启动 AI 助手和 MCP 服务器，并会指出哪些配置值需要企业版。详情请参阅[企业策略](xref:policies#enterprise-policies)。

### 针对不安全脚本的管理员策略

管理员现在还可以仅允许在语义模型范围内运行的 C# Script 和宏。启用此限制后，任何读取或写入文件、访问网络、启动其他程序、引入外部代码或直接向服务器发送命令的脚本，都会在运行前被拒绝。此策略适用于所有可运行脚本的入口：脚本编辑器、Best Practice Analyzer 的 **应用修复**、**AI 助手**、**MCP 服务器** 以及 `te` 命令行 (在 Windows 上)。执行上述任一操作的宏将不再出现在任何菜单中，并会在 **视图 > 宏** 中被标记；不过仍可在其中打开并编辑。

此限制需要 Tabular Editor 3 企业版：启用该策略时，任何其他版本都将完全不允许执行脚本或宏。详情请参阅策略参考中的[脚本和宏](xref:policies#scripts-and-macros)。

### DAX UDF 的逐文件序列化

现在，使用 JSON 文件夹格式保存模型时，可将 DAX 用户定义函数 (UDF) 序列化为单独的文件。每个 UDF 都会写入模型根目录下 `functions/` 子文件夹中的独立 `.json` 文件，因此并行编辑不同的 UDF 不再会在共享的 `Database.json` 上产生 Git 合并冲突。新的 **用户定义函数 (UDFs)** 开关会显示在 **工具 > 偏好 > 保存到文件夹** 和 **模型 > 序列化选项** 中；对新保存为文件夹的模型默认启用。现有以文件夹方式序列化的模型会保留其内联布局，直到你选择启用该选项并保存。

详情请参阅[用户定义函数 (UDFs)](xref:save-to-folder#user-defined-functions-udfs)。

### 语义分析器会标记用户上下文感知计算列的限制

现在，当 **用户上下文感知计算列**（即 Expression Context 设为 User Context 的计算列）在 Power BI 不允许的位置被引用时，语义分析器会报告错误。直接引用会在 DAX 编辑器、**信息** 视图和 `te validate` CLI 命令中报告；间接引用和关系端点违规会在 **信息** 视图中报告。

详情请参阅 @user-context-calculated-columns。

### 在数据预览中显示实际 DAX 查询

**数据预览** 网格新增了一个 **显示实际 DAX 查询** 的右键选项。它会打开一个新的、可编辑的 DAX 查询文档，并预先填入一条反映当前预览筛选和排序状态的查询，这样你就可以把眼前的预览直接带入查询，继续进行后续工作。详情请参阅[显示实际 DAX 查询](xref:table-preview#show-actual-dax-query)。

### 破坏性变更：C# Script 现改为使用脚本查询辅助方法，而不再使用 Model.Database

C# Script 不能再直接通过 `Model.Database` 调用查询或命令相关成员。脚本中查询连接模式下已连接模型的方式（而且一直以来都是）是使用内置脚本辅助方法 `EvaluateDax(...)`、`ExecuteDax(...)`、`ExecuteReader(...)` 和 `ExecuteCommand(...)`，这些方法没有变化。使用文档中这些辅助方法的脚本不受影响。参见 @script-helper-methods。

## 3.27.0.0 版本改进

- 现在可在 `Software\Policies\Tabular Editor ApS` 下设置策略；若某项策略只需应用于单个产品，可使用产品专属子键 `TE3` 或 `TECLI`。此外，这些策略也会从计算机范围的注册表配置单元读取，因此“计算机配置”组策略将生效，且用户无法覆盖。原有的 `Software\Policies\Kapacity\Tabular Editor` 键仍可照常使用，Windows 上的 `te` 命令行工具也会遵循这些策略。 Tabular Editor 3 现在还会安装一对组策略管理模板，因此每项策略都可以在组策略编辑器中设置，而无需编辑注册表。参见 @policies 和 [使用管理模板](xref:policies#using-the-administrative-templates)。
- 在 **工具 > 偏好 > 用户界面 > 辅助功能** 下新增了 **色盲模式**。该模式会用青绿色而非绿色标记自上次保存以来新增的对象，让新增、删除和更改的对象在最常见的色觉缺陷情况下仍能清晰区分。它适用于 **TOM Explorer** 中的更改指示器，以及模型比较视图中的颜色。参见 @accessibility。
- 已在 **新建模型** 对话框中添加 Power BI / Fabric 兼容级别 1706，并取代 1702 成为最新级别。现在，整个应用程序都会将 1706 视为最新级别，包括“Power BI 模型应使用最新兼容级别”这一 Best Practice Analyzer 规则，以及使用 `te init` 创建的新 Power BI 模型。
- **数据预览**值筛选器最多支持 5,000 条不同的行。如果需要处理大型表，新增的偏好设置允许提高该上限；但请注意，提高上限可能会增加加载时间。
- 已在 **工具 > 偏好 > 数据浏览 > 表格预览** 下新增了 **按字母顺序排序表格预览列** 偏好设置。启用后，**数据预览** 中的列将按名称排序，与 **TOM Explorer** 中的显示顺序一致，而不是按引擎返回的顺序。默认关闭。参见 [列顺序](xref:table-preview#column-order)。
- 现在，在 **TOM Explorer** 中选择某列时，**数据预览** 会自动滚动到该列并高亮显示，因此无需再在宽表中横向滚动查找。该跟踪功能默认开启。你可以通过 **跟踪所选列** 工具栏按钮为单个预览关闭该功能，也可以在 **工具 > 偏好 > 数据浏览 > 表格预览 > 行为** 下全局关闭。参见 [在宽表中查找列](xref:table-preview#finding-a-column-in-a-wide-table)。
- 在 **DAX 依赖关系视图** 中勾选 **跟踪 TOM Explorer** 后，现在会立即显示当前所选对象的依赖项，而无需等到下一次选择更改。
- 改进了 **TOM Explorer**，现在编辑 DAX 表达式后不再闪烁或跳动。此前，树视图可能会短暂重绘，并丢失其滚动位置。
- 模型图现在也会跟随 **TOM Explorer** 中的程序化导航：通过 **转到** 操作或搜索结果跳转到表或列时，该对象会在所有已打开的图表中高亮显示，与在树视图中单击它的效果一致。
- **文件 > 还原** 现已改为 **文件 > 从磁盘重新加载** 或 **文件 > 从服务器重新加载**，名称会表明当前打开的模型来源；该命令显示的所有文本也统一使用相同措辞：包括确认提示、执行过程中及完成后的状态栏信息，以及失败时的错误信息。
- DAX 编辑器现在可识别 [LOOKUP](https://dax.guide/lookup/) 函数的可选 `AssociatedColumnsBehavior` 参数；此前它会被加下划线标记为无法解析的引用。它会在参数提示中显示为末尾的可选参数，自动完成还会提供两个取值 `EXPLICIT` 和 `INFERRED`，并根据你的 **首选关键字大小写** 偏好以相应大小写显示。
- 现在，在对话框打开时，菜单和工具栏操作不再导致屏幕阅读器及其他辅助功能或自动化工具卡死。
- 现在可以直接重命名 Metric View 对象，无需先创建新对象再删除旧对象。导入包含重复对象名称的 Metric View YAML 现在会失败，并给出清晰的诊断信息；连接、字段和度量值表达式中的问题也会分别报告，并注明涉及的对象类型。
- **最新动态** 页面已替换为新的 **快速入门** 页面，可从 **帮助** 菜单打开，并会在首次启动和更新后显示。

## 3.27.0.0 的错误修复

- 修复了一个问题：以 TMDL 格式保存模型时，如果某个表、角色、透视或区域设置的文件名与对象自身名称仅在大小写上不同，则可能导致该对象被破坏。例如，名为 `Sales` 的表保存在 `tables/sales.tmdl` 中——这是重命名对象后可能遗留的情况。此前，保存会显示成功，但对象文件及其全部内容实际上已被删除，下一次打开模型时，该对象就会直接消失。现在，这类模型可以正确保存：对象会保留下来，其文件会以对象自身名称保存，而触发保存的编辑也会被应用。
- 修复了一个问题：从 SQL Server、Fabric Lakehouse 或 Fabric Warehouse 源导入或更新表时，无论是在 **模型 > 导入表**、**模型 > 更新表架构** 还是在 CLI 中，列都可能按任意顺序创建。现在，列会遵循源表的列顺序。
- 修复了一个问题：通过已包含其 SQL analytics endpoint 的数据源从 Fabric Lakehouse 或 Warehouse 导入表时，可能会在没有任何提示的情况下创建出一个没有列的表。现在，如果没有可用列，会明确显示错误信息。
- 修复了一个问题：如果导入的表的服务器、数据库、架构或对象名称中包含双引号，生成的 Power Query 表达式将无法解析。现在，这类名称以及从 Databricks 或 Snowflake 导入时的查询本身都会被正确转义。
- 修复了一个问题：使用 **External browser** 身份验证的 Snowflake 连接在其缓存的登录状态过期或被身份提供程序撤销后，无法恢复。此前，如果不重新打开浏览器，之后的所有 Snowflake 操作都会失败；“导入表”向导不会显示错误，而是直接显示空表和空列；唯一的恢复方式是重启 Tabular Editor。现在，只要 Snowflake 拒绝缓存的登录，浏览器登录就会重新打开；而超时或被放弃的登录会被视为取消，而不是会阻塞后续操作的错误。参见 [External browser sign-ins](xref:connect-snowflake#external-browser-sign-ins)。
- 修复了一个问题：在 macOS 或 Linux 上将模型保存到文件夹或 `.bim` 文件时，生成的文件与 Windows 上不一致，包括在 Windows 上无法检出的对象名称、与平台相关的行尾符以及不固定的表顺序。现在，在任何平台上保存的模型都会生成完全相同的输出。这也修复了一个长期存在的问题：如果两个对象的名称映射到同一个转义后的文件名，它们会覆盖彼此的文件。
- 修复了一个问题：将度量值或计算列移动到其他表，或复制它时，即使表达式仍然无效，其错误指示器也会消失。此前，只有再次编辑该表达式后，指示器才会重新出现。
- 修复了一个问题：重新加载已连接到 Workspace 数据库的模型时，通过 **File > Reload from disk** 或在磁盘上的文件发生更改后自动重新加载，**TOM Explorer** 会折叠并丢失当前选择。现在会保留已展开节点、焦点对象、选择内容和滚动位置；从文件打开的模型在重新加载时也会保留选择。
- 修复了一个问题：在 **TOM Explorer** 中粘贴对象后，原始对象和粘贴出来的副本可能会同时处于选中状态，并且树视图会滚动离开粘贴对象。现在，粘贴的对象会被选中、获得焦点并保持在可视范围内。
- 修复了一个问题：在其他视图中工作时，如果在 **TOM Explorer** 中选择对象，活动文档可能会切换到已打开的模型图。
- 修复了一个问题：在 **TOM Explorer** 中选择 Direct Lake 分区或由增量刷新策略生成的分区时，会引发错误并打开崩溃 Report 对话框。现在，如果分区具有数据覆盖范围定义表达式，**表达式编辑器** 会显示该表达式；否则保持为空。
- 修复了一个问题：打开包含计算表格的模型时，如果这些表的列是根据 DAX 表达式推断出来的，可能会间歇性失败，并出现“Collection was modified; enumeration operation may not execute”错误。
- 当模型的用户选项文件 (`.tmuo`) 中没有可读取内容时，打开模型不再因错误而失败。该文件现在也会以原子方式写入，从而从源头上避免因写入中断而损坏。
- 修复了一个问题：保存由 Power BI Desktop 创建的 PBIP 语义模型时，会重命名该项并清除在 Fabric 中设置的任何描述；这些更改随后会在下一次 Fabric Git 同步时传播到 Workspace。现在，将此类模型保存到新位置时，也会按该项的名称为文件夹命名。
- 修复了一个问题：**文件 > 另存为...** 可能会建议一个 Windows 拒绝保存的文件名，这种情况最常见于标签页标题包含冒号的文档。现在，建议名称中的无效字符会进行百分号编码，同时该名称仍可完全编辑。
- 修复了一个问题：当为连接选择自定义 **状态栏颜色** 时，状态栏中的文本可能会难以辨认。状态栏文本和链接颜色现在由所选颜色决定，而不是由当前主题决定。
- 修复了一个问题：在 Tabular Editor 尚未创建其本地应用程序数据文件夹的计算机上（例如首次运行时），Best Practice Analyzer 的“本地用户规则”集合可能会显示为只读。
- 修复了 DAX 自动完成的一个问题：它会建议在当前参数上下文中无效的用户定义函数，同时还会遗漏有效的函数。 UDF 现在会按其推断的返回类型进行筛选；筛选参数现在也会建议 UDF（此前会被完全省略）；定义中包含语义错误的 UDF 则不再提供。
- 修复了一个问题：DAX 编辑器中的 **内联度量值** 在引用位于行语境中时（例如在 `SUMX` 或 `FILTER` 内），可能会悄然改变计算结果。内联后的表达式现在会用 `CALCULATE( ...` 包裹…… )\` 中，以保留度量值引用所执行的语境转换，但只会在这种包裹确实会带来差异时才这样做。
- 修复了一个问题：如果展开后的度量值表达式以注释行结尾，**内联度量值** 可能会把周围表达式的一部分注释掉。该行中位于度量值引用之后的任何内容现在都会移到新的一行，并保持相同缩进。
- 修复了一个问题：在便携版（zip）中，即使已配置 AI 提供程序，**AI 助手** 有时也会在启动后不可用。此前，发送一条信息时会 Report “AI client not initialized”，随后在未更改任何设置的情况下点击确认又会因“Method not found”错误而失败，并且该错误会一直持续到重启应用程序为止。现在，助手在每次启动时都会稳定完成初始化；如果初始化失败，聊天也会 Report 实际原因。
- 修复了一个问题：当提供程序设为 `Anthropic` 或 `OpenAI` 且模型名称留空时，**AI 助手** 可能无法初始化。现在，模型名称留空会按预期工作；如果初始化失败，也会在聊天中 Report，而不再是毫无反应。
- 修复了一个问题：当要求 **AI 助手** 修改它在当前对话较早阶段编写的脚本或查询时，可能会因错误 "The requested operation requires an element of type 'Number', but the target element has type 'String'" 而失败。现在，回复能够正常完成，并会直接更新现有脚本或查询。
- 修复了一个问题：当 **AI 助手** 中的 **需要权限** 卡片正在等待答复时，**停止** 按钮不起作用，导致对话卡住。现在，按 **停止** 会结束当前轮次，并且可以通过新信息继续同一会话。
- 修复了一个问题：在浅色主题下，**AI 助手** 中的代码块难以阅读，近乎黑色的文字显示在近乎黑色的代码块背景上。现在，代码块、其语言标签、**复制** 按钮和语法高亮都会跟随主题，代码块的标题栏也已调整得更整洁。
- 修复了一个问题：**AI 助手** 工具栏上的 **删除会话** 按钮会立即删除当前会话，且无法恢复。现在会先要求确认，并且已从面板的关闭按钮旁移开，避免被误认为是关闭按钮。
- 修复了一个问题：在 **AI 助手** 的回复中，紧跟在脚本卡片或查询卡片后面的文本可能会以未格式化的状态显示，出现如 `**` 或反引号等原始字符，而非格式化文本。
- 修复了一个问题：如果某个对象在 **AI 助手** 首次创建后被重命名、移动或编辑，**AI 助手** 可能会创建重复对象，而不是更新现有对象。
- 修复了一个问题：当 **AI 助手** 连接到使用某些思考/推理模型的自定义（兼容 OpenAI）的提供方时，可能会报错并无法响应。依赖工具的请求（例如列出度量值或运行 DAX 查询）现在也能在这些模型中正常工作。
