## 3.27.0.0 版本新增内容

概览请参阅[发布博客](https://tabulareditor.com/blog/tabular-editor-3-september-2026-release)。

### MCP 服务器

Tabular Editor 3 现在可以充当 MCP（Model Context Protocol）服务器。 Claude Code、GitHub Copilot、VS Code 代理模式、Codex 和 Cursor 等代理工具都可以连接到它，并在你当前打开的模型上使用与 AI Assistant 相同的功能，而且无需在 Tabular Editor 中配置 AI 提供程序或 API 密钥。

该代理通过与 AI Assistant 相同的对象模型、脚本引擎和安全检查来处理模型，其更改会显示在你的 Tabular Editor 会话中，你可以在其中检查、撤销并保存这些更改。选择 **工具 > MCP 服务器...**，点击 **启动服务器**，然后将生成的配置粘贴到你的代理工具中；只需粘贴一次即可连接代理。状态栏指示器会显示服务器是否正在运行。

AI 权限 **模型元数据**、**模型数据**、**Best Practice Analyzer**、**文档** 和 **宏** 用于控制已连接的代理可以执行哪些操作。你可以在启动服务器之前，在服务器对话框中设置这些权限。你没授权的工具不会提供给代理，工作时也不会出现任何同意提示。 AI Assistant 聊天使用同一套权限，你可以在任一处进行编辑。更改会在服务器下次启动时生效，已连接的代理必须重新连接才能看到这些更改。

启用 **模型元数据 > 写入** 后，代理会通过 C# Script 修改你的模型，Tabular Editor 会对其进行编译、安全检查并以原子方式执行。每个脚本都对应一个撤销步骤，名称为 **C# Script (MCP)**。访问文件、网络或外部程序集的脚本不会自行运行。如果授予了 **文档 > 写入**，此类脚本会作为 C# Script 文档打开供你审查；若未授予该权限，则完全不会运行。

想了解详情，可以看看新的 @mcp-server 文章。权限模型在[权限与同意](xref:ai-assistant#permissions-and-consent)中有说明。

### AI Assistant 已正式发布

**AI 助手**现已正式发布。安装程序中的 **AI 功能** 组件现在默认选中。标准安装包含 AI Assistant 和 MCP 服务器。你仍然可以在安装程序中取消选中该组件；如果 IT 管理员已禁用 AI 功能，这些功能仍将不可用。支持的提供商包括 OpenAI、Anthropic、Azure OpenAI 以及与 OpenAI 兼容的端点，包括本地模型。更多信息见 @ai-assistant。

Assistant 现在可以运行它编写的 C# Script，以实现你要求的模型更改。此前，这些脚本需要你自己运行。在 **工具 > 偏好 > AI 功能 > AI 助手 > 偏好** 中选择 **允许 AI 助手直接运行 C# Script**，并在 **工具 > 偏好 > AI 功能 > 权限** 中将 **模型元数据** 设为 **读取/写入**，即可启用此功能。只有修改模型本身的脚本才会以这种方式运行；访问文件、网络或外部程序集的脚本仍会在脚本文档中打开，以便审查。每次运行都算作一次单独的撤销步骤；如果脚本中途失败，模型不会发生更改。**预览更改** 仍然适用：在保留更改之前，你会先看到改了什么，也可以单击 **取消** 进行还原。

现在，**AI 模型名称** 下拉列表和面板中的模型选择器都会从在线列表中加载选项，因此无需更新 Tabular Editor 也能选择新模型。上下文使用情况栏、对话开始压缩的阈值以及回复的最大长度，现在都会使用所选模型的限制。以前，这些都使用同一个固定值。对于 **Azure OpenAI**，模型字段现在标记为 **部署**，与 Azure 的术语保持一致。感谢 [edhans](https://github.com/edhans) 在我们的 [GitHub 创意论坛](https://github.com/TabularEditor/TabularEditor3/discussions/1580) 中提出模型选择器的建议。

助手现在会根据每条指令的描述来选择自定义指令，而且某条指令一旦被加载，就会在该对话的剩余部分持续生效。如果你维护自己的指令文件，请确保每个文件的 `description` 准确且具体。 `triggers` 部分会被忽略，可以删除。输入 `/instruction-id` 仍可显式加载某条指令。

在 Enterprise 许可证下，Tabular Editor 3 还会保留一份[审计日志](xref:ai-audit-log)，记录助手和 MCP 服务器执行过的操作。该日志会记录请求的权限及其答复、使用的工具及其结果，以及代理运行或交给你的任何脚本的完整文本，但不会记录提示词、回复或数据值。除非管理员将其重定向到其他位置，否则日志会写入本地。**打开审计文件夹**，在 **工具 > 偏好 > AI 功能** 下以及 **工具 > MCP 服务器...** 对话框中，可打开其所在位置。管理员可设置的策略见[AI 助手和 MCP 服务器的 Enterprise 策略](#enterprise-policies-for-the-ai-assistant-and-mcp-server)。

详情请参阅 @ai-assistant 和 [让助手更改你的模型](xref:ai-assistant#letting-the-assistant-change-your-model)。

### 未保存更改指示标记

**TOM Explorer** 和 **属性** 视图现在会标记带有未保存更改的对象，无论更改是手动完成、通过脚本完成，还是由 AI 代理完成。在 **TOM Explorer** 中，新增的对象会以绿色显示并带有 **+** 标记，已删除的对象会以红色显示并带有 **−** 标记，已编辑的对象会以橙色显示并带有圆点标记；**属性** 视图也会用相同方式标记已更改的行。两个视图的工具栏中都有一个 **显示更改** 开关，用于仅显示发生更改的内容。当你保存或重新加载模型，或通过撤销回到已保存状态时，这些标记会消失。

在 **TOM Explorer** 中右键单击带标记的对象，然后选择 **还原**，即可将该对象及其下所有内容恢复为上次保存时的状态。对于单个属性，在 **属性** 视图中右键单击其所在行，然后选择 **还原**。

已删除的对象不再会立即从 **TOM Explorer** 中消失。在你保存模型之前，它们会保留在原位置并显示删除线；你可以右键单击其中一个对象并选择 **恢复**，将其恢复到删除前的状态。在 **工具 > 偏好 > Tabular Editor > TOM Explorer** 下的 **未保存的更改** 部分中，你可以关闭这些标记、将某个容器中已删除的对象归组到单个 **已删除的对象** 节点下，并设置已删除对象保持可见的时长。 C# Script 现在可以使用新的成员 `Revert()`、`HasUnsavedChanges`、`DeletedObjects` 和 `Selected.Deleted`，以及与之对应的 `Restore()`。有关详细信息，详见新的 @unsaved-changes 文章。

### 从磁盘自动重新加载

如果已加载的模型元数据文件在应用程序外部发生更改，例如由 AI 代理、脚本或其他编辑器修改，Tabular Editor 现在会重新加载当前打开的模型。对于这些更改，你无需再使用 **文件 > 从磁盘重新加载**。对于从 `.bim` 文件加载的模型，对该文件的更改会触发重新加载；对于从文件夹加载的模型，模型根目录下任意 `.json` 或 `.tmdl` 文件的更改都会触发重新加载。

如果你没有未保存的更改，模型会直接重新加载，不会出现提示。如果你有未保存的更改，会弹出 **检测到外部更改** 提示。**重新加载** 会放弃你的本地更改，**忽略** 则会保留这些更改。

默认启用自动重新加载。如果要关闭此功能，请在 **工具 > 偏好 > Tabular Editor > 杂项** 下取消选中新增的 **从磁盘自动重新加载（热重载）** 复选框。有关详细信息，详见新的 @auto-reload 文章。

### Snowflake 密钥对身份验证

Snowflake 连接现已支持 **密钥对** 身份验证，这是 Snowflake 服务用户的登录方式，因为这类用户无法使用密码登录。在 Snowflake 连接对话框中，选择 **密钥对** 作为身份验证器，输入用户名，然后浏览并选择你的 RSA 私钥文件。如果密钥已加密，请输入其口令。支持的密钥包括未加密的 PKCS#1 和 PKCS#8 密钥，以及使用口令加密的 PKCS#8 密钥；Snowflake 文档中的密钥生成步骤生成的正是这种格式。有关详细信息，请参阅[密钥对身份验证](xref:connect-snowflake#key-pair-authentication)。

### AI 助手和 MCP 服务器的企业策略

管理员现在可以为五项 AI 权限分别设置策略，以控制 AI 助手和 MCP 服务器在用户计算机上可访问的内容以及可执行的操作。如果某项限制已生效，**工具 > 偏好 > AI 功能 > 权限** 下的选项以及 **工具 > MCP 服务器...** 对话框中的选项将只显示允许的级别，AI 助手也不再请求被策略阻止的权限。如果 **模型元数据** 被阻止，就不会共享任何有关当前打开模型的信息。

管理员还可以用同样的方式锁定 AI 提供程序、终结点、模型或部署名称，以及 OpenAI 组织和项目；也可以将这些设置限制为只能使用允许列表中的提供程序和终结点主机。其他策略还可以为整个组织发布一个“自定义说明”文件夹，阻止用户使用自己保存的“自定义说明”，选择 MCP 服务器向已连接代理提供哪些工具，并固定服务器的端口。

这些策略需要 Tabular Editor 3 企业版，并且在企业版、咨询版和试用许可证下都会生效。如果没有企业版许可证，在设置了这些策略时，AI 助手和 MCP 服务器将不会启动，并会显示一条信息，指出哪些策略值需要企业版。详见 [企业策略](xref:policies#enterprise-policies)。

### 针对不安全脚本的管理员策略

管理员现在还可以将 C# Script 和宏限制为仅能对语义模型本身执行操作。启用此限制后，如果脚本会读写文件、访问网络、启动其他程序、加载外部代码，或直接向服务器发送命令，它会在运行前被阻止。该策略适用于所有可运行脚本的位置：

- 脚本编辑器
- Best Practice Analyzer 的 **应用修复**
- **AI 助手**
- **MCP 服务器**
- （在 Windows 上）`te` 命令行工具

执行上述任一操作的宏将不再出现在任何菜单中，并会在 **视图 > 宏** 中标记显示；你仍可在此打开并编辑它。

此限制需要 Tabular Editor 3 企业版，并且在企业版、咨询许可和试用许可下同样适用。如果没有企业版许可证，在该策略启用期间，所有脚本和宏执行都会被阻止。详见策略参考中的 [脚本和宏](xref:policies#scripts-and-macros)。

### DAX UDF 的逐文件序列化

以 JSON 文件夹格式保存模型时，现在可以将 DAX 用户自定义函数 (UDF) 序列化为单独的文件，每个 UDF 都会写入模型根目录下 `functions/` 子文件夹中的独立 `.json` 文件。这样一来，并行编辑不同的 UDF 就不会再在共享的 `Database.json` 中引发 Git 合并冲突。新的 **用户自定义函数 (UDF)** 开关位于 **工具 > 偏好 > 文件格式 > 保存到文件夹** 以及 **模型 > 序列化选项...** 中，并且在新建“保存到文件夹”时默认启用。现有采用文件夹序列化的模型会保持内联布局，直到你启用该开关并保存。详见 [用户定义函数 (UDFs)](xref:save-to-folder#user-defined-functions-udfs)。

### 语义分析器标出用户上下文计算列的限制

当在 Power BI 不允许的位置引&#x7528;_&#x7528;户上下文计算&#x5217;_&#x65F6;，语义分析器现在会报告错误。_用户上下文计算&#x5217;_&#x662F;指其 `ExpressionContext` 属性（在 **属性** 视图中显示为 **表达式上下文**）设置为 **用户上下文** 的计算列。直接引用会在 DAX 编辑器、**信息** 视图以及 `te validate` CLI 命令的输出中报告；间接引用和关系端点违规则会在 **信息** 视图中报告。详见 @user-context-calculated-columns。

### 在表格预览中显示实际 DAX 查询

**表格预览** 网格的右键菜单中新增了 **显示实际 DAX 查询** 选项；点击后会打开一个新的、可编辑的 DAX 查询文档，其中的查询会反映当前预览的筛选和排序。详见 [显示实际 DAX 查询](xref:table-preview#show-actual-dax-query)。

### 重大变更：C# Script 将改为使用脚本查询辅助方法，替代 Model.Database

C# Script 不能再直接在 `Model.Database` 上调用查询和命令成员 `ExecuteCommand`、`ExecuteReader`、`ExecuteDax` 和 `EvaluateDax`。要运行查询和命令，请使用内置脚本辅助方法 `EvaluateDax(...)`、`ExecuteDax(...)`、`ExecuteReader(...)` 和 `ExecuteCommand(...)`；这些方法保持不变。其他 `Model.Database` 成员（例如 `Name`、`ID` 和 `CompatibilityLevel`）也保持不变。详见 @script-helper-methods。

## 3.27.0.0 版本改进

- 现在可以在 `Software\Policies\Tabular Editor ApS` 下设置策略；若某项策略仅适用于某个产品，可使用产品专用的子键 `TE3` 和 `TECLI`。现在也会从计算机范围的注册表配置单元读取策略，因此“计算机配置”组策略将生效，用户无法覆盖它们。此前的 `Software\Policies\Kapacity\Tabular Editor` 键仍然有效，`te` 命令行工具在 Windows 上也会遵循这些策略。 Tabular Editor 3 还会安装一对组策略管理模板，使你无需编辑注册表即可在组策略编辑器中设置所有策略。参见 @policies 和 [使用管理模板](xref:policies#using-the-administrative-templates)。
- 新的 **色盲模式** 位于 **工具 > 偏好 > Tabular Editor > 用户界面** 下的 **辅助功能** 组中，它会将自上次保存以来新增的对象标记为蓝绿色，而不是原本的绿色。启用后，新增、删除和已更改的对象在最常见的色盲类型下仍能清晰区分。该模式适用于 **TOM Explorer** 的更改标记，以及模型比较视图的配色。参见 @accessibility。
- 已在 **新建模型** 对话框中添加 Power BI / Fabric 兼容级别 1706，它取代 1702 成为最新级别。现在整个应用都将 1706 视为最新级别，包括 Best Practice Analyzer 中的“Power BI 模型应使用最新兼容级别”规则，以及使用 `te init` 创建的新 Power BI 模型。
- **表格预览** 的值筛选器最多可列出 5,000 个不同值。对于大型表，可通过 **Max。筛选下拉列表中的值** 来提高该上限，该设置位于 **工具 > 偏好 > 数据浏览 > 表格预览** 下。更高的限制可能会增加加载时间。
- 已在 **工具 > 偏好 > 数据浏览 > 表格预览** 下新增 **按字母顺序对表格预览列排序** 偏好，默认关闭。选中后，**表格预览** 中的列将按名称排序，与 **TOM Explorer** 中的顺序一致；取消选中后，列将按引擎返回的顺序显示。参见 [列顺序](xref:table-preview#column-order)。
- 默认情况下，在 **TOM Explorer** 中选择某一列时，**表格预览** 现在会滚动到该列并将其高亮显示。**跟踪所选列** 工具栏按钮可为单个预览关闭此跟踪，而 **工具 > 偏好 > 数据浏览 > 表格预览 > 行为** 可全局关闭它。参见 [在宽表中查找列](xref:table-preview#finding-a-column-in-a-wide-table)。
- 现在，在 **DAX 依赖关系视图** 中选择 **跟踪 TOM Explorer** 后，会立即显示当前所选对象的依赖关系。此前，该视图会等到下一次选择更改后才更新。
- 编辑 DAX 表达式后，**TOM Explorer** 不再闪烁或跳动。此前，该树视图可能会短暂重绘，并丢失滚动位置。
- 模型图现在会跟随 **TOM Explorer** 中以编程方式进行的导航。当你通过 **转到** 操作或搜索结果跳转到某个表或列时，所有打开的模型图都会高亮显示该对象，就像你在树形视图中单击它时一样。
- 现在，**文件 > 还原** 会根据当前打开模型的来源，显示为 **文件 > 从磁盘重新加载** 或 **文件 > 从服务器重新加载**。确认提示、重新加载期间及之后的状态栏信息，以及失败时的错误信息，现在都使用相同的措辞。
- DAX 编辑器现在可识别 [LOOKUP](https://dax.guide/lookup/) 函数的可选 `AssociatedColumnsBehavior` 参数。此前，此参数会被以下划线标记为未解析的引用。它现在会作为可选的末尾参数显示在参数提示中，自动完成还会建议其两个值 `EXPLICIT` 和 `INFERRED`，其大小写形式遵循你的 **首选关键字大小写** 偏好。
- 在对话框打开期间，菜单和工具栏操作不再会导致屏幕阅读器以及其他辅助功能或自动化工具挂起。
- 你现在可以直接重命名 Metric View 对象。此前，你必须新建一个对象，再删除旧对象。现在，导入包含重复对象名称的 Metric View YAML 时会失败，并报错 `Duplicate <kind> name '<name>'`；联接、字段和度量值表达式中的问题也会分别报告，并在每条消息中说明所涉及的对象类型。
- **新增功能** 页面已替换为新的 **开始使用** 页面，可从 **帮助** 菜单打开，并会在首次启动和更新后显示。

- 已将 Tabular Editor 所依赖的第三方组件更新到其最新的兼容版本，包括 [Microsoft.AnalysisServices](https://www.nuget.org/packages/Microsoft.AnalysisServices/)（Tabular Object Model/AMO）19.117.0、[DevExpress WinForms](https://www.nuget.org/packages/DevExpress.Win.Design/) 25.2.9、用于 C# Script 的 [Roslyn](https://www.nuget.org/packages/Microsoft.CodeAnalysis.CSharp/) 5.9.0、[WebView2](https://www.nuget.org/packages/Microsoft.Web.WebView2/) 1.0.4129.50、用于 AI 助手的 [Microsoft.Extensions.AI](https://www.nuget.org/packages/Microsoft.Extensions.AI/) 10.9.0 和 [Anthropic](https://www.nuget.org/packages/Anthropic/) 12.40.0、[Microsoft.Fabric.Api](https://www.nuget.org/packages/Microsoft.Fabric.Api/) 2.20.0、[Microsoft.PowerBI.Api](https://www.nuget.org/packages/Microsoft.PowerBI.Api/) 5.1.0、[Microsoft.Identity.Client](https://www.nuget.org/packages/Microsoft.Identity.Client.Desktop/) 4.87.0、[Microsoft.Data.SqlClient](https://www.nuget.org/packages/Microsoft.Data.SqlClient/) 6.1.5，以及用于命令行接口的 [Spectre.Console](https://www.nuget.org/packages/Spectre.Console/) 0.57.2。 DAX 和 M 编辑器背后的代码编辑组件（[Scintilla](https://www.nuget.org/packages/Scintilla5.NET/)）已更新到 7.0.0，该版本为 ARM64 和 x64 提供了经过数字签名的原生组件。这些签名组件在 Windows on Arm 设备以及强制执行代码完整性策略的环境中尤为重要。随着此次 Analysis Services 更新，对于兼容级别 1706 或更高的模型，现在会显示列的 **String Indexing Behavior** 属性。

## 3.27.0.0 中的错误修复

- 修复了一个问题：以 TMDL 格式保存模型时，如果某个表、角色、透视或区域设置的文件名与对象名称仅在字母大小写上不同（这种状态可能由重命名对象遗留），则可能导致该对象被破坏，例如名为 `Sales` 的表存储在 `tables/sales.tmdl` 中。此前，保存会显示成功，但该对象的文件及其内容会被删除，并且下次打开模型时该对象会消失。现在，这类模型可以正确保存：对象会被保留，其文件会按对象名称保存，并且会应用触发此次保存的编辑。
- 修复了一个问题：通过 **模型 > 导入表...**、**模型 > 更新表架构...** 或 CLI，从 SQL Server、Fabric Lakehouse 或 Fabric Warehouse 源导入或更新表时，列可能会以任意顺序创建。现在，列会遵循源表中的列顺序。
- 修复了一个问题：通过已包含其 SQL analytics endpoint 的数据源从 Fabric Lakehouse 或 Warehouse 导入表时，可能会创建一个没有任何列且不报错的表。现在会通过该 endpoint 读取列；如果无法确定 endpoint，则会显示错误，指出无法确定 OneLake 源的 SQL analytics endpoint。
- 修复了一个问题：导入的表如果其服务器、数据库、架构或对象名称中包含双引号，生成的 Power Query 表达式将无法解析。现在，这类名称会被正确转义；从 Databricks 或 Snowflake 导入时，查询本身也会被正确转义。
- 修复了一个问题：使用 **外部浏览器** 身份验证的 Snowflake 连接，在其缓存登录过期或被身份提供程序撤销后无法恢复。此前若不重新打开浏览器，后续的每次 Snowflake 操作都会失败：表导入向导不会报错，而是显示空的表和列；你必须重启 Tabular Editor 才能恢复。现在，当 Snowflake 拒绝缓存登录时，会重新打开浏览器登录；而超时或被放弃的登录现在会被视为取消，不再阻塞后续操作。参见[外部浏览器登录](xref:connect-snowflake#external-browser-sign-ins)。
- 修复了一个问题：在 macOS 或 Linux 上将模型保存到文件夹或 `.bim` 文件时，生成的文件会与 Windows 上不同，包括无法在 Windows 上签出的对象名称、与平台相关的换行符以及不固定的表顺序。现在，在任何平台上保存的模型都会生成完全相同的输出。这也修复了一个长期存在的问题：当两个对象的名称映射到同一个转义后的文件名时，它们会互相覆盖对方的文件。
- 修复了一个问题：将度量值或计算列移动到另一张表，或复制它时，即使表达式仍然无效，其错误标记也会被移除。此前，只有在再次编辑表达式后，该指示器才会重新出现。
- 修复了一个问题：重新加载带有已连接 Workspace 数据库的模型时，无论是通过 **文件 > 从磁盘重新加载**，还是在磁盘上的文件发生更改后自动重新加载，**TOM Explorer** 都会折叠并丢失当前选择。现在会保留已展开的节点、焦点对象、所选内容和滚动位置；重新加载从文件打开的模型时，也会保留选择。
- 修复了一个问题：在 **TOM Explorer** 中粘贴对象后，原始对象和粘贴后的副本可能会同时保持选中状态，而且树视图可能会滚动到看不到粘贴对象的位置。现在，粘贴的对象会被选中、获得焦点并保持在可见范围内。
- 修复了一个问题：在其他视图中工作时，如果在 **TOM Explorer** 中选择某个对象，活动文档可能会切换到已打开的模型图。
- 修复了一个问题：在 **TOM Explorer** 中选择 Direct Lake **分区**，或由增量刷新**刷新策略**生成的分区时，会引发错误并打开崩溃 **Report** 对话框。现在，如果分区具有数据覆盖范围定义表达式，**表达式编辑器** 会显示该表达式；如果没有，则保持为空。
- 修复了一个问题：打开包含计算表格（其列由 DAX 表达式推断）的模型时，可能会间歇性失败，并报错“Collection was modified; enumeration operation may not execute”。
- 如果模型的用户选项文件 (`.tmuo`) 中没有可读取的内容，打开模型现在也不会再因错误而失败。现在该文件也会以原子方式写入，因此写入中断不会损坏文件。
- 修复了一个问题：保存由 Power BI Desktop 创建的 PBIP 语义模型时，可能会将该项目重命名，并清除在 Fabric 中设置的任何描述；该更改随后会在下一次 Fabric Git 同步时同步到 Workspace。现在，将此类模型保存到新位置时，也会按该项的名称为文件夹命名。
- 修复了一个问题：**文件 > 另存为...** 可能会建议一个 Windows 无法保存的文件名，这种情况最常见于选项卡标题中包含冒号的文档。现在，建议名称中的无效字符会采用百分号编码，你仍可继续编辑该名称。
- 修复了一个问题：为连接选择自定义的 **状态栏颜色** 时，状态栏文本可能难以辨认。状态栏文本和链接颜色现在会根据所选颜色自动生成。此前，它们是从当前主题派生的。
- 修复了一个问题：在 Tabular Editor 尚未创建其本地应用程序数据文件夹的计算机上，Best Practice Analyzer 的“本地用户规则”集合可能会显示为只读，例如在首次运行时。
- 修复了一个问题：DAX 自动完成功能会建议在当前参数语境中无效的用户定义函数，同时漏掉有效的函数。现在会根据推断的返回类型筛选 UDF，并且定义中包含语义错误的 UDF 不再显示为建议项。 FILTER 参数以前完全不显示 UDF，现在也会建议它们。
- 修复了一个问题：在 DAX 编辑器中，当引用位于行语境内时，例如在 `SUMX` 或 `FILTER` 中，**内联度量值** 可能会在没有任何提示的情况下更改计算结果。在可能影响结果的情况下，内联后的表达式现在会被包裹在 `CALCULATE( ...`…… )\` 中，以保留度量值引用触发的语境转换。
- 已修复一个问题：当展开后的度量值表达式以注释行结尾时，**Inline measure** 可能会把周围表达式的一部分注释掉。现在，该行中位于度量值引用之后的任何代码都会移到新的一行，并保持相应的缩进。
- 已修复一个问题：便携版（zip）中的 **AI Assistant** 在启动后有时不可用，即使已配置 AI 提供程序也是如此。此前，发送消息时会提示“AI client not initialized”，并且在确认未更改的设置时会因“Method not found”错误而失败，直到重启应用程序才会恢复正常。现在，助手会在每次启动时进行初始化；如果初始化失败，聊天中会显示原因。
- 已修复一个问题：当提供程序设为 `Anthropic` 或 `OpenAI` 且模型名称留空时，**AI Assistant** 会无法初始化。现在，模型名称留空也可以正常使用；而此前不会提供任何反馈的初始化失败，现在会在聊天中显示。
- 已修复一个问题：当让 **AI Assistant** 修改它在同一对话较早时写过的脚本或查询时，可能会因错误“The requested operation requires an element of type 'Number', but the target element has type 'String'”而失败。现在回复会正常完成，现有脚本或查询也会在原位置更新。
- 已修复一个问题：当 **Permission Required** 卡片正在等待答复时，**AI Assistant** 中的 **Stop** 按钮不起作用，导致对话卡住。现在，按 **停止** 会结束当前轮次，你可以通过发送新信息继续同一段对话。
- 已修复一个问题：在浅色主题下，**AI Assistant** 中的代码块难以阅读，显示效果接近黑底黑字。代码块、其语言标签、**复制** 按钮和语法高亮现在都会跟随主题，代码块的标题栏样式也一并进行了优化。
- 已修复一个问题：**AI Assistant** 工具栏上的 **Delete conversation** 按钮会立即删除当前对话，且无法恢复。现在会显示确认提示，并且该按钮已移离面板的关闭按钮，以免被误认为是关闭按钮。
- 修复了一个问题：在 **AI 助手** 的回复中，紧跟在脚本卡片或查询卡片后面的文本可能无法正确套用格式，而会显示 `**` 或反引号等原始字符。
- 修复了一个问题：如果要求 **AI 助手** 更新一个在首次由助手创建后又被重命名、移动或编辑过的现有对象，它可能会创建一个重复对象。
- 修复了一个问题：当连接到使用某些思考型或推理型模型的自定义（兼容 OpenAI 的）提供程序时，**AI 助手** 可能会显示错误并无法响应。诸如列出度量值或运行 DAX 查询之类的工具请求，现在也能与这些模型配合工作。

- 可自定义的 IDE，支持多显示器、Hi-DPI 和多种主题

- 录制 C# Script 并将其保存为宏（以前称为“自定义操作”）
- 集成 VertiPaq分析器
- DAX调试器
- 集成 DAX优化器
- 用于重构 DAX 的代码操作

\*=仅在连接到 Analysis Services 或 Power BI 时才可用
