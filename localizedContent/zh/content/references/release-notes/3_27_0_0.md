## 3.27.0.0 版本新增内容

查看我们的[发布博客](https://tabulareditor.com/blog/tabular-editor-3-september-2026-release)，快速了解本次版本中最重要的更新。

### MCP 服务器

Tabular Editor 3 现在可以充当 MCP（Model Context Protocol，模型上下文协议）服务器，所以你已经在用的代理工具（Claude Code、GitHub Copilot、VS Code 代理模式、Codex、Cursor 等）都可以针对你当前打开的模型，调用和 AI Assistant 一样的功能，而且不用在 Tabular Editor 中配置任何 AI 提供商或 API 密钥。如果你一直对代理式语义模型开发感兴趣，但不想再额外订阅一项 AI 服务，或者只是更喜欢使用自己的代理工具来工作，那么这就是理想的入门方式。

代理会通过 MCP 服务器，直接在你当前于 Tabular Editor 3 中打开的模型上进行操作，并使用与 AI Assistant 相同的对象模型、脚本引擎和安全检查机制。它执行的所有操作都会直接反映在你的 Tabular Editor 会话中，你可以检查、撤销，并在满意后保存。选择 **工具 > MCP 服务器...**，点击 **启动服务器**，然后将现成的配置粘贴到你的代理工具中，只需一次；状态栏指示图标会显示服务器是否正在运行。

你可以在服务器启动前，在服务器对话框中设置五项 AI 权限（**模型元数据**、**模型数据**、**Best Practice Analyzer**、**文档**和**宏**），从而预先决定通过 MCP 连接的代理可以执行哪些操作；任何不在你授予权限范围内的工具都不会向代理开放，因此你在工作时不会出现同意弹窗。同一组权限也适用于 AI Assistant 聊天，并且可以在任一位置进行编辑。这些更改会在下次启动服务器时生效，而已经连接的代理必须重新连接后才能看到。

启用 **模型元数据 > 写入** 后，代理可通过 C# Script 更改你的模型；这些脚本会由 Tabular Editor 编译、安全检查，并以原子方式运行。你随时都可以用一次 **Ctrl+Z** 撤销代理所做的全部更改。如果代理试图借助 Tabular Editor 在模型之外进行更改（文件、网络、外部程序集），系统将一律禁止执行，而会改为把内容作为 C# Script 打开供你审查。

详情请参阅新的 @mcp-server 文章；权限模型请参见 [权限和同意](xref:ai-assistant#permissions-and-consent)。

### AI 助手正式发布

**AI 助手**现已正式发布。安装程序现在默认选中 **AI 功能** 组件，因此完成标准安装后，助手和 MCP 服务器即可直接使用（你仍可取消勾选；如果你的 IT 管理员已禁用 AI 功能，它将继续不可用）。你可以自带 OpenAI、Anthropic 或 Azure OpenAI 的 API 密钥，也可以将其指向任何兼容 OpenAI 的端点（包括本地模型），或者完全不提供密钥，直接使用 MCP 服务器与现有的代理配合使用。

助手现在可以直接执行你要求的模型更改，不再只是为你生成一个待运行的脚本。在 **工具 > 偏好 > AI 功能 > AI 助手** 下勾选 **允许 AI 助手直接运行 C# Script**，即可启用此功能。这要求在 **工具 > 偏好 > AI 功能 > 权限** 中将 **模型元数据** 设为 **写入**。只有修改模型本身的脚本才会以这种方式运行；凡是涉及文件、网络或外部程序集的内容，仍会以脚本文档的形式交给你审查。每次运行都会记为一个单独的撤销步骤；如果脚本中途失败，模型不会受到影响；并且仍会遵循 **预览更改**，因此你可以在更改生效前查看变更，并通过 **取消** 还原。

我们还让在 AI 助手中选择模型变得更容易。 **AI 模型名称** 下拉列表和面板中的模型选择器现在都从在线列表填充，因此无需等待 Tabular Editor 更新，也能选择新模型。上下文用量条、会话被压缩的阈值以及回复的最大长度，现在都会根据当前所用模型的真实限制动态调整，而不再使用一个固定数值；对于 **Azure OpenAI**，模型字段也会按 Azure 的做法标记为 **部署**。感谢 [edhans](https://github.com/edhans) 在我们的 [GitHub 创意论坛](https://github.com/TabularEditor/TabularEditor3/discussions/1580) 中提出模型选择器的建议。

现在会根据每条指令的描述来选择自定义指令，而一旦助手采用了某条指令，它会在该次对话的剩余过程中持续生效。如果你维护自己的指令文件，确保每个文件的 `description` 准确且具体；`triggers` 部分会被忽略，可以删除。输入 `/instruction-id` 仍可显式加载某条指令。

Tabular Editor 3 企业版还会在本地额外保留一份助手和 MCP 服务器的活动记录（请求过的权限及其答复、使用过的工具及其结果，以及代理运行或交给你的任何脚本的完整文本）。它绝不会记录提示词、回复或数据值，并且完全保留在用户本地。你可以在 **工具 > 偏好 > AI 功能** 下打开审计文件夹来找到它。管理员可设置的策略将在下文的企业版策略部分说明。

详情请参阅 @ai-assistant 和 [让助手更改你的模型](xref:ai-assistant#letting-the-assistant-change-your-model)。

### 未保存更改指示标记

**TOM Explorer** 和 **属性** 窗格新增了一项功能，可在整个编辑器中标记具有未保存更改的对象，让你一眼就能看出自上次保存以来改动过哪些内容。在 **TOM Explorer** 中，新添加的对象会以绿色显示并带有 **+** 标记，已删除的对象会以红色显示并带有 **−** 标记，已编辑的对象会以橙色显示并带有圆点标记。**属性** 窗格也会以同样方式标记已更改的行；此外，这两个窗格的工具栏都新增了一个切换开关，可仅显示发生更改的内容。这些指示器涵盖所有未保存的更改，无论是手动修改、由脚本修改，还是由 AI 代理修改；一旦模型被保存、重新加载，或通过撤销操作恢复到已保存状态，这些指示器就会立即清除。

你还可以选择性地还原更改：右键单击带标记的属性并选择 **还原**，即可将该属性及其下方的所有内容恢复到上次保存时的状态；也可以选择仅还原某个单独的属性。

这项功能还意味着，已删除的对象不再只是简单地从模型中消失。在模型保存之前，它们会保留在原来的位置并显示删除线；右键单击并选择 **恢复**，即可将对象精确恢复到删除前一刻的状态。在 **工具 > 偏好 > TOM Explorer > 未保存更改** 中，你可以关闭这些标记；将某个容器中已删除的对象汇总到单个 **已删除对象** 节点下；并选择已删除对象保持可见的时长。 C# Script 也可以使用这项功能新增的函数，包括 `Revert()`、`HasUnsavedChanges`、`DeletedObjects` 和 `Selected.Deleted`，以及对应的 `Restore()`。

有关详细信息，详见新的 @unsaved-changes 文章。

### 从磁盘自动重新加载

现在，当 Tabular Editor 加载的模型元数据文件在应用程序外部发生更改时（例如由 AI 代理、脚本或其他编辑器修改），它能够检测到这些更改，并将其同步到当前打开的模型中，而无需你手动使用 **文件 > 从磁盘重新加载**。如果模型是从 `.bim` 文件加载的，系统会监视该文件；如果模型是从文件夹加载的，系统会监视模型根目录下所有 `.json` 或 `.tmdl` 文件。

如果你没有未保存的更改，模型只会在后台重新加载。如果你有未保存的更改，系统会显示 **检测到外部更改** 提示，询问你是要 **重新加载**（丢弃本地更改）还是 **忽略**（保留本地更改）。

此行为默认启用，也可以在 **工具 > 偏好 > 杂项** 下通过新的 **自动从磁盘重新加载（热重载）** 复选框将其关闭。有关详细信息，详见新的 @auto-reload 文章。

### Snowflake 密钥对身份验证

Snowflake 连接现已支持 **密钥对** 身份验证，以配合 Snowflake 面向服务账户推行 MFA 的路线图。在 Snowflake 连接对话框中，选择 **密钥对** 作为身份验证器，输入用户名，浏览并选择你的 RSA 私钥文件；如果密钥已加密，则还需要输入其密码短语。支持未加密的 PKCS#1/PKCS#8 密钥，以及使用密码短语加密的 PKCS#8 密钥（即 Snowflake 文档中所述密钥生成步骤产生的格式）。有关详细信息，详见 [密钥对身份验证](xref:connect-snowflake#key-pair-authentication)。

### AI 助手和 MCP 服务器的企业策略

现在，管理员可以通过分别为五项 AI 权限设置策略，来决定 AI 助手和 MCP 服务器在任何用户的计算机上可以访问哪些内容以及可以执行哪些操作。在适用限制时，**工具 > 偏好 > AI 功能 > 权限** 下的选项以及 **工具 > MCP 服务器...** 对话框中的选项只会提供被允许的内容；助手也不会再请求无法获批的权限；而当模型元数据被禁止访问时，任何有关当前打开模型的信息都不会被共享。

AI 提供商、端点、模型或部署名称，以及 OpenAI 的组织和项目，也可以用同样的方式锁定；也可以仅允许使用允许列表中的提供商和端点主机。管理员还可以为整个组织发布一个“自定义说明”文件夹（并排除用户自己保留的那些），决定 MCP 服务器向已连接的代理提供哪些工具，并固定服务器的端口。

这些策略需要 Tabular Editor 3 企业版。启用这些策略时，其他版本将拒绝启动 AI 助手和 MCP 服务器，并指出哪些值需要企业版。详见 [企业策略](xref:policies#enterprise-policies)。

### 针对不安全脚本的管理员策略

管理员现在还可以将 C# Script 和宏限制为只能在语义模型内操作。启用此限制后，任何读取或写入文件、访问网络、启动其他程序、引入外部代码，或直接向服务器发送命令的脚本，都会在运行前被拒绝。此策略适用于所有可运行脚本的界面：脚本编辑器、Best Practice Analyzer 的 **Apply fix**、**AI Assistant**、**MCP server** 以及 `te` 命令行 (在 Windows 上)。执行上述任一操作的宏将不再显示在任何菜单中，并会在 **视图 > 宏** 中被标记；但仍可在此处打开并编辑。

此限制需要 Tabular Editor 3 企业版：启用该策略期间，任何其他版本都将完全不允许执行脚本或宏。详见策略参考中的 [脚本和宏](xref:policies#scripts-and-macros)。

### DAX UDF 的逐文件序列化

现在，使用 JSON 文件夹格式保存模型时，可以将 DAX 用户定义函数 (UDF) 序列化为独立文件。每个 UDF 都会写入模型根目录下 `functions/` 子文件夹中的独立 `.json` 文件，因此并行编辑不同 UDF 时，不再会在共享的 `Database.json` 上产生 Git 合并冲突。新的 **用户定义函数 (UDFs)** 开关会显示在 **工具 > 偏好 > 保存到文件夹** 和 **模型 > 序列化选项** 中。对新创建的文件夹保存默认启用；对于现有以文件夹方式序列化的模型，在你选择启用并保存之前，仍会保持内联布局。

详见 [用户定义函数 (UDFs)](xref:save-to-folder#user-defined-functions-udfs)。

### Semantic Analyzer 标记与用户上下文感知计算列相关的限制

现在，当在 Power BI 不允许的位置引用 **用户上下文感知计算列**（即 Expression Context 设置为 User Context 的计算列）时，Semantic Analyzer 会报告错误。直接引用会在 DAX 编辑器、**信息** 视图以及 `te validate` CLI 命令中报告；间接引用和关系端点违规则仅在 **信息** 视图中报告。

详见 @user-context-calculated-columns。

### 在数据预览中显示实际 DAX 查询

**数据预览** 表格新增了 **显示实际 DAX 查询** 的右键选项。它会打开一个新的、可编辑的 DAX 查询文档，并预先填入一条查询，该查询会反映当前预览的筛选和排序状态；这样，你就可以将正在查看的预览直接作为查询继续处理。详见 [显示实际 DAX 查询](xref:table-preview#show-actual-dax-query)。

### 重大变更：C# Script 将改为使用脚本查询辅助方法，替代 Model.Database

C# Script 不再能在 `Model.Database` 上直接调用查询/命令成员。在脚本中查询已连接模型的方式是（而且一直都是）使用内置脚本辅助方法 `EvaluateDax(...)`、`ExecuteDax(...)`、`ExecuteReader(...)` 和 `ExecuteCommand(...)`，它们都没有变化。使用文档中这些辅助方法的脚本不受影响。详见 @script-helper-methods。

## 3.27.0.0 版本改进

- 现在可以在 `Software\Policies\Tabular Editor ApS` 下设置策略；并提供产品专用子键 `TE3` 和 `TECLI`，用于仅需作用于单个产品的策略。这些策略现在也会从计算机级的注册表配置单元读取，因此“计算机配置”组策略会生效，且用户无法覆盖。原有的 `Software\Policies\Kapacity\Tabular Editor` 注册表项仍可照常使用，无需更改；Windows 上的 `te` 命令行工具也会遵循这些策略。 Tabular Editor 3 现在还会安装一对组策略管理模板，因此每项策略都可以直接在组策略编辑器中设置，而无需手动编辑注册表。参见 @policies 和 [使用管理模板](xref:policies#using-the-administrative-templates)。
- 在 **工具 > 偏好 > 用户界面 > 辅助功能** 中新增 **色盲模式**。启用后，会将自上次保存以来新增的对象以青绿色而非绿色标记，使新增、删除和更改的对象在最常见的色觉障碍类型下依然清晰可区分。它适用于 **TOM Explorer** 中的更改指示器，以及模型比较视图中的颜色。参见 @accessibility。
- 在 **新建模型** 对话框中新增了 Power BI / Fabric 兼容级别 1706，取代 1702 成为最新级别。现在整个应用都将 1706 视为最新级别，包括 Best Practice Analyzer 中的“Power BI 模型应使用最新兼容级别”规则，以及使用 `te init` 创建的新 Power BI 模型。

- 在 **工具 > 偏好 > 数据浏览 > 表格预览** 下新增了 **按字母顺序对表格预览列排序** 偏好设置。启用后，**数据预览** 中的列会按名称排序，与 **TOM Explorer** 中的显示顺序一致，而不是按引擎返回的顺序。默认关闭。参见 [列顺序](xref:table-preview#column-order)。

- 现在，在 **DAX 依赖关系视图** 中勾选 **跟踪 TOM Explorer** 后，会立即显示当前所选对象的依赖项，而不必等到下次选择变更。

- 模型图现在会跟随 **TOM Explorer** 中的程序化导航：通过 **转到** 操作或搜索结果跳转到表或列时，该对象会在所有已打开的模型图中高亮显示，效果与在树视图中点击它一致。
- **文件 > 还原** 现已改为 **文件 > 从磁盘重新加载** 或 **文件 > 从服务器重新加载**，具体名称取决于当前打开模型的来源。与该命令相关的所有文案也统一采用相同表述：确认提示、运行期间和完成后的状态栏消息，以及失败时的错误消息。

## 3.27.0.0 中的错误修复

- 修复了一个问题：以 TMDL 格式保存模型时，如果某个表、角色、透视或区域设置的文件名与对象名称仅大小写不同，则该对象可能会损坏。例如，名为 `Sales` 的表保存在 `tables/sales.tmdl` 中，这种情况正是重命名对象后可能遗留的结果。此前，保存会报告成功，但该对象的文件及其中的全部内容实际上已被删除，下一次打开模型时，这个对象就会直接消失。现在，这类模型可以正确保存：对象会被保留，文件会以对象自身的名称保存，并且触发此次保存的编辑也会被应用。
- 修复了一个问题：从 SQL Server、Fabric Lakehouse 或 Fabric Warehouse 源导入或更新表时，无论是在 **模型 > 导入表**、**模型 > 更新表架构** 还是在 CLI 中，列都可能按任意顺序创建。现在，列会遵循源表中的列顺序。
- 修复了一个问题：如果通过已包含 SQL analytics endpoint 的数据源从 Fabric Lakehouse 或 Warehouse 导入表，系统可能会静默创建一个没有任何列的表。当没有可用列时，现在会显示明确的错误信息。
- 修复了一个问题：导入服务器、数据库、架构或对象名称中包含双引号的表时，可能会生成无法解析的 Power Query 表达式。现在，这类名称以及从 Databricks 或 Snowflake 导入时的查询本身都会被正确转义。
- 修复了一个问题：使用 **外部浏览器** 身份验证的 Snowflake 连接一旦其缓存的登录过期或被身份提供程序撤销，就无法恢复。此前，后续每一次 Snowflake 操作都会失败，除非重新打开浏览器；导入表向导不会显示错误，而是静默地显示空表和空列；唯一的恢复方式是重启 Tabular Editor。现在，只要 Snowflake 拒绝已缓存的浏览器登录信息，浏览器登录窗口就会立即重新打开；如果登录超时或被放弃，也会被视为取消，而不是会阻止后续操作的错误。参见[外部浏览器登录](xref:connect-snowflake#external-browser-sign-ins)。
- 修复了一个问题：在 macOS 或 Linux 上将模型保存到文件夹或 `.bim` 文件时，生成的文件与 Windows 上不同，包括在 Windows 上无法检出的对象名称、依赖平台的行尾符以及不一致的表顺序。现在，在任何平台上保存的模型都会生成完全相同的输出。这也修复了一个长期存在的问题：如果两个对象的名称映射到同一个转义后的文件名，它们会相互覆盖对方的文件。
- 修复了一个问题：将度量值或计算列移动到另一张表，或复制它时，即使表达式仍然无效，其错误指示器也会消失。此前，只有在再次编辑表达式后，该指示器才会重新出现。
- 修复了一个问题：重新加载已连接到 Workspace 数据库的模型时，**TOM Explorer** 会折叠并丢失当前选择，无论是通过 **文件 > 从磁盘重新加载**，还是在磁盘上的文件发生更改后自动重新加载。现在会保留已展开的节点、焦点对象、所选内容和滚动位置；重新加载从文件打开的模型时，也会保留所选内容。
- 修复了一个问题：在 **TOM Explorer** 中粘贴对象后，原始对象和粘贴后的副本可能会同时保持选中状态，而且树视图可能会滚动到看不到粘贴对象的位置。现在，粘贴的对象会被选中、获得焦点并保持在可见范围内。
- 修复了一个问题：在其他视图中工作时，如果在 **TOM Explorer** 中选择某个对象，活动文档可能会切换到已打开的模型图。
- 修复了一个问题：在 **TOM Explorer** 中选择 Direct Lake **分区**，或由增量刷新**刷新策略**生成的分区时，会引发错误并打开崩溃 **Report** 对话框。现在，**表达式编辑器** 会在分区存在数据覆盖范围定义表达式时显示该表达式；否则保持为空。
- 修复了一个问题：打开包含计算表格（其列由 DAX 表达式推断）的模型时，可能会间歇性失败，并报错“Collection was modified; enumeration operation may not execute”。
- 如果模型的用户选项文件 (`.tmuo`) 中没有可读取的内容，打开模型现在也不会再因错误而失败。该文件现在也会以原子方式写入，因此即使写入被中断，也不会导致文件损坏。
- 修复了一个问题：保存由 Power BI Desktop 创建的 PBIP 语义模型时，会重命名该项目并清除在 Fabric 中设置的任何描述；这些更改会在下一次 Fabric Git 同步时同步到 Workspace。现在，将此类模型保存到新位置时，也会按该项的名称为文件夹命名。
- 修复了一个问题：**文件 > 另存为...** 可能会建议一个 Windows 不允许保存的文件名，这种情况最常见于选项卡标题中包含冒号的文档。现在，建议的名称中的无效字符会进行百分号编码，且该名称仍可完全编辑。
- 修复了一个问题：为某个连接选择自定义 **状态栏颜色** 时，状态栏中的文本可能难以辨认。状态栏文本和链接颜色现在会根据所选颜色派生，而不是根据当前主题派生。
- 修复了一个问题：在尚未由 Tabular Editor 创建本地应用数据文件夹的计算机上（例如首次运行时），Best Practice Analyzer 的“本地用户的规则”集合可能会显示为只读。
- 修复了 DAX 自动完成会建议在当前参数上下文中无效的用户定义函数，并遗漏有效函数的问题。现在会按推断的返回类型筛选 UDF；FILTER 参数也会提示 UDF（此前会被完全省略）；定义中包含语义错误的 UDF 也不再提供。
- 已修复一个问题：在 DAX 编辑器中，当引用位于行语境内时，例如在 `SUMX` 或 `FILTER` 中，**Inline measure** 可能会在无提示的情况下更改计算结果。现在，内联表达式会被包裹在 `CALCULATE( …… )` 中，以保留度量值引用所执行的语境转换，但仅在这种包裹会产生影响时才会这样做。
- 已修复一个问题：当展开后的度量值表达式以注释行结尾时，**Inline measure** 可能会把周围表达式的一部分注释掉。现在，该行中跟在度量值引用后面的任何内容都会移到新的一行，并保持相同的缩进。
- 已修复一个问题：便携版（zip）中的 **AI Assistant** 在启动后有时不可用，即使已配置 AI 提供程序也是如此。此前，发送信息时会提示“AI client not initialized”，随后确认未更改的设置也会因“Method not found”错误而失败，且该错误会一直持续，直到重启应用程序。现在，助手每次启动时都能一致地完成初始化；如果初始化确实失败，聊天中也会报告实际原因。
- 已修复一个问题：当提供程序设为 `Anthropic` 或 `OpenAI` 且模型名称留空时，**AI Assistant** 会无法初始化。现在，模型名称留空也能按预期工作；如果初始化失败，聊天中会报告错误，而不是毫无反应。
- 已修复一个问题：当让 **AI Assistant** 修改它在同一对话较早时写过的脚本或查询时，可能会因错误“The requested operation requires an element of type 'Number', but the target element has type 'String'”而失败。现在，回复可以正常完成，现有脚本或查询也会直接在原处更新。
- 已修复一个问题：当 **Permission Required** 卡片正在等待答复时，**AI Assistant** 中的 **Stop** 按钮不起作用，导致对话卡住。现在，按下 **Stop** 会结束当前轮次，你也可以在同一对话中继续发送新信息。
- 已修复一个问题：在浅色主题下，**AI Assistant** 中的代码块难以阅读，显示效果接近黑底黑字。现在，代码块、其语言标签、**Copy** 按钮和语法着色都会遵循当前主题，代码块的标题栏也已整理优化。
- 已修复一个问题：**AI Assistant** 工具栏上的 **Delete conversation** 按钮会立即删除当前对话，且无法恢复。现在会先让你确认，而且这个按钮也已移离面板的关闭按钮，以免被误认成关闭按钮。
- 已修复一个问题：在 **AI Assistant** 的回复中，紧跟在脚本或查询卡片后面的文本可能会显示为未格式化状态，直接显示 `**` 或反引号等原始字符，而不是格式化后的文本。
- 已修复一个问题：如果某个对象在助手首次创建后又被重命名、移动或编辑，**AI Assistant** 在后续操作时可能会创建重复对象，而不是更新现有对象。
- 已修复一个问题：当连接到使用某些思考/推理模型的自定义（兼容 OpenAI 的）提供程序时，**AI Assistant** 可能会显示错误并无法响应。现在，依赖工具的请求（例如列出度量值或运行 DAX 查询）已可与这些模型配合使用。

- DAX调试器
- 集成 DAX优化器
- 代码操作：轻松重构 DAX。
