### 前提条件

Tabular Editor 3.3.0（及更高版本）使用 .NET 6。在启动 Tabular Editor 3.3.0（或更高版本）之前，你可能需要先安装 [适用于桌面的.NET 6.0 运行时](https://dotnet.microsoft.com/en-us/download/dotnet/6.0/runtime)。从 3.3.1 开始，如果系统中缺少这些先决条件，Tabular Editor 3 安装程序会自动下载并安装它们。

## 3.13.0 新增内容

查看我们的[发布博客](https://blog.tabulareditor.com/2023/12/15/tabular-editor-3-december-2023-release/)，快速了解此版本中最重要的更新。

## 3.13.0 改进内容

- 现在，只有在变量声明块完整后，才会显示未使用变量的警告，而且只会高亮变量名本身。此外，你现在可以在 **工具 > 偏好 > DAX编辑器 > Code Assist** 中关闭这些警告。
- TE3 中的 VertiPaq分析器现在使用与 DAX Studio 相同的默认设置。现在你还可以在 **工具 > 偏好 > VertiPaq分析器** 中配置“从 DirectQuery 表读取统计信息”选项。
- 我们对表的“刷新策略”在 **属性** 视图中的显示方式做了一个小调整，以便更好地与 [TOM](https://learn.microsoft.com/en-us/dotnet/api/microsoft.analysisservices.tabular.table.refreshpolicy?view=analysisservices-dotnet) 保持一致。这项更改还允许你向刷新策略添加注释和扩展属性，而这在以前是做不到的。 C# Script 仍然可以直接通过 `Table` 对象使用刷新策略属性，但我们建议你更新脚本，改为通过 `Table.RefreshPolicy` 对象访问这些属性。
- 在 TOM Explorer 中选择表或列时，我们现在会高亮显示（使用 **粗体** 字体）该对象参与的所有关系，参见 [#865](https://github.com/TabularEditor/TabularEditor3/issues/865)。可在 **工具 > 偏好 > TOM Explorer** 中禁用此功能。
- 我们现在会显示主要存储模式（Import、DirectQuery、Direct Lake 等）在标题栏中显示模型名称。
- 除了表之外，现在还可以在“Dependencies”视图中从某个特定列开始查看关系。右键单击某列，选择“Show dependencies”，然后选择“Show relationships starting from this column”选项，参见 [这条评论](https://github.com/TabularEditor/TabularEditor3/issues/865#issuecomment-1490782086)。
- 当对象处于未处理状态时，现在会在 **信息** 视图中显示警告。这同样适用于表、列和分区。同时也解决了 [#1153](https://github.com/TabularEditor/TabularEditor3/issues/1153)。
- 当某列使用的“按列排序”目标列的 `IsAvailableInMDX` 被设置为 **false** 时，我们现在会在 **信息** 视图中显示一条警告（否则在保存/部署模型时会报错）。参见 [#868](https://github.com/TabularEditor/TabularEditor3/issues/868)。
- 我们已将 AMO/TOM 更新为使用最新版本 [19.72.0](https://www.nuget.org/packages/Microsoft.AnalysisServices.retail.amd64/)。这个库还包含更新版本的 TMDL，应该能修复表应用了增量刷新的刷新策略时出现的反序列化问题。
- 使用 TMDL 序列化模型时，我们现在还会输出一个 `database.tmdl` 文件，其中包含数据库级别的元数据（名称、兼容模式、兼容级别等），从而提升整体 TMDL 体验。

> [!NOTE]
> **TMDL 仍处于预览阶段，不应在生产环境中使用，因为更新之间可能存在破坏性变更。**
> 如果你在打开由较早版本 Tabular Editor 以 TMDL 格式保存的模型时遇到问题，一种可能的解决办法是：使用同一较早版本的 Tabular Editor 从 TMDL 打开该模型，将其另存为 Model.bim 文件；然后使用最新版本的 Tabular Editor 打开该 Model.bim 文件，并再将其保存回 TMDL 格式。

## 3.13.0 中的错误修复

- 修复了一个问题：撤销（Ctrl+Z）从表中移除刷新策略的操作时，无法恢复该刷新策略的配置。
- 修复了一个问题：当将窗口函数用作 [`CALCULATE`](https://dax.guide/calculate/) 或 [`CALCULATETABLE`](https://dax.guide/calculatetable/) 的筛选参数时，DAX编辑器的自动补全会为窗口函数参数推荐不正确的项目。
- 修复了一个 bug：连接到 Power BI Desktop 实例时无法向层次结构添加/移除级别，尽管这是一个 [受支持的建模操作](https://learn.microsoft.com/en-us/power-bi/transform-model/desktop-external-tools#data-modeling-operations)。
- 修复了一个问题：对于常规表，“Calculate”刷新选项未显示。
- 修复了一个问题：如果所选内容中第一条 `EVALUATE` 语句的正上方紧挨着一行注释，那么仅评估 DAX 查询当前选中的内容将无法正常工作，参见 [#912](https://github.com/TabularEditor/TabularEditor3/issues/912)。
- 当文件夹中包含“.tmdl”文件时，Tabular Editor 现在应允许你“从文件夹打开”（旧版本的 TMDL 使用“.tmd”扩展名）。参见 [#1175](https://github.com/TabularEditor/TabularEditor3/issues/1175)。
- 此前用于判定表是否为“日期表”的逻辑过于严格，这在某些情况下可能会误报循环依赖错误，或在 DAX调试器中错误显示被覆盖的筛选语境（由于日期表会隐式移除筛选）。

## 从 Tabular Editor 2.x 升级过来？

观看[此视频](https://www.youtube.com/watch?v=pt3DdcjfImY)，了解 Tabular Editor 3 的新功能。另外，也别忘了看看我们的 [上手指南](https://docs.tabulareditor.com/onboarding/index.html)。

**Tabular Editor 3 主要功能概览：**

- 完全可自定义的 IDE，支持多显示器、高 DPI 和主题
- 全新强大的 DAX 代码编辑器，具备自动补全、语法检查、代码折叠等众多功能
- \*Workspace 工作区模式：在将更改保存到磁盘的同时，将模型元数据同步到 Analysis Services
- \*支持无限滚动预览表格数据，可创建 PivotGrids 或编写 DAX 查询来浏览模型或测试计算逻辑
- \*支持计划数据刷新
- 在 Provider 数据源和 Structured数据源上更新表架构（没错，连 M 查询也支持！）
- 创建 Data model 关系图
- 创建 DAX 脚本，在单个文档中编辑多个度量值或其他计算对象
- 录制 C# Script 并保存为宏（此前称为“Custom Actions”）
- 集成 VertiPaq分析器
- DAX调试器

\*=仅在连接到 Analysis Services 或 Power BI 的实例时
