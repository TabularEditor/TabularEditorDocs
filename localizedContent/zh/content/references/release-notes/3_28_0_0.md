## v28.0.0 新增功能

如需了解概览，请参阅[发布博客](https://tabulareditor.com/blog/tabular-editor-3-november-2026-release)。

### TMDL 文件夹中的每个对象文件

Tabular Editor 3 企业版现在可以将 TMDL 文件夹保存为每个对象一个文件。每个列、度量值、分区和层次结构都在其表文件旁边的文件夹中拥有自己的文件。函数、共享表达式、数据源和关系也各自对应一个文件。计算项保留在其表格的文件中。然后，对一个度量的更改在源代码管理中显示为对一个文件的更改，并且编辑同一表的不同度量的两位开发人员不再编辑同一个文件。

要选择布局，请在**工具 > 首选项 > 文件格式 > 保存到文件夹 > TMDL 序列化**下，或在您打开的模型的**模型 > 序列化选项…**下，勾选**将对象保存到单独的文件**。所选内容将与文件夹一起存储，并且**文件 > 保存**将保留文件夹已有的布局。由早期版本或 Power BI Desktop 保存的文件夹将保留标准布局，直至您另行选择。

以这种方式保存的文件夹仍然是标准 TMDL。Power BI Desktop、Tabular Editor 2.26 或更高版本、Tabular Editor 3.19 或更高版本以及 Tabular Editor 3 Business Edition 可以打开它，并以标准布局将其保存回去。请勿在旧版本的 Tabular Editor 中打开此类文件夹，因为这可能会导致共享表达式的文本丢失。在保存操作将标准布局写入以这种方式保存的文件夹之前，Tabular Editor 3 会先征求您的意见。有关详细信息，请参阅新的 @tmdl-per-object-serialization 文章。

### 基本属性和高级属性视图

**属性**视图现在可以在底部显示两个选项卡：**基本**和**高级**。**基本**是一个表单，其中包含 Power BI Desktop 在其**模型视图**的“属性”窗格中显示的字段。这些字段被分组在“常规”、“格式”和“数据”等部分中，并提供选项开关以及 Power BI Desktop 使用的值名称。**高级**是属性网格，包含每个属性、工具栏和搜索功能。

**基本**是公开预览版。请在**工具 > 首选项 > Tabular Editor > 公开预览**下使用**基本属性视图**将其启用。在您启用之前，**属性**视图仅显示属性网格。视图将在您上次使用的选项卡上打开，您可以使用同一页面上的**“属性”视图选项卡**进行更改。

在**基本**选项卡上，您可以：

- 编辑 Power BI Desktop 为每种对象类型显示的字段，例如度量的**主表**和**格式**、关系的**源**和**目标**、KPI 的**状态**、**目标**和**趋势**以及模型的**兼容性级别**
- 点击表达式或角色的行级安全性筛选器，在**表达式编辑器**中打开它
- 从它们所属的对象打开**透视编辑器**、**元数据翻译编辑器**或**日历编辑器**
- 一次编辑多个所选对象。不同的字段显示 **（多个值）**，一次 **撤消**即可还原所有字段的更改
- 查看对象的多少个其他属性具有值，并使用**在“高级”中显示**在**“高级”**选项卡上列出这些属性

有关详细信息，请参阅 @properties-view。

### 字体偏好

**工具 > 首选项 > Tabular Editor > 用户界面** 下的新 **字体** 部分用于设置应用程序的字体。**用户界面字体**和**用户界面字体大小**（8 至 14 磅）适用于菜单、工具窗口、对话框、网格、消息框、代码编辑器工具提示和 AI 助手聊天。**代码编辑器字体大小**（8 至 14 磅，默认为 10 磅）适用于 DAX、M、SQL 和 C# 编辑器以及对话框中的代码框。更改将在 Tabular Editor 3 重新启动后生效。

字体列表仅显示计算机上已安装的字体。**语言默认值**使用 Segoe UI，或中文的 Microsoft YaHei UI 和日文的 Yu Gothic UI。**Ctrl+鼠标滚轮**仍可缩放当前会话的一个编辑器、**AI 助手**或**入门**页面。新的**“编辑”>“重置缩放”**命令（**Ctrl+0**）可将编辑器恢复为首选大小，并将**“AI 助手”**和**“入门”**页面恢复为 100%。有关详细信息，请参阅@preferences。

## v28.0.0 中的改进

- 在新的**安全**类别中添加了四条内置的 Best Practice Analyzer 规则。它们会标记行级或对象级安全性从未生效的角色、具有“读取”以外权限的 Power BI 角色、允许其成员查看其他角色受保护的模型中所有数据的角色，以及由于同时属于行级安全角色和对象级安全角色而导致查询失败的成员。请参阅@built-in-bpa-rules。
- DAX 编辑器现在可识别以下函数：[GROUPCROSSAPPLY](https://dax.guide/groupcrossapply/)、[GROUPCROSSAPPLYTABLE](https://dax.guide/groupcrossapplytable/)、[FILTERCLUSTER](https://dax.guide/filtercluster/)、[ALLSELECTEDAPPLY](https://dax.guide/allselectedapply/)、[ALLSELECTEDREMOVE](https://dax.guide/allselectedremove/)、[ALWAYSAPPLY](https://dax.guide/alwaysapply/)、[NONFILTER](https://dax.guide/nonfilter/)、[SHADOWCLUSTER](https://dax.guide/shadowcluster/) 和 [DEPENDON](https://dax.guide/dependon/)。此前，它们被标为未知函数并带有下划线。它们的参数和位置现在以引擎验证它们的方式进行验证，并且它们具有参数信息和 DAX 格式。自动补全仅在它们有效时才会建议使用，大小写形式根据您的**首选函数大小写**偏好设置而定。
- DAX 编辑器现在识别全文本搜索函数 [TEXTCONTAINS](https://dax.guide/textcontains/) 和 [TEXTSIMILARITY](https://dax.guide/textsimilarity/)，并提供参数信息和自动完成功能。之前，这两个函数都被标为未知函数并加下划线。自动补全仅建议启用全文索引的列，当列或参数无法用于全文搜索时，将显示错误。
- **DAX 调试器**现在可以调试 DAX 查询使用 `DEFINE MEASURE` 定义的度量值单元格。此前，系统会显示一条消息，指出无法调试查询范围内的度量值。
- **DAX 调试器**现在可以单步执行用户定义的函数，包括模型函数和 DAX 查询使用 `DEFINE FUNCTION` 定义的函数。函数调用会在**调用树**中显示其参数，然后显示函数的主体，而**局部变量**则会显示函数的参数以及传递给每个参数的实参。在您进行调试时，查询定义的代码现在会在 DAX 查询本身中显示并突出显示。在您停止调试之前，查询为只读状态，**调试**工具栏和菜单上的新**停止调试**按钮可结束会话。请参阅@dax-debugger。
- 现在，当调试停止时，无论是通过**调试 > 停止调试**、关闭已调试的文档还是关闭模型，**DAX 调试器**都会关闭其**局部变量**、**监视**、**评估语境**和**调用树**窗口。下一个调试会话将再次打开您上次离开时的窗口。之前，这些窗口在调试结束后仍保持打开状态且为空。
- 在 **TOM Explorer** 中选定的表和列现在在图表中醒目显示。表格标题采用当前主题的强调色，选定的列行采用 **TOM Explorer** 的选择色。图表的其余部分现在也遵循当前主题和调色板。之前，它使用固定的浅色或深色配色方案。当您选择多个表或列时，图表会突出显示其中的每个表；当您选择一个不在视图中的单个对象时，图表会在当前缩放级别下平移到该对象。
- 在文档选项卡的右键菜单中添加了“**复制**”命令。它将打开 DAX 查询、DAX 脚本、C# 脚本、图表或 Pivot Grid 的一个新未保存副本，让您可以在现有文档的基础上进行构建，而无需更改原始文档。感谢 [JuanSombrero23](https://github.com/JuanSombrero23) 在我们的 [GitHub 创意论坛](https://github.com/TabularEditor/TabularEditor3/discussions/1594)上提出的建议。
- 围绕要保存的格式重新设计了“保存到文件夹”首选项。**工具 > 首选项 > 文件格式 > 保存到文件夹** 现在设置了 **文件 > 保存到文件夹** 的默认格式，并且为每种文件夹格式提供了一个设置页面。**序列化模式**下拉菜单已消失。与 Model.bim 文件共享的设置现位于**文件格式 > 常规**，而**模型 > 序列化选项……**显示模型保存的格式。如果您使用了默认的 Database.json 模式，**文件 > 保存到文件夹**现在将写入 TMDL，您的**包含敏感信息**设置现在也适用于文件夹保存，并且**忽略增量刷新分区**已启用，这意味着 Model.bim 保存时也会省略这些分区。其他偏好将沿用。对于新安装，**忽略增量刷新分区**也默认为启用状态。请参阅@save-to-folder。
- 将模型保存到 TMDL 文件夹现在可以重用与模型一起存储的序列化设置，与保存到 Database.json 文件夹相同。此前，TMDL 保存始终使用“工具”>“首选项”中的设置，即使模型带有自己的设置也是如此。
- 现在，当打开模型时，TMDL 文件夹中的描述将保留其缩进以及前导和尾随空格，并且当重新打开文件夹时，角色成员上的注释和扩展属性将不再丢失。以前，像项目符号列表这样的缩进描述在保存并重新打开后会失去缩进。较早版本的 Tabular Editor 在打开和保存文件夹时仍会同时丢弃缩进和空格，这意味着共享 TMDL 文件夹的团队成员应一起更新。这些更改随 [Microsoft.AnalysisServices](https://www.nuget.org/packages/Microsoft.AnalysisServices/)（Tabular Object Model/AMO）更新至 19.120.1 而来。
- 将模型保存到 TMDL 或 Database.json 文件夹时，如果文件的完整路径达到 260 个字符或以上，现在会显示警告，因为 Power BI Desktop、不带 `core.longpaths` 的 Git 和 Windows PowerShell 5.1 无法打开此类文件。此类路径最有可能出现在深层文件夹中，且启用了**将对象保存到单独的文件**。警告会指出最长的路径，并建议使用较短的文件夹。仅当路径变长或更多文件受到影响时，**文件 > 保存**才会再次针对同一模型显示该警告，而**文件 > 另存为**和**文件 > 保存到文件夹**始终显示该警告。请参阅@save-to-folder。
- **属性**视图的**高级**选项卡上的属性类别**基本**现已更名为**常规**，以避免与新的**基本**选项卡混淆。
- **编辑 > 撤消**和**编辑 > 恢复**（**Ctrl+Z**、**Ctrl+Y**）现在在下拉列表或只读文本框获得焦点时（例如，在您在**属性**视图中选择一个值后）即可使用。之前，在您点击其他位置之前，它们不可用。

## v28.0.0 中的错误修复

- 修复了以下问题：在保存语义模型后，Tabular Editor 显示“字典中不存在给定的键”错误，该语义模型中另一个工具已在服务器上替换了表的增量刷新策略、度量的 KPI、分区的“数据覆盖范围”定义或列的“替代项”。之前，更改会被保存，但在保存过程中或显示受影响的对象时会出现错误，直到再次打开模型。现在，保存操作已在不出现错误的情况下完成，并且对象显示了来自服务器的值。
- 修复了编辑 **Model** 对象 **Database** 组中的属性（例如 **Name**、**Compatibility Level** 或 **Description**）时，未将该编辑显示为未保存更改的问题。之前，**TOM 资源管理器**中的**模型**节点保持未标记状态，**显示更改**隐藏了编辑，而**模型**节点上的**还原**将其保留在原处。现在，编辑内容会像其他内容一样被标记、还原和列出。
- 修复了对数据库**ID**的更改执行**编辑 > 撤消**或**编辑 > 恢复**时出现错误的问题。现在，“撤消”将恢复上一个 ID，“重做”将恢复已更改的 ID。
- 修复了**“编辑”>“撤消”**留下批注和空透视图条目（在保存后显示为源代码管理中的意外更改）的问题。之前，通过在**TOM 资源管理器**中拖动度量值或计算列，或通过在**属性**视图中更改**主表**，将度量值或计算列移动到另一个表，然后撤消该操作，会向对象添加 `TabularEditor_InPerspective` 和 `TabularEditor_Translated...` 注释，并在对象的每个透视中保留目标表的空条目。撤消将对象包含在其表未包含的透视中，以及在撤消从透视中删除表后执行**“编辑”>“重做”**，也会保留该表的空条目。现在，撤消和重做都不会留下任何内容。
- 修复了这样一个问题：撤消对度量值的**格式字符串**所做的更改时，未恢复度量值的`Format`注释（该注释由在 Visual Studio (SSDT) 中构建的模型存储，并会在格式字符串更改时被移除）。之前，**“编辑”>“撤消”**会恢复格式字符串，但注释仍被移除，且模型不再被标记为已更改，因此在下一次保存时该注释会被丢弃。现在，一次撤消操作即可恢复两者，而**编辑 > 重做**则会再次移除该注释。
- 修复了清除无效的**格式字符串表达式**后仍保留其错误的问题。此前，在从度量值中移除无效的格式字符串表达式后，该度量值在**TOM资源管理器**中仍保留其错误图标，并且错误仍保留在**消息**视图中，之后添加新的格式字符串表达式时仍会列出旧的错误。在**消息**视图中，对于计算项的格式字符串表达式、度量值的**明细行表达式**和表格的**默认明细行表达式**，以及计算组的**多选或空选择**和**无选择**表达式和格式字符串表达式，也会发生同样的情况。现在，只要清除表达式，错误就会消失。
- 修复了当模型连接到Analysis Services或Power BI/Fabric XMLA endpoint时，对数据库属性的更改丢失，并且该属性被重置为模型打开时的值的问题。之前，保存操作已完成且未出现错误，但服务器保留了旧值。对**Unicode 字符行为**本身的更改从未保存到服务器。现在，服务器会接收您保存的每个数据库属性值。
- 修复了在最近的 Windows 11 更新（例如 2026 年 10 月预览更新 (KB5127936)）中未列出正在运行的 Power BI Desktop 实例的问题。之前，**文件 > 打开 > 从数据库打开模型...**中的**本地实例**下拉列表一直为空。现在，实例再次列出，并显示其 Power BI Desktop 文件的名称。当没有本地实例运行时，下拉菜单会显示*未找到本地实例*，并且会在不重新打开对话框的情况下列出新启动的实例。
- 修复了一个问题，即以 **“保存到文件夹”** (Database.json) 格式将模型保存到现有文件夹的 C# 脚本可能会删除模型的大多数文件。以前，当文件夹路径使用正斜杠写入或包含双分隔符时，保存操作会报告成功，但只留下 `database.json`。现在，保存操作会保留模型的每个文件，仅删除已删除或已重命名的对象的文件。
- 修复了一个问题：DAX 用户定义函数在窗口函数（如 `ROWNUMBER`、`RANK`、`INDEX`、`OFFSET` 或 `WINDOW`）的 `ORDERBY`、`PARTITIONBY` 或 `MATCHBY` 中使用 `ANYREF` 或 `COLUMNREF` 参数时，尽管 Power BI 可以运行该函数，但仍会报告错误。之前，该函数及其调用的每个对象都会被标记为“在 Relation 参数中找不到列 [...]”。现在，该函数已被接受，只有在调用传递了 Power BI 也会拒绝的列时才会报告错误。
- 修复了一个问题：将 `COLUMNREF` 或 `ANYREF` 参数传递给 `DISTINCT` 的 DAX 用户定义函数在每次使用列调用时都被报告为错误，尽管 Power BI 能够运行它。之前，每个调用该函数的度量值都会被标记为*无法确定列……的单个值*。现在，该调用已被接受。通过 `ANYREF` 参数传递给 `DISTINCT` 的度量值仍会被报告。
- 修复了一个问题，该问题导致将区域设置名称传递给 `FORMAT` 在目标 Analysis Services 版本不支持该名称的模型中被报告为有效。此前，在针对 SQL Server Analysis Services 2022 之前版本的模型中，`FORMAT ( TODAY (), "dddd", "da-DK" )` 不会生成任何消息，该问题仅在部署时才会出现。第三个参数现在在 DAX 编辑器和**消息**视图中被标记。
- 修复了更改模型的**兼容级别**后，仍会显示有关新级别支持的 DAX 的消息的问题。之前，**消息**视图和**TOM资源管理器**中的警告图标会一直报告该表达式，直到模型被关闭并再次打开，并且打开的DAX脚本或DAX查询会保留旧级别的消息，例如，即使在您编辑后，也不支持用户定义的函数。DAX 编辑器、打开的 DAX 文档、**消息**视图和**TOM Explorer** 现在都会在兼容级别发生变化后立即使用当前兼容级别。
- 修复了将模型的**兼容级别**设置为其某个对象无法工作的值时，尽管该值被拒绝，但仍会在撤消历史记录中留下条目的问题。之前，按 **Ctrl+Z** 会撤消从未发生的更改。现在，消息会指明需要更高级别的对象，并且撤消历史记录保持不变。
- 修复了添加到 OneLake 表的 Direct Lake 的计算列无法保存到 Power BI 服务的问题。之前，创建列时将**表达式上下文**设置为“标准”，但服务会拒绝此设置。现在，在兼容级别 1705 或更高版本中，创建列时将**表达式上下文**设置为 UserContext，C# 脚本或 DAX 脚本添加列时也是如此，并且此类表中设置为 Standard 的计算列在**消息**视图中被报告为错误。请参阅@user-context-calculated-columns。
- 修复了一个问题：当大型模型仍在分析时编辑模型可能会失败，并显示“在调用 BeginUpdate() 之前调用了 EndUpdate()”，或者更改不会记录在撤消历史记录中。之前，这种情况可能在打开模型或撤消删除后立即发生。现在，编辑操作会正常记录。
- 修复了 DAX 表达式中值前面的负号或正号（例如 `-[Discount] + [Fee]` 或 `-2^2`）的读取方式与 Power BI 和 Analysis Services 的评估方式不同的问题。以前，这可能会导致表达式的数据类型错误或出现错误信息。现在，符号的运用方式与引擎的运用方式相同：`(-[Discount]) + [Fee]` 和 `-(2^2)`。对于此类度量值显示的数据类型（Best Practice Analyzer 规则也可以检查），可能会更改为引擎返回的数据类型。
- 修复了当表不在模型中时，格式化 DAX 查询会导致从传递给查询所定义函数的 `COLUMNREF` 或 `ANYREF` 参数的列中移除表名的问题。之前，`F ( T[Grp] )` 变为 `F ( [Grp] )`，然后查询失败。现在，列保留其表名。
- 修复了一个问题，该问题是，DAX 查询使用 `DEFINE MEASURE` 或 `DEFINE FUNCTION` 重新定义的度量值或函数也应用于查询所使用的模型度量值和函数中。此前，对于此类查询，这可能会显示错误的数据类型或错误，并且**DAX 调试器**会显示错误的值。现在，只有查询自己的代码才会使用重新定义，与 Analysis Services 和 Power BI 中一样。
- 修复了 C# 脚本失败时可能在未发出警告的情况下关闭 Tabular Editor 3 的问题。此前，某些脚本失败时不会显示错误信息，并且未保存的更改会丢失。现在，失败的脚本始终会报告出哪里出了问题，并且脚本更改的所有内容仍可撤消。
- 修复了 DAX 自动补全和参数信息中显示的 `APPROXIMATEDISTINCTCOUNT` 的描述。此前，它指出该函数需要 DirectQuery 模式。现在，它还涵盖导入模型和 Direct Lake 模型。
- 修复了 Tabular Editor 3 可能意外关闭的几个问题。这可能发生在以下情况下：在具有代码操作的 DAX 编辑器中键入时；在代码编辑器关闭后更改“**查找/替换**”选项时；在“**DAX 依赖项**”中滚动模式选择器时；在 DAX 查询到达服务器之前取消该查询时；在打开图表但未加载模型时；或在双击有关已删除对象的提示消息时。
- 修复了 **DAX 调试器**中的一个问题，即在在一列中返回多个文本值的监视或局部变量（例如 `VALUES('Product'[Color])`）中，`|` 在值中显示为“` ~!` ``”。
- 修复了当您在现有文本前面或内部输入时，DAX 自动补全不显示任何项，或显示所选项无法插入的列表的问题。之前，在现有引用前面输入 `[` 或 `'` 时，不会显示可用的列表，并且插入项目可能会删除光标后面的文本。现在，列表将根据您输入的内容进行筛选，您正在编辑的引用将被整体替换，而光标后的其他文本将保持不变。
- 修复了**数据刷新**视图中的行可能显示误导性持续时间或状态的问题。之前，快速刷新的所有行显示的大致持续时间都相同，并且服务器报告出错的表或分区仍可能显示为成功。现在，持续时间反映了在服务器上所花费的时间，失败的行仍标记为失败，在到达服务器之前失败的刷新会显示原因。
- 修复了“数据刷新”视图对于快速完成的刷新操作（例如对单个小表的“计算”刷新）不显示表和分区进度的一个问题。之前，仅显示顶级作业。
- 修复了在**表达式编辑器**中存在未应用的更改时，启动数据刷新却未显示警告的问题。之前，刷新是对之前保存的表达式执行的。现在，编辑器的更改会在刷新开始前应用，并且会显示**在处理之前保存更改？**提示。现在，在**日历编辑器**包含未应用更改时关闭或打开模型，也会询问是否保存这些更改。
- 修复了一个问题：在**“入门”**页面背后的嵌入式浏览器停止后，可能会出现意外错误，并且当浏览器无法启动时，页面会保持空白。现在，页面会说明发生了什么，并提供一个“重试”链接和一个指向该页面在线版本的链接。
- 修复了以下问题：当**AI 助手**的嵌入式浏览器无法启动时，它会显示错误报告和空白面板；如果浏览器稍后停止，则面板会保持为空。现在，面板会说明发生了什么，并提供一个“重试”链接，该链接会在不重启 Tabular Editor 3 的情况下，使用当前对话重新启动聊天。
- 修复了在 **AI 助手**启动时，Tabular Editor 3 关闭或布局发生变化时可能出现意外错误的问题。
- 修复了当**AI 助手**回复中的表格不适合面板时（例如，**用户界面字体大小**较大或面板较窄），该表格在消息右边缘被截断的问题。之前，最后一列会在单词中间被隐藏，整个对话会横向滚动。现在，如果表过宽，消息内部将显示该表自己的水平滚动条，并且其边缘会在隐藏更多列的一侧淡出。
- 修复了当**用户界面字体大小**高于默认值或使用显示缩放时，**元数据翻译编辑器**的**项目**列过窄的问题。之前，**模型**下的名称被截断为“P…”和“T…”，展开**表**后，较长的表名称也会被截断。现在，列的宽度足以容纳**模型**下的名称，并且在您展开名称不适合的节点时会变宽。通过拖动列边缘设置的宽度将得到保留。
- 修复了从 Power BI Project 语义模型的 `definition` 文件夹或 `definition\database.tmdl` 文件打开该模型时，窗口标题以“definition”开头的问题。现在，标题以语义模型文件夹的名称开头，不带其 `.SemanticModel` 后缀，位置显示包含该文件夹的文件夹。
- 修复了当“**属性**”视图显示包含“**替代**”的列时，Tabular Editor 3 可能意外关闭的问题。此前，这种情况会在撤消对列或其表的删除操作后，或在将带有“**替代**”的计算列移动到另一个表后发生。
- 修复了在“工具”>“首选项”>“Tabular Editor”>“代理设置”下输入的代理密码未保存的问题。此前，需要用户名和密码的自定义代理可能无法通过身份验证。如果您的代理需要密码，请在该页面上再次输入密码。
- 修复了以下问题：与服务器名称（例如，**“模型”>“部署...”**或**“文件”>“打开”>“从数据库打开模型...”**中的`powerbi://api.powerbi.com/v1.0/myorg/<workspace>;Password=<token>`）一起输入的密码或访问令牌以纯文本形式存储在最近服务器列表中，并再次显示在**“服务器”**框中。现在，在将服务器添加到列表之前，密码会被移除，并且在 Tabular Editor 3 首次启动时，早期版本存储的密码也会被移除。
- 修复了以下问题：在同时安装了 Tabular Editor 2 的计算机上，Tabular Editor 3 在首次启动时会接管 Tabular Editor 2 的所有偏好设置。此前，Tabular Editor 3 的默认设置（例如**忽略增量刷新分区**以及**工具 > 首选项 > 文件格式**下的 TMDL **保存为文件夹格式**）会被 Tabular Editor 2 的值替换，且不会有任何提示。现在，Tabular Editor 3 将使用其自身的默认设置启动。如果您的 Tabular Editor 2 序列化设置与它们不同，或者您在 Tabular Editor 2 中有 Best Practice Analyzer 规则，则在启动后会显示一个提示，列出将要导入的内容，并提供保留 Tabular Editor 3 设置或从 Tabular Editor 2 导入您的设置的选择。不再导入其他 Tabular Editor 2 首选项。请参阅 @migrate-from-te2。
- 修复了保存模型或刷新**Pivot Grid** 时有时会显示意外错误报告的问题。
- 修复了当同一表中的另一列绑定到同一源列时，**“模型”>“更新表架构”**将一列列为已移除的问题。之前，应用比较操作会删除该列。现在，绑定到仍存在的源列的每个列都将保留。
- 修复了当列绑定到用方括号（例如 `[amount]`）书写的源列名称时，**“模型”>“更新表架构”**将表的每一列同时报告为已删除和已添加的问题。Tabular Editor 2 为原生查询上的表写入此格式。之前，接受比较会删除并重新创建每一列，这会丢弃它们的属性并破坏引用它们的 DAX。现在，此类列与同名的源列相匹配。
- 修复了当 Tabular Editor 无法读取表的源时，**“模型”>“更新表架构”**可能会将表报告为最新版本的问题。现在，此类表被报告为无法检测到其架构的表。
- 修复了工具窗口（例如**表达式编辑器**、**数据刷新**、**消息**和**VertiPaq Analyzer**）以选项卡形式停靠在文档区域时，在重新启动 Tabular Editor 或从**窗口 > 布局**应用布局时，这些窗口的排列顺序丢失的问题。现在，选项卡将按照您离开时的顺序返回，已固定的选项卡将保持固定。

## 来自 Tabular Editor 2.x？

如需了解 Tabular Editor 3 主要功能的概览，请观看[此视频](https://youtu.be/O4ATwdzCvWc)。要开始使用，请参阅[入门指南](https://docs.tabulareditor.com/onboarding/index.html)。

**Tabular Editor 3 的主要功能：**
- 可定制的 IDE，支持多显示器、高 DPI 和主题
- 具备自动完成、语法检查、代码折叠和格式化功能的 DAX 代码编辑器
- *工作区模式，可将您的更改保存到磁盘，并同时将模型元数据同步到 Analysis Services
- *使用无限滚动预览表格数据，创建数据透视网格或编写 DAX 查询以浏览模型或测试计算逻辑
- *安排数据刷新
- 更新提供程序和 Structured 数据源上的表格架构，包括 M 查询
- 创建数据模型图
- 创建 DAX 脚本，以便在单个文档中编辑多个度量值或其他计算对象
- 录制 C# 脚本并将其保存为宏（原“自定义操作”）
- VertiPaq Analyzer 集成
- DAX 调试器
- DAX 优化器集成
- 用于重构您的 DAX 的代码操作

*=仅在连接到 Analysis Services 或 Power BI 实例时
