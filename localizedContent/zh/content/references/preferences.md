# Tabular Editor 3 首选项

“首选项”对话框用于控制 Tabular Editor 3 的用户界面、文件格式、连接性、数据浏览、AI 功能和编辑器行为。

本文介绍了 Tabular Editor 3 的“首选项”对话框以及您可以通过该对话框控制的设置。

要访问“首选项”对话框，请转到**工具 > 首选项**。

> [!NOTE]
> 所有 Tabular Editor 首选项均针对每个 Windows 用户配置文件存储在`%localappdata%\TabularEditor3`文件夹中。只需复制此文件夹的内容，即可将您的设置迁移到另一台计算机。

> [!TIP]
> 使用“偏好”对话框顶部的搜索框，可快速找到特定设置。

## Tabular Editor > 功能

![首选项常规功能](~/content/assets/images/pref-general-features.png)

### Power BI

**允许不受支持的编辑**（禁用）：仅适用于 2025 年 6 月之前的 Power BI Desktop 版本，这些版本限制了外部工具可以执行的建模操作。选中此项后，在 Tabular Editor 3 连接到此类版本时，所有 TOM 属性都可进行编辑，包括[Power BI Desktop 不支持](xref:desktop-limitations)的更改。此设置对 2025 年 6 月或更高版本的 Power BI Desktop 无效。

**隐藏自动日期/时间警告**（禁用）：选中时，将隐藏有关 Power BI 自动日期/时间表格的警告。当 Power BI Desktop 中的“自动日期/时间”设置启用时，这些警告就会出现。该设置会创建计算表格，从而在 Tabular Editor 3 的内置 DAX 分析器中触发警告。

**DAX第一行换行**（禁用）：在 Power BI Desktop 中，由于公式栏显示 DAX 代码的方式，通常会在 DAX 表达式的第一行插入换行符。如果您经常在 Tabular Editor 和 Power BI Desktop 之间来回切换，不妨启用此选项，让 Tabular Editor 3 自动插入换行符。

**仅适用于多行DAX表达式**（已启用）：当“DAX第一行换行”被启用时，此子设置控制是否仅对多行DAX表达式添加换行符。选中此选项后,单行表达式将保持不变。

**默认Power BI身份验证模式**（集成）：选择连接到Power BI数据集时使用的默认身份验证方法（集成、ServicePrincipal或MasterUser）。

### 最佳实践分析器

**在后台扫描最佳实践违规**（已启用）：每当模型发生变化时，就在后台线程上运行最佳实践分析器。如果取消勾选，请从**Best Practice Analyzer** 窗口运行分析。对于大型模型或具有复杂规则的模型，后台扫描会降低编辑速度。

**内置 BPA 规则**（对新用户启用）：选择是否启用、禁用或提示使用 Tabular Editor 的内置 Best Practice Analyzer 规则。内置规则涵盖格式化、元数据、模型布局、DAX 表达式和翻译等方面的关键最佳实践。新安装将默认启用内置规则。

### 通知

**数据刷新通知**（已启用）：选中此选项后，数据刷新操作完成后将显示通知。

### DAX 公式修正

**启用公式修正**（已启用）：当对象被重命名或移动时，自动调整 DAX 表达式中的引用。此功能可确保在您重组模型时，您的 DAX 代码仍保持有效。

**启用粘贴时的公式修正**（已启用）：粘贴对象时自动调整 DAX 表达式中的引用。这在表或模型之间复制度量值或计算列时非常有用。

## Tabular Editor > 更新和反馈

![更新和反馈首选项](~/content/assets/images/pref-updates-and-feedback.png)

### 更新

**在更新时显示“入门”页面**（已启用）：选中此项后，在 Tabular Editor 更新后首次运行时，将自动打开**“入门”**页面。它**在更新时**显示，而不是在每次启动时显示。您可以随时通过**“帮助”>“入门”**打开它。

**启动时检查更新**（已启用）：在应用程序启动时检查是否有新版本。

**仅主要更新**（禁用）：选中时，仅主要版本更新会触发通知。次要更新和补丁更新将被忽略。此设置仅在选中**启动时检查更新**时可用。

您正在运行的版本显示在这些设置下方，同时还有一个**检查更新**按钮，可立即运行检查。

### 由您的组织管理

如果管理员已配置[策略](xref:policies)，则此页面将附加一个只读的**由您的组织管理**部分，其中列出 Tabular Editor 找到的每个策略值，格式为`Name = value`。将鼠标悬停在条目上，查看其来自哪个注册表项和配置单元。

Tabular Editor 无法解释的值会显示 `(invalid)` 标记，而不是被省略。该标记是查找看似不起作用的策略背后的拼写错误的最快方法，因此，当策略未生效时，请先在此处检查。

当不适用任何策略时，此部分将不存在。策略锁定或限制的设置在此对话框的其他位置以及**工具 > MCP 服务器……**对话框中以只读形式显示，并带有说明此情况的工具提示。

### 使用数据和反馈

**通过收集匿名使用数据帮助改进 Tabular Editor**（已启用）：数据不包含任何个人身份信息，也不包含有关您的数据模型的结构或内容的任何信息。取消勾选此项，即可选择退出遥测数据收集。

**发送错误报告**（已启用）：选中此选项后，在发生崩溃时，Tabular Editor 将显示一个用于发送崩溃报告的选项。

**使用最新兼容级别作为默认值**（已启用）：自动为新模型使用最新的可用兼容级别。启用后，此选项将覆盖上述特定兼容级别设置，并且下拉菜单将被禁用。

**新模型使用工作区数据库**（已启用）：创建新模型时，在 Analysis Services 上自动创建工作区数据库。这使您能够在开发过程中立即测试和查询您的模型。

**默认保存模式**（AlwaysAsk）：选择是否始终保存为文件（.bim）、文件夹（多个 JSON 文件）、TMDL（表格模型定义语言），或在保存时始终询问。选项：AlwaysAsk、File、Folder、TMDL。

**保存到磁盘时使用 PBIX 文件名**（已启用）：保存从 PBIX 文件加载的模型时，使用 PBIX 文件名作为默认值。这可以保持 Power BI 文件与已保存模型元数据之间的命名一致性。

**为新模型创建用户选项**（启用）：自动为新模型创建 .tmuo（表格模型用户选项）文件。这些文件存储用户特定的设置，例如图表布局和窗口位置。

## Tabular Editor > 用户界面

控制工具栏和菜单、显示模型源位置的多少、窗口布局、语言、辅助功能以及最近项目列表。

### 工具栏和菜单

**在浮动窗口中显示工具栏**（启用）：在您取消停靠到浮动窗口的文档和视图中显示工具栏。

**隐藏非活跃工具栏**（启用）：隐藏不适用于活跃文档或视图的工具栏。

**隐藏非活跃菜单**（启用）：隐藏不适用于活跃文档或视图的[动态菜单](xref:user-interface#dynamic-menus-context-dependent)。

**隐藏版本号**（禁用）：从标题栏中隐藏 Tabular Editor 3 的构建号和版本号。

**模型源详细信息**（完整路径）：设置已加载模型的源位置在标题栏、状态栏连接项、文档选项卡工具提示以及最近文件和模型菜单的悬停文本中显示的程度：

- **完整路径**：模型名称及其完整路径、服务器或工作区位置
- **仅名称**：文件名、文件夹名称或数据库名称，不包含路径或服务器名称
- **隐藏**：不显示模型名称，也不显示其位置。当您连接到服务器时，标题栏显示**模型已加载**，状态栏显示**已连接**。

通过 @mcp-server 连接的代理会在同一级别接收模型标题。如果您在早期版本中选择了**隐藏模型源详细信息**，则此设置为**隐藏**。

### 搜索和替换

**非活跃时的对话框不透明度** (70% )：**查找和替换**对话框未获得焦点时的不透明度。

### 布局

**记住窗口是否最大化**（启用）：Tabular Editor 3 启动时，恢复主窗口的最大化状态。

**记住窗口位置和大小**（已启用）：Tabular Editor 3 启动时，恢复主窗口的位置和大小。

### 语言

**用户界面语言**（英语）：用户界面的语言。重启 Tabular Editor 3 以应用更改。

### 无障碍功能

**色盲模式**（禁用）：在**TOM 资源管理器**的更改指示器和模型比较视图中，将自上次保存以来添加的对象标记为青色（否则将显示为绿色）。请参阅@accessibility。

### 最近项目

**使用紧凑文件路径**（已启用）：缩短最近文件和模型菜单中的长文件路径。将“模型源详细信息”设置为“完整路径”后，标题栏的位置部分也会缩短。

**显示的最近文件数** (10)：最近文件菜单中的最大文件数，最多 50 个。

**显示的最近模型数**（10）：最近模型菜单中的最大模型数，最多 50 个。

**显示的最近服务器数** (10)：连接到语义模型时**服务器**列表中服务器的最大数量，最多 50 个。已固定的服务器不计入其中，并且始终保留在列表中。请参阅 @xmla-as-connectivity。

**清除最近文件**、**清除最近模型**、**清除最近服务器**和**清除所有最近项目**：清除相应列表。**清除最近服务器**和**清除所有最近项目**会保留已固定的服务器及其保存的设置。

## Tabular Editor > TOM Explorer

![TOM Explorer 设置](~/content/assets/images/unsaved-changes/preferences.png)

控制 TOM（Tabular Object Model）Explorer 如何显示模型，以及您删除的对象会发生什么情况。

决定哪些对象类型（例如度量值、列、层次结构、分区、显示文件夹和隐藏对象）显示在树中的切换开关不是偏好设置。它们位于 @tom-explorer-view 工具栏上，您可以在其中针对每个模型更改它们，而无需打开此对话框。

### 显示和筛选

**使用表格组**（已启用）：在 TOM Explorer 中对表格进行分组，例如将计算组、维度和事实表分开。Tabular Editor 在表格本身的注释中记录表格的组，因此分组会随模型一起移动。这是 Tabular Editor 内部的功能：其他客户端工具（包括 Power BI Desktop）都不会显示它。请参阅@table-groups。

**显示完整分支**（禁用）：当您筛选树时，Tabular Editor 会显示与您的筛选字符串匹配的对象及其父级。启用此选项还可以显示匹配项的每个子项，无论子项本身是否与字符串匹配。

**突出显示关系**（已启用）：突出显示涉及您所选表或列的关系，以便您可以一眼看出列与什么内容关联。

### 未保存的更改

这些设置控制如何在 TOM Explorer 和“属性”视图中显示[未保存的更改](xref:unsaved-changes)。

**标记具有未保存更改的对象**（已启用）：在 TOM Explorer 中突出显示与模型上次保存的版本不同的对象，使用带颜色的行和对象图标上的徽章：橙色表示已编辑的对象，绿色表示已添加的对象，红色表示已删除的对象。包含已更改对象的表、文件夹和组将显示阴影填充。禁用时，已删除的对象仍会根据以下设置保持可见，并且**显示更改**工具栏筛选器仍将有效。使用**用户界面 > 无障碍**下的**色盲模式**，将添加的对象标记为蓝绿色，而不是绿色。

**使已删除的对象保持可见**（直到模型保存为止）：已删除的对象在 TOM Explorer 中保持可见（带删除线）的时间，以及它们之前所在的位置。右键单击已删除的对象，然后选择**还原**以将其恢复。选项：

- **永不**：已删除的对象会立即从 TOM Explorer 中消失。
- **直到模型被保存**：已删除的对象被视为未保存的更改，并在模型被保存时消失。
- **直到模型关闭**：在整个编辑会话中，即使在多次保存后，已删除的对象仍保持可见且可恢复。

**将已删除对象归集到“已删除对象”节点下**（禁用）：将表、层次结构、角色或表组的已删除对象归集到其容器末尾的单个**“已删除对象”**节点下，而不是显示在它们原先所在的位置。右键单击该节点并选择**还原**，即可一次性将所有对象还原。

**在属性窗格中标记具有未保存更改的属性**（已启用）：使用带颜色的行突出显示属性视图中与模型上次保存的版本不同的属性。禁用时，属性视图中的**显示更改**工具栏筛选器仍可使用。

### 删除

**始终显示删除警告**（禁用）：要求您确认每次对象删除。如果取消选中，则仅在删除多个对象以及其他对象引用的对象时才会显示确认提示。

> [!NOTE]
> 按下 CTRL+Z 可撤消 Tabular Editor 3 中的所有删除操作。

### 本地化

这些设置决定了当您在属性窗格中为对象选择“货币”数字格式时，Tabular Editor 写入的格式字符串。

**默认货币**（英语（美国））：货币格式字符串所基于的格式化约定。选择您想要的货币符号、小数点分隔符和数字分组的区域设置。

**使用自定义货币符号**（禁用）：提供您自己的符号，而不是从上面的区域设置中选取符号。以下三项设置仅在选中此项时适用。

**自定义货币符号**：要使用的符号。单独输入符号，不带数字；空格将被忽略。

**自定义货币符号位置**（数字之前）：符号是在数值之前还是之后。

**在数字和符号之间添加空格**（禁用）：用空格将符号与数值分隔开。

控制复制对象时包含哪些元数据：

**包含翻译**（已启用）：随对象一起复制翻译元数据。启用后，为已复制对象定义的任何翻译也将被复制。

**包含透视**（已启用）：随对象一起复制透视成员资格。启用后，复制的对象将与原始对象属于相同的透视。

**包含 OLS**（已启用）：随对象一起复制对象级安全性设置。这适用于复制具有 OLS 限制的对象。

控制透视成员资格的处理方式：

**对新对象继承透视成员资格**（已禁用）：新创建的对象自动从其父级继承透视成员资格。例如，新度量值将自动添加到与其父表相同的透视中。

**对已移动的对象继承透视成员资格**（已禁用）：已移动的对象从其新父级继承透视成员资格。这在重组模型结构时非常有用。

**将表添加到透视时继承**（已启用）：将表添加到透视时，自动添加所有表对象（列、度量值、层次结构）。

**从透视中删除表时继承**（已启用）：从透视中删除表时，自动删除所有表对象。

## Tabular Editor > 架构比较

![架构比较首选项](~/content/assets/images/pref-schema-compare.png)

配置在更新表架构时，架构比较过程中要忽略哪些更改：

**忽略导入模式更改**（已禁用）：不标记对导入模式属性的更改。如果您希望在架构比较过程中忽略导入、DirectQuery 和双模式之间的更改，请启用此选项。

**忽略数据类型更改**（禁用）：不标记列数据类型更改。如果您希望在架构比较过程中忽略数据类型更改，请启用此选项。

**忽略说明更改**（已禁用）：不标记对象说明的更改。如果您不希望在架构比较中看到说明更改，请启用此选项。

**忽略十进制到双精度更改**（禁用）：不标记十进制和双精度数据类型之间的更改。处理不区分这些类型的数据源时，此选项非常有用。

**优先使用 Analysis Services 架构检测器**（禁用）：将 Analysis Services 元数据用作架构检测的权威来源。启用后，架构检测将直接查询 Analysis Services 实例。

## Tabular Editor > 保存到文件夹/文件

![“保存到文件夹”首选项](~/content/assets/images/pref-save-to-folder.png)

### 序列化模式

**使用 TMDL 格式**（禁用）：使用表格模型定义语言 (TMDL) 格式而非 JSON 格式保存模型元数据。TMDL 是建议用于版本控制和协作的现代格式。

**使用推荐的序列化设置**（启用）：应用基于文件夹的序列化的推荐设置（覆盖自定义设置）。启用后，Tabular Editor 将采用将模型保存到文件夹的最佳实践，并针对版本控制进行优化。

### 旧版 (JSON) 序列化设置

**文件名前缀**（已禁用）：为文件名添加数字前缀，以便排序。这有助于在文件资源管理器中保持一致的文件顺序。

**本地关系**（已启用）：将关系定义存储在各个表中，而不是存储在中心位置。这样，在使用版本控制时，更容易看到哪些关系属于每个表。

**本地透视**（已启用）：将透视成员资格存储在单个对象中，而不是存储在中心位置。这可以减少版本控制中的合并冲突。

**本地翻译**（已启用）：将翻译存储在单个对象中，而不是存储在中心位置。这可以减少版本控制中的合并冲突。

**级别**：选择要在不同文件夹级别序列化的对象类型。这使你能够将模型文件组织成层次结构。可用级别包括数据源、用户定义函数 (UDF)、共享表达式、透视、关系、角色、表、列、层次结构、度量值、分区、计算项和翻译。

**忽略推断对象**（已启用）：不序列化引擎自动推断的对象。这可以减少已保存元数据中的杂乱。

**忽略推断属性**（已启用）：不序列化由引擎自动推断的属性。这可以使保存的元数据保持简洁，并专注于显式设置的值。

**忽略时间戳**（已启用）：不序列化时间戳元数据。对于版本控制，强烈建议这样做，因为这可以防止每次提交时出现不必要的更改。

**忽略 Lineage tag**（禁用）：不序列化 Power BI Lineage tag 元数据。如果您不希望保存的元数据中包含沿袭信息，请启用此选项。

**忽略隐私设置**（禁用）：不序列化数据源隐私设置。如果您单独管理隐私设置,请启用此选项。

**包含敏感数据**（已禁用）：在序列化元数据中包含敏感信息（如密码）。出于安全原因，不建议这样做。

**忽略增量刷新分区**（禁用）：不序列化由增量刷新策略创建的分区。如果您希望将增量刷新与保存的元数据分开管理,请启用此选项。

**拆分多行字符串**（已启用）：将长字符串值拆分为多行，以便在版本控制中更易于阅读。这使您更容易看到 DAX 表达式和其他长文本属性的变化。

**对数组排序**（已禁用）：按字母顺序对数组元素排序，以实现一致的序列化。减少版本控制中的排序差异，并更改某些元素的顺序。

### TMDL 序列化设置

**缩进模式**（制表符）：在 TMDL 文件中选择使用制表符或空格进行缩进。制表符是默认且推荐的选项。

## 数据浏览 > DAX 查询

<!-- 重新截取屏幕截图 (3.27.1)：pref-dax-query.png。显示“打开其他模型时保持 DAX 查询打开”部分。-->
![DAX 查询偏好](~/content/assets/images/pref-dax-query.png)

### 基本

**默认自动执行 DAX 查询**（已启用）：新的 DAX 查询在打开时将启用**自动执行**，因此每当对已部署的语义模型进行更改时，查询都会重新运行。如果您希望自行执行每个查询，请将其关闭。

**在结果网格中保留现有排序和筛选** (WhenQueryUnchanged)：控制在重新执行查询时是否保留网格筛选和排序：
- **从不**：执行查询时，排序和筛选始终被重置
- **WhenQueryUnchanged**：仅当查询被修改时，排序和过滤才会被重置
- **始终**：如果列仍然存在，则绝不会重置排序和筛选

### 查询设置

**智能选择**（已启用）：当您执行查询的一部分时，Tabular Editor 会代您将该选择转换为有效的 DAX 查询，将标量表达式包裹在花括号中，并在它们不是选择的一部分时添加 `DEFINE` 部分或 `EVALUATE` 关键字。在包含多个 `DEFINE ... EVALUATE` 查询的文档中，添加的 `DEFINE` 部分是属于所选查询的部分。所选列引用（包括 `ORDER BY` 子句中的列引用）将返回该列的非重复值。

**行数限制**（1,000）：将每个 `EVALUATE` 语句包装在 `TOPN` 调用中，以防止对大表进行的意外查询长时间运行或耗尽内存。将其设置为 `0` 以完全移除限制。

### 代码生成

**使用注释作为分隔符**（已启用）：将注释插入生成的对象定义中，例如由**在查询中定义对象**生成的 `DEFINE` 块，以便于阅读。

### 切换模型时保持文档打开状态

**打开其他模型时保持 DAX 查询打开**（启用）：打开其他模型时，保持 DAX 查询文档打开。查询文本将被保留，先前的结果将被清除，查询将对新打开的模型执行。禁用时，DAX 查询文档将与上一个模型一起关闭。请参阅@dax-query。

**行数限制** (100)：在 DirectQuery 模式下，为表预览检索的最大行数。如果需要查看更多数据，请提高此值，但请记住，每行数据都是从底层源中提取的。

**在 TOM Explorer 中跟踪所选列**（已启用）：当您在 @tom-explorer-view 中选择一列时，打开的表格预览会将该列滚动到视图中并突出显示，这是查找非常宽的表格中的一列的最快方式。对于单个预览，可以使用表格预览工具栏上的**跟踪所选列**来启用和禁用相同的设置。

Tabular Editor 3 的 DAX 编辑器具有高度可配置性。此页面提供 DAX 编辑器常规配置的设置：

**代码折叠**（已启用）：在 DAX 代码中启用可折叠区域，以提高可读性。请务必试用此功能！

**注释样式**（斜杠）：DAX 支持使用斜杠 (`//`) 或连字符 (`--`) 的行注释。此设置确定 Tabular Editor 3 生成 DAX 代码时使用哪种注释样式。

**DAX 函数文档**：使用此设置指定当光标位于 DAX 函数上时，每次按 F12 键时在默认网页浏览器中打开的 URL。选项包括 https://dax.guide（推荐）和 Microsoft 的官方文档。

**Analysis Services 版本设置**：只有当 Tabular Editor 3 无法确定所使用的 Analysis Services 版本时（例如直接加载 Model.bim 文件时），这些设置才适用。在这种情况下，Tabular Editor 会根据兼容级别尝试猜测模型将部署到哪个版本。如果 Tabular Editor 报告不正确的语义或语法错误，请将这些设置设置为您要部署到的 Analysis Services 版本。

## 文本编辑器 > DAX编辑器 > 自动格式化

![自动格式化设置](~/content/assets/images/auto-formatting-settings.png)

DAX 编辑器**非常**强大，可帮助您在键入时生成美观、易于阅读的 DAX 代码。

**键入时自动格式化代码**（启用）：按下特定键时应用格式化规则。例如，当右括号闭合时，括号内的所有内容都会根据此页面上的其他设置进行格式化。

**自动格式化函数调用**（已启用）：在右括号键入时格式化函数调用（参数和括号之间的空格）。

**自动缩进**（已启用）：此选项在函数调用中插入换行符时自动缩进函数参数。

**自动添加括号**（已启用）：此选项会在每次输入左括号或引号时自动插入右括号或引号。

**Wrap选择**（已启用）：启用此选项后，当输入左大括号时，此选项将自动使用右大括号Wrap当前选择。

### 大小写和引号

除了格式化 DAX 代码的空白字符外，Tabular Editor 3 还可以修复对象引用以及函数/关键字的大小写。

**修正度量值/列限定符**（启用）：选中此项时，表前缀将自动从度量值引用中移除，并自动插入到列引用中。

**首选关键字大小写**（大写）：此设置允许您更改关键字使用的大小写，例如 `ORDER BY`、`VAR`、`EVALUATE` 等。它还控制着自动补全功能为使用这些关键字的函数提供的固定关键字值：`ASC` 和 `DESC`、`KEEP`、`FIRST`、`LAST` 和 `DEFAULT`、`CROSSFILTER` 方向以及 `LOOKUP` 的 `EXPLICIT` 和 `INFERRED`。选择**仅首字母大写**，以提供`Explicit`而不是`EXPLICIT`。

**首选函数大小写**（大写）：此设置允许您更改函数使用的大小写，例如 `CALCULATE(...)`、`SUM(...)` 等。

**修正关键字/函数大小写**（已启用）：选中此选项后，每当代码自动格式化或手动格式化时，关键字和函数的大小写都会自动修正。

**修正对象引用大小写**（已启用）：DAX 是一种不区分大小写的语言。启用此选项后，对表、列和度量值的引用将自动修正，使大小写与被引用对象物理名称的大小写相匹配。

**始终引用表**（禁用）：在 DAX 中引用某些表名时，不需要使用单引号括起来。但是，如果您希望表引用始终带引号，则可以选中此选项。

**始终为扩展列添加前缀**（禁用）：可以不使用表名来定义扩展列。选中此选项后,DAX编辑器将为扩展列添加表名前缀。
