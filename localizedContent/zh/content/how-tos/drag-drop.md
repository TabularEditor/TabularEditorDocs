# 拖放对象

在@tom-explorer-view中拖放可在显示文件夹、表格、层次结构、计算组和表格组之间移动对象。拖动始终会移动对象，没有修饰键可将其转换为副本。拖动时，移动光标显示允许放置的位置，禁止放置光标显示不允许放置的位置。**复制**（在 @duplicate-and-batch 中有介绍）可复制对象。

## 移动显示文件夹

将显示文件夹拖到另一个文件夹上即可移动该文件夹。其中的每个对象和子文件夹都随之移动，并且子文件夹结构得以保留。

您还可以：

- 按住 **Ctrl 并单击** 或 **Shift 并单击** 以选择多个对象，然后将它们一起拖动。如果度量值、列、层次结构和文件夹位于同一表格中，您可以将它们混合在一起。
- 将对象拖放到表节点上，将其从所在文件夹移至表的顶层。
- 将一个文件夹拖放到另一个文件夹上，即可将其嵌套。您不能将文件夹拖放到其自身的子文件夹中。

每次拖放都是一个撤消步骤（**Ctrl+Z**），无论它移动了多少个对象。

显示文件夹是每个对象的字符串属性，使用“`\`”分隔各级：“`Sales\Ratios`”是“Sales”中的“Ratios”文件夹。要在一个以上的文件夹中显示对象，请使用`;`分隔路径。

## 将对象移动到另一个表

将度量值和计算列拖到另一个表上，或者在 Tabular Editor 3 中拖到该表中的显示文件夹上，以将它们移动到该位置。对于其他对象类型，则无法执行此操作。

在 Tabular Editor 3 中，移动操作会保留对象的以下内容：

- 其名称和说明的翻译
- 透视成员资格，除非您在**工具 > 偏好设置 > Tabular Editor > 建模操作**下选择**将对象粘贴/移动到表时继承表成员资格**，这将使对象具有目标表的透视成员资格
- KPI（对于具有 KPI 的度量值）
- 错误和警告指示符，因此无效表达式在移动后仍被标记为无效

> [!WARNING]
> 当您将计算列移动到另一个表时，不会出现确认提示，并且以下内容将发生变化：
>
> - 使用该列的关系将被删除
> - 基于该列的层次结构级别被删除
> - 该列将从日历和变体中移除
> - 对该列的 `SortByColumn` 引用被清除
>
> 按 **Ctrl+Z** 一步撤消移动和所有这些更改。

通过旧表引用该列的 DAX（例如 `'Reseller Sales'[Margin]`）不会被重写，并且会继续指向该列离开的表。度量值引用写为`[Measure]`，不带表，因此不受影响。运行 @using-bpa 或在移动后检查 @messages-view ，以了解哪些内容出现问题。在“信息”视图中，取消选中**显示级联错误**，以便仅列出您需要修复的表达式。

## 构建层次结构和排序计算项

- 将一个或多个列拖动到层次结构上，将其添加为级别。拖放到两个现有级别之间，以选择位置。您无法添加已经是该层次结构级别的列。
- 拖动层次结构中的级别以重新排序，或拖动到同一表中的另一个层次结构以将其移动到该处。
- 拖动计算项，以便在其计算组中重新排序，或拖动到另一个计算组以将其移动。

## 表格分组

> [!NOTE]
> 表组仅在 Tabular Editor 3 中可用。

将一个或多个表格拖动到表格组中，将其移入该组，或拖动到另一个表格中，将其移入该表格的组中。将表格拖放到不属于任何组的表格上，会将它们从其组中移除。表组用于组织 TOM Explorer，并以注释形式存储，Power BI 和 Analysis Services 会忽略这些注释。

## 显示文件夹和翻译

拖动操作仅会更改 TOM Explorer 中所选翻译的显示文件夹：

- 如果未选择翻译（默认），则拖动操作会更改未翻译的显示文件夹。已翻译的显示文件夹不会发生变化，因此已翻译的视图仍会显示旧文件夹中的对象。
- 如果在 TOM Explorer 的翻译下拉列表中选择了某种文化，则拖动操作将更改该文化的已翻译显示文件夹，而未翻译的显示文件夹将保持不变。

在 @metadata-translation-editor 中更新翻译，或使用 [为所有文化翻译显示文件夹](xref:kb.bpa-translate-display-folders) Best Practice Analyzer 规则的修复功能，该功能会将未翻译的值复制到每种文化中。

## 可以拖动哪些内容，以及可以拖动到哪里

| 拖动 | 到 | 结果 |
|---|---|---|
| 度量值、列、层次结构、文件夹 | 同一表中的显示文件夹 | 对象移动到该文件夹中 |
| 度量值、列、层次结构、文件夹 | 表格节点 | 对象离开其文件夹 |
| 度量值、计算列 | 另一个表或其中的文件夹（文件夹：仅限 Tabular Editor 3）| 对象移动到该表 |
| 列 | 层次结构或其一个级别 | 列将作为级别添加 |
| 级别 | 同一层次结构，或表格中的另一个层次结构 | 级别被重新排序或移动 |
| 计算项 | 其所属组或其他计算组 | 计算项被重新排序或移动 |
| 表格（仅限 Tabular Editor 3）| 表格组或其他表格 | 表格移动到该组 |

适用以下限制：

- 分区、角色、透视、关系、数据源和共享表达式无法拖动。
- 在 Tabular Editor 3.27.0 及更高版本中，自上次保存以来被删除的对象在树中显示为带删除线的形式，您无法拖动它们或将对象拖放到它们上。
- 仅当显示文件夹和表格组在 TOM Explorer 工具栏中启用时，它们才接受拖放操作。

## 通过脚本进行相同的更改

脚本通过设置`DisplayFolder`字符串在显示文件夹之间移动对象。在常规 C# 字符串或逐字字符串中使用 `\\`：

```csharp
Selected.Measures.SetDisplayFolder(@"Sales\Ratios");
Model.Tables["Sales"].Measures["Margin %"].DisplayFolder = @"Sales\Ratios";
Model.Tables["Sales"].Measures["Margin %"].TranslatedDisplayFolders["da-DK"] = @"Salg\Nøgletal";
```

`MoveTo` 将 Measure 移动到另一个表，并保留其错误指示符：

```csharp
Model.Tables["Sales"].Measures["Margin %"].MoveTo(Model.Tables["Reseller Sales"]);
```

脚本 API 没有将计算列移动到另一个表的方法。在 Tabular Editor 3 中，设置 `TableGroup` 可将表移动到表组：`Model.Tables["Sales"].TableGroup = "Facts";`，在您运行的脚本中，如 @csharp-scripts 中所述。

## 拖动到其他视图

您还可以将对象从 TOM Explorer 拖动到：

- DAX 或 C# 编辑器，以插入对象的完全限定名称。请参阅@dax-editor。
- 打开的模型图表，以便向其中添加表格。在图表中，将列拖动到另一个表格的列上，以创建关系。请参阅@diagram-view。
- [Pivot Grid](xref:pivot-grid)，以将列、度量值或层次结构添加为字段。

模型图和数据透视网格仅在 Tabular Editor 3 中可用。
