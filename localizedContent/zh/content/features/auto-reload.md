# 从磁盘自动重新加载

在你工作时，模型会同时存在两份：一份是 Tabular Editor 在内存中保存的副本，另一份是磁盘上用于加载该模型的元数据文件。只改其中一份而不改另一份，就会让两者失去同步。

![Tabular Editor 在内存中保存模型，磁盘上的文件也保存着同一个模型；File > Save 会将内存中的内容写入磁盘，自动重新加载则会把更改从磁盘带回内存，而其他工具（例如代理、脚本或 Git pull）会直接写入这些文件](~/content/assets/images/features/auto-reload-sync.png)

Tabular Editor 会在两个方向上让它们保持同步：

| 方向    | 触发方式                                                |
| ----- | --------------------------------------------------- |
| 内存到磁盘 | 你可以随时执行 **文件 > 保存**（**Ctrl+S**）。                    |
| 磁盘到内存 | 自动，因为 Tabular Editor 会监视这些文件，并在它们被其他程序或操作改动时重新加载模型。 |

另一个工具通常是 AI 代理或脚本，但也可能是另一个编辑器、一次 `git pull`，或是在共享文件夹中工作的同事。

> [!NOTE]
> 这是文件级同步。这与 **跟踪外部模型更改** 和 **自动刷新本地 Tabular Object Model 元数据** 不同；这两个选项也位于 [工具 > 偏好 > 杂项](xref:preferences#miscellaneous) 中、紧挨着此项，但它们会启动 Analysis Services 跟踪，以检测对 _已连接的数据库_ 所做的更改。这两种机制彼此独立，覆盖的变更来源也不同。

## Tabular Editor 监视的内容

| 模型加载来源                                       | 是否监视                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `.bim` 文件                                    | 仅此一个文件。同一文件夹中的其他文件会被忽略。                                                   |
| 采用 JSON（Database.json）格式的文件夹 | 模型根目录下的每个 `.json` 文件，包括子文件夹中的文件。                                          |
| 采用 [表格模型定义语言（TMDL）](xref:tmdl) 格式的文件夹        | 模型根目录下的每个 `.tmdl` 文件，包括子文件夹中的文件。                                          |
| Workspace 数据库                                | 在 [工作区模式](xref:workspace-mode) 下为 Workspace 数据库支撑该模型的文件，并按与上面两行相同的规则进行监视。 |
| 数据库或 Power BI Desktop，在工作区模式之外               | 没有。该模型在磁盘上没有文件，因此不存在需要对照的两个副本。                                            |
| `.pbit` 模板，或从未保存过的模型                         | 没有。 `.pbit` 是二进制文件，任何外部工具都不会直接在原文件上编辑它。                                   |

## 仅文件发生更改时

如果你没有未保存的更改，那么只有一个副本发生了变化，因此无需比较取舍。 Tabular Editor 会重新加载模型，使两者重新保持同步。

## 当两个副本都发生更改时

如果你也有未保存的更改，那么两个副本都已变化，而且内容不一致。 Tabular Editor 无法合并模型元数据，因此会让你选择以哪个副本为准。

![当 Tabular Editor 检测到两个副本都已更改时显示的提示](~/content/assets/images/features/external-changes-prompt.png)

- **重新加载** 会丢弃你未保存的更改，并采用磁盘上的版本。
- **忽略** 会保留你的更改，并让模型保持当前状态。磁盘上的文件不会被改动，因此两个副本会继续不同步，直到你下次保存时把它们覆盖为止。

默认情况下，选择 **忽略** 最安全。按 Esc，或点击窗口的关闭按钮关闭该提示，效果与选择 **忽略** 完全相同，都会保留你的更改。

> [!WARNING]
> 如果你选择 **重新加载**，Tabular Editor 会直接丢弃你尚未保存的更改，不会再额外确认，并且你也无法撤销这次重新加载。

### 典型步骤

1. 你打开一个 TMDL 文件夹模型，然后重命名一个度量值。内存中的副本已经先于磁盘文件发生了变化。
2. 一个在同一文件夹中工作的 AI 代理重写了四个 TMDL `.tmdl` 文件。现在，两个副本都变了，而且变化方向不同。
3. Tabular Editor 会等待代理的写入稳定下来，然后弹出一个 **检测到外部更改** 的提示。
4. 你选择 **重新加载**。你对度量值的重命名已丢失；代理写入的四个文件已加载；两个副本重新同步；并且 TOM Explorer 仍展开在你之前处理的那张表上。

如果你当时选择的是 **忽略**，你的重命名会保留下来，两个副本会继续不一致，而代理写入的那四个文件会在你下次按 **Ctrl+S** 时被覆盖。

## 合并与后台更改

重写以文件夹形式序列化的模型的工具，会在极短时间内连续修改许多文件。 Tabular Editor 会等待这些写入稳定下来，然后只重新加载一次，而不是每个文件重新加载一次。

当 Tabular Editor 处于后台时到达的更改不会立即提示，而是先暂存起来。当你切回 Tabular Editor 时，系统只会询问你一次，因此即使你刚从一个重写了十几个文件的代理会话返回，也只会看到一个提示。

## 工作区模式

[工作区模式](xref:workspace-mode) 会增加第三个副本：服务器上的 Workspace 数据库。重新加载也会重新部署它，这样三个副本就能保持同步，而不会让服务器继续使用文件已不再描述的元数据。

## 关闭该功能

默认启用自动重新加载。要把从磁盘到内存的同步改回手动，请在 **工具 > 偏好 > 杂项** 下取消选中 **从磁盘自动重新加载**。

![工具 > 偏好 > 杂项，其中显示了“元数据同步”下的自动重新加载设置](~/content/assets/images/pref-miscellaneous.png)

如果模型文件夹还会被持续运行的其他程序写入，例如文件同步客户端，或会在后台刷新的 CI 检出目录，请将其关闭。该提示是模态的，因此如果文件夹经常变化，它更像是在打断你，而不是帮到你。

清除该设置后，Tabular Editor 将不再监视任何内容；只有当你使用 **文件 > 从磁盘重新加载** 或 **文件 > 保存** 时，这两份副本才会重新合并。

该页面上的其他设置请参见[偏好](xref:preferences#miscellaneous)。
