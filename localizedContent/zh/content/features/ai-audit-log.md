# AI 审计日志

Tabular Editor 3 企业版会在本机保留一份记录，记录 [AI 助手](xref:ai-assistant) 和 [MCP 服务器](xref:mcp-server) 在这台电脑上执行过的操作。它回答了审计人员真正关心的问题：请求了哪些权限、这些请求如何被回应；运行了哪些工具、每个工具如何结束；以及任何由代理编写的 C# Script 脚本中包含的内容。

这份记录经过专门设计，可安全收集。它只记录 _类别和结果_，绝不记录内容。也就是说，其中不会写入你的提示、助手的回复，或模型中的数据值。

## 记录存放位置

除非管理员已将其移到别处，否则日志会写入：

```
%LocalAppData%\TabularEditor3\AI\audit
```

你可以通过 **打开审计文件夹** 访问它。这个选项位于两处：**工具 > 偏好 > AI 功能**，以及 **工具 > MCP 服务器...** 对话框中。该文件夹会在首次有内容需要写入时创建，因此全新安装后，它可能还不存在，暂时无法打开。

在其中，你会看到每天一个文件 `ai-audit-<date>.jsonl`，按 UTC 日期轮换；另有一个 `scripts` 文件夹，用于在 `scripts\\<date>` 下保存脚本本身。

## 记录了什么

每一行都是一个 JSON 对象。每条记录开头都包含相同的字段：

| 字段          | 包含内容                                      |
| ----------- | ----------------------------------------- |
| `ts`        | 发生时间，采用 UTC，精确到毫秒                         |
| `event`     | 该记录的类型，取值见下表                              |
| `surface`   | `chat` 表示 AI 助手，`mcp` 表示通过 MCP 服务器连接的外部代理 |
| `sessionId` | 该操作所属的对话或 MCP 会话。若两者都不适用，则不会包含该字段         |
| `model`     | 当时打开的语义模型的名称。未打开任何模型时不包含此字段               |
| `user`      | Windows 账户名                               |

接下来是属于该事件的字段：

| `event`       | 写入时机                 | 包含内容                                                                                           |
| ------------- | -------------------- | ---------------------------------------------------------------------------------------------- |
| `consent`     | 请求权限时                | 资源、访问级别、是一次性授权还是持续授权、你是否批准或拒绝，以及授权持续时长                                                         |
| `tool_call`   | 工具运行时                | 工具名称、所需权限，格式为 `Resource:Access`、结束方式、耗时的毫秒数、其参数&#x7684;_&#x540D;&#x79F0;_&#x4EE5;及这些参数值总大小的字节数 |
| `script`      | 智能体运行或提交 C# Script 时 | 工具、状态、结果、已保存副本的路径、其 SHA-256 哈希，以及它对模型进行了多少项更改                                                  |
| `turn`        | 一轮聊天结束时              | 提供方、模型名称、端点主机、结果、轮次编号以及令牌数量，包括已缓存和已计费的部分                                                       |
| `config`      | AI 配置发生更改时           | 提供方、模型名称和端点主机                                                                                  |
| `mcp_server`  | MCP 服务器启动或停止时        | 端口、是否需要访问令牌，以及启动时对五类资源分别授予的权限                                                                  |
| `mcp_session` | 智能体连接或断开连接           | 客户端的名称和版本，以及协商出的 MCP 协议版本                                                                      |

一个 `tool_call` 记录会以以下五种方式之一结束：`ok`、`error`、在所需权限未授予时为 `denied`、在被管理员设置的上限拒绝时为 `policy`，或在你中止该轮次，或客户端在完成前断开连接时为 `cancelled`。

### 脚本会完整保留

`script` 事件是“记录类别，而非内容”这一原则的例外，而且这是有意为之：智能体针对你的模型运行过的脚本，是事后你最需要能够查看的内容。脚本文本不会写入日志行。相反，脚本会按原样另存为 `scripts\\<date>` 下的独立 `.csx` 文件，而该日志行会指向该文件并附带其 SHA-256 哈希，这样你就能证明磁盘上的文件就是实际运行过的那个文件。

## 永不记录的内容

- 你的提示词文本和助手的回复。
- 模型中的任何值。 `tool_call` 只记录工具带有参数以及参数有多大，绝不会记录参数内容。
- API 密钥和访问令牌。

## 保留期限

超过 30 天的文件会被删除。清理会在每个会话中运行一次，且在写入第一行之前执行，因此如果 Tabular Editor 从未打开过，就不会修剪旧文件。

管理员可以调整保留期限，也可以选择永久保留所有内容。参见下方策略。

## 管理审计日志

有两项[策略](xref:policies)用于控制该日志。两者都需要企业版。

| 值                         | 类型             | 作用                                                             |
| ------------------------- | -------------- | -------------------------------------------------------------- |
| `AiAuditLogPath`          | 路径             | 将日志写入其他位置，以便集中收集。指向网络共享的 UNC 路径可用。路径必须是绝对路径；相对路径会被忽略，并将使用默认文件夹 |
| `AiAuditLogRetentionDays` | 数值，范围 0 到 3650 | 要保留的天数。 `0` 表示全部保留。默认值为 30                                     |

重定向日志时，已保存的脚本也会一并移动，因为它们位于同一文件夹中。

审计绝不会影响被审计功能本身。例如，如果由于重定向后的共享不可访问而导致日志无法写入，系统会在 Tabular Editor 自身的日志中记录一次该失败，随后 AI 助手和 MCP 服务器会继续运行。
