# 模型部署

Tabular Editor 3（Business Edition 和 Enterprise Edition）可以复制当前加载的语义模型元数据，并将其部署到 Analysis Services 实例或 Power BI/Fabric XMLA endpoint。

要执行部署，请通过**“模型”>“部署...”**菜单选项启动**“部署向导”**。

> [!NOTE]
> Tabular Editor 3 商业版在 XMLA 连接支持的 Analysis Services 实例类型或 Power BI/Fabric 工作区方面存在一定的[限制](xref:editions)。这也适用于部署。

## 目标服务器

在**目标服务器**页面上，输入服务器名称，或从最近服务器的**服务器**列表中选择一个。右键单击列表中的服务器，将其固定到列表顶部或将其删除。该列表与**文件 > 打开 > 从数据库打开模型…**共享。有关详细信息，请参阅[最近使用的服务器和已固定的服务器](xref:xmla-as-connectivity#recent-and-pinned-servers)。

## 部署选项

选择要部署的目标服务器和数据库后，系统将显示**部署选项**列表，如下图所示。

![部署选项](~/content/assets/images/deployment-options.png)

这些选项包括：

- **部署模型结构**：这表示将部署模型元数据。取消选中此选项将阻止您执行部署（此选项出于历史原因而存在）。
- **部署数据源**：对于使用*显式*数据源的模型，此选项表示是否将任何此类数据源包含在部署中。如果数据源上的一个或多个属性已被修改，且你并不打算部署这些修改，则取消选中此选项可能很有用。例如，如果您要将模型元数据从开发环境部署到测试环境，您可能希望在目标环境中保留所有连接字符串等内容的原样。请注意，此选项通常不会对 Power BI / Fabric 语义模型启用，因为此类模型使用*隐式*数据源，其中凭据由 Power BI 服务管理，连接详细信息存储在模型中分区上的 M 查询或共享表达式中。
- **部署表分区**：此选项指示是否应部署表分区。在某些情况下，目标数据库可能包含模型元数据中不存在的分区。取消选中此选项将阻止部署修改目标服务器上的任何现有分区。如果选中此选项，Tabular Editor 将使目标服务器上的分区与模型元数据同步。如果目标服务器上存在任何分区，但模型元数据中不存在这些分区，则将删除这些分区（包括其中包含的数据）。
  - **部署受增量刷新策略管理的分区**：启用**部署表分区**选项时，您将有一个选项，以避免部署受增量刷新策略管理的分区。当您的模型包含由[增量刷新策略](xref:incremental-refresh-about)自动创建的分区，并且您希望部署除受该策略约束的分区之外的所有分区时，此选项非常有用。
- **部署共享表达式**：部署模型的共享表达式，例如 Power Query 参数和共享查询。取消选中此选项，以保留目标数据库中存在的共享表达式。
- **部署模型角色**：此选项指示是否应部署模型中定义的角色。取消选中此选项将按原样保留模型上的现有角色。如果您正在部署对模型中表或列的更改，则可能需要重新查看[RLS 或 OLS 设置](xref:data-security-about)，以确保它们仍然有效。
  - **部署模型角色成员**：此选项指示是否应部署角色成员。通常会在服务器上直接管理角色成员，而不是在模型元数据中管理。取消选中此选项将阻止部署修改目标服务器上的任何现有角色成员。
- **部署语言元数据（问答同义词、AI 指令和 AI 数据架构）**：部署模型中每个区域设置的语言元数据。在 Power BI 中，一种文化的语言元数据包含其问答同义词以及在 Power BI 服务中使用**为 AI 准备数据**设置的 AI 指令和 AI 数据架构。此选项默认选中。取消选中此选项，以便在您重新部署时保留目标语义模型上的语言元数据：
  - 两个模型中的一种文化都会获得模型的翻译，并保留目标的语言元数据
  - 仅存在于目标中的文化将保留其语言元数据，但不保留其翻译
  - 仅存在于模型中的文化在部署时没有语言元数据

Tabular Editor 不会更新保留的语言元数据，因此保留的 AI 数据架构可以列出已部署的模型不再包含的表或列。

## 数据源凭据

默认情况下，Tabular Editor 在将模型保存到磁盘时不会保存密码、账户密钥和其他密钥。因此，从文件加载的模型可能具有缺少密钥的数据源。部署向导会在部署之前检查这一点。当密钥为空或为`********`时，即视为缺失。向导将检查：

- 连接字符串包含密码关键字（例如 `Password` 或 `Pwd`）的提供程序数据源，
- 模拟特定 Windows 帐户的提供程序数据源，
- 使用 Windows 或用户名/密码身份验证或帐户密钥的 Structured数据源。

对于每个缺失的密钥，向导都会要求你提供服务器在刷新模型时应使用的凭据。Tabular Editor 将您输入的内容以加密形式存储为 @user-options 文件中的数据源覆盖，并在下次部署时使用，而不会再次询问。

当您清除**部署数据源**时，向导会对目标上已存在的数据源执行相同的检查。如果服务器未返回其中一个数据源所需的密钥，向导会在每次部署时都要求提供该密钥，因为这些答案不会被存储。

Power BI 和 Fabric 语义模型不会在模型中存储凭据。而是要在 Power BI 服务中的语义模型上设置它们。

## 部署脚本

在部署过程中，Tabular Editor 会生成一个[CreateOrReplace TMSL 脚本](https://learn.microsoft.com/analysis-services/tmsl/createorreplace-command-tmsl?view=asallproducts-allversions)，然后针对 Analysis Services 引擎执行该脚本。CreateOrReplace 脚本包含重新创建模型所需的所有元数据，包括表、列、度量值、关系、视角、翻译等。如果目标服务器上尚不存在该模型，则将创建该模型。如果模型已存在，现有对象将被脚本中指定的新元数据替换。

如果您在**部署选项**页面上清除了某个选项，则生成的 TMSL 脚本将保留目标对这些对象的现有定义。
部署向导的最后一页**部署摘要**列出了所选选项。点击**TMSL 脚本**，在部署前查看生成的脚本。**导出生成...** 会忽略 **部署共享表达式** 和 **部署语言元数据** 选项。

## 部署影响

> [!WARNING]
> 此类型的部署是**仅元数据部署**。根据对模型所做更改的类型，导入的数据可能会在部署过程中丢失。在这种情况下，部署完成后，您可能需要执行刷新操作。

通常情况下，可以对模型进行以下更改，而无需随后刷新数据：

- 添加/编辑/删除度量值和 KPI，包括其 DAX 表达式。
- 编辑属性，例如 FormatString、Description、DisplayFolder 等。
- 添加/编辑/移除元数据翻译、视角、OLS 和 RLS 角色。

在可以查询对象之前，以下更改可能需要执行**计算刷新**：

- 添加/编辑计算列、计算表格和计算组
- 添加/编辑关系
- 添加/编辑层次结构
- 删除列/表格

以下更改可能需要**完全刷新**：

- 添加/编辑分区、表和列

> [!WARNING]
> 由于以这种方式部署语义模型可能产生影响，我们建议不要使用此选项对生产环境执行部署。最好设置一个[用于将模型部署到生产环境的 CI/CD 管道](https://blog.tabulareditor.com/category/ci-cd/)。
