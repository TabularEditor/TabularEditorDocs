## Novedades en la versión 3.27.0.0

Para una visión general, consulta la [publicación del blog de lanzamiento](https://tabulareditor.com/blog/tabular-editor-3-september-2026-release).

### Servidor MCP

Tabular Editor 3 ahora puede actuar como un servidor MCP (Model Context Protocol). Herramientas de agentes como Claude Code, GitHub Copilot, el modo agente de VS Code, Codex y Cursor pueden conectarse a él y usar las mismas funciones que el Asistente de IA sobre el modelo que tengas abierto, sin necesidad de configurar en Tabular Editor un proveedor de IA ni una clave de API.

El agente trabaja en el modelo a través del mismo modelo de objetos, motor de scripting y comprobaciones de seguridad que el Asistente de IA, y sus cambios aparecen en tu sesión de Tabular Editor, donde puedes inspeccionarlos, deshacerlos y guardarlos. Elige **Herramientas > Servidor MCP...**, haz clic en **Iniciar servidor** y pega una sola vez la configuración generada en tu herramienta de agente para conectar un agente. Un indicador en la barra de estado muestra si el servidor está en ejecución.

Los permisos de IA **Metadatos del modelo**, **Datos del modelo**, **Best Practice Analyzer**, **Documentos** y **macros** controlan lo que puede hacer un agente conectado. Los configuras en el cuadro de diálogo del servidor antes de iniciarlo. Las herramientas que no cubran los permisos que hayas concedido no se ofrecen al agente, y no aparece ninguna solicitud de consentimiento mientras trabajas. El chat del Asistente de IA usa los mismos permisos, que puedes editar desde cualquiera de los dos lugares. Los cambios surten efecto la próxima vez que se inicie el servidor, y un agente que ya esté conectado debe volver a conectarse para verlos.

Con **Metadatos del modelo > Escritura**, un agente modifica tu modelo mediante **C# Scripts**, que Tabular Editor compila, somete a comprobaciones de seguridad y ejecuta de forma atómica. Cada script corresponde a un paso de deshacer y se llama **C# Script (MCP)**. Un script que accede a archivos, a la red o a ensamblados externos no se ejecuta por sí solo. Si se concede **Documentos > Escritura**, dicho script se abre como un documento de **C# Script** para su revisión y, sin ese permiso, no se ejecuta en absoluto.

Para más información, consulta el nuevo artículo @mcp-server. El modelo de permisos se describe en [Permisos y consentimiento](xref:ai-assistant#permissions-and-consent).

### El Asistente de IA ya está disponible de forma general

El **Asistente de IA** ya está disponible de forma general. El componente **Funciones de IA** del instalador ahora está seleccionado de forma predeterminada. Una instalación estándar incluye el Asistente y el servidor MCP. Todavía puedes desmarcar el componente en el instalador y, si tu administrador de TI ha deshabilitado las funciones de IA, seguirán sin estar disponibles. Los proveedores compatibles son OpenAI, Anthropic, Azure OpenAI y puntos de conexión compatibles con OpenAI, incluidos los modelos locales. Consulta @ai-assistant.

El Asistente ahora puede ejecutar los **C# Scripts** que escribe para realizar los cambios en el modelo que le pides. Antes, tenías que ejecutar sus scripts tú mismo. Activa esta opción seleccionando **Permitir que el asistente de IA ejecute C# Scripts directamente** en **Herramientas > Preferencias > Funciones de IA > Asistente de IA > Preferencias**, con **Metadatos del modelo** establecidos en **Lectura/escritura** en **Herramientas > Preferencias > Funciones de IA > Permisos**. Solo se ejecutan así los scripts que cambian el propio modelo, y los scripts que acceden a archivos, a la red o a ensamblados externos siguen abriéndose en un documento de script para su revisión. Cada ejecución cuenta como un único paso de deshacer, y si un script falla a mitad del proceso, el modelo queda sin cambios. **Vista previa de los cambios** sigue aplicándose: ves qué ha cambiado antes de confirmarlo y puedes hacer clic en **Cancelar** para revertirlo.

La lista desplegable **Nombre del modelo de IA** y el selector de modelos del panel ahora se rellenan a partir de una lista en línea, lo que permite seleccionar modelos nuevos sin actualizar Tabular Editor. La barra de uso de contexto, el punto en el que una conversación se compacta y la longitud máxima de una respuesta ahora usan los límites del modelo seleccionado. Antes usaban un único valor fijo. Para **Azure OpenAI**, el campo de modelo ahora se etiqueta como **Deployment**, siguiendo la terminología de Azure. Gracias a [edhans](https://github.com/edhans) por sugerir el selector de modelos en nuestro [foro de ideas de GitHub](https://github.com/TabularEditor/TabularEditor3/discussions/1580).

Ahora, el Asistente elige las **Instrucciones personalizadas** según la descripción de cada instrucción, y una instrucción que ya ha cargado permanece activa durante el resto de la conversación. Si mantienes tus propios archivos de instrucciones, asegúrate de que la propiedad `description` de cada archivo sea precisa y específica. La sección `triggers` se ignora y puede eliminarse. Escribir `/instruction-id` sigue cargando una instrucción de forma explícita.

Con licencias Enterprise, Tabular Editor 3 también mantiene un [registro de auditoría](xref:ai-audit-log) de lo que hicieron el Asistente y el servidor MCP. El registro almacena los permisos solicitados y las respuestas a esos permisos, las herramientas usadas y sus resultados, y el texto completo de cualquier script que un agente ejecutó o te entregó, pero no los prompts, las respuestas del asistente ni los valores de datos. Se escribe localmente, a menos que un administrador lo redirija. **Abrir carpeta de auditoría**, en **Herramientas > Preferencias > Funciones de IA** y en el cuadro de diálogo **Herramientas > Servidor MCP...**, abre su ubicación. Las directivas que un administrador puede establecer se describen en [Directivas empresariales para el Asistente de IA y el servidor MCP](#enterprise-policies-for-the-ai-assistant-and-mcp-server).

Para obtener más información, consulta @ai-assistant y [Permitir que el Asistente cambie tu modelo](xref:ai-assistant#letting-the-assistant-change-your-model).

### Indicadores de cambios no guardados

El **Explorador TOM** y la vista **Propiedades** ahora marcan los objetos con cambios no guardados, tanto si el cambio se hizo manualmente como mediante un script o un agente de IA. En el **Explorador TOM**, un objeto agregado aparece en verde con una insignia **+**, un objeto eliminado en rojo con una insignia **−** y un objeto editado en naranja con una insignia de punto; la vista **Propiedades** marca del mismo modo las filas modificadas. Ambas vistas tienen un conmutador **Mostrar cambios** en la barra de herramientas que muestra solo lo que ha cambiado. Los indicadores desaparecen al guardar o recargar el modelo, o al deshacer hasta volver a su estado guardado.

Haz clic con el botón derecho en un objeto marcado en el **Explorador TOM** y elige **Revert** para devolver el objeto y todo lo que hay debajo de él al estado que tenían en el último guardado. Para una sola propiedad, haz clic con el botón derecho en su fila en la vista **Propiedades** y elige **Revert**.

Los objetos eliminados ya no desaparecen del **Explorador TOM** de inmediato. Hasta que guardes el modelo, permanecen en su sitio, tachados, y puedes hacer clic con el botón derecho en uno y elegir **Restaurar** para recuperarlo en el estado que tenía antes de que se eliminara. En la sección **Cambios no guardados**, en **Herramientas > Preferencias > Tabular Editor > Explorador TOM**, puedes desactivar los marcadores, agrupar los objetos eliminados de un contenedor bajo un único nodo **Objetos eliminados** y establecer cuánto tiempo permanecen visibles los objetos eliminados. Los C# Scripts pueden usar los nuevos miembros `Revert()`, `HasUnsavedChanges`, `DeletedObjects` y `Selected.Deleted`, junto con el correspondiente `Restore()`. Para más información, consulta el nuevo artículo @unsaved-changes.

### Recarga automática desde el disco

Cuando los archivos de metadatos del modelo cargado cambian fuera de la aplicación, por ejemplo mediante un agente de IA, un script u otro editor, Tabular Editor ahora vuelve a cargar el modelo abierto. No hace falta usar **Archivo > Recargar desde disco** para estos cambios. En el caso de un modelo cargado desde un archivo `.bim`, los cambios en ese archivo desencadenan una recarga, y en el caso de un modelo cargado desde una carpeta, los cambios en cualquier archivo `.json` o `.tmdl` situado debajo de la raíz del modelo desencadenan una recarga.

Si no tienes cambios sin guardar, el modelo se recarga sin mostrar ningún aviso. Si hay cambios sin guardar, aparece el aviso **Se detectaron cambios externos**. **Recargar** descarta los cambios locales y **Ignorar** los conserva.

La recarga automática está habilitada de forma predeterminada. Para desactivarlo, desmarca la nueva casilla **Recargar automáticamente desde disco (hot reload)** en **Herramientas > Preferencias > Tabular Editor > Varios**. Para más información, consulta el nuevo artículo @auto-reload.

### Autenticación con par de claves de Snowflake

Las conexiones de Snowflake ahora admiten autenticación con **par de claves**, el método de inicio de sesión para los usuarios de servicio de Snowflake, que no pueden iniciar sesión con una contraseña. En el cuadro de diálogo de conexión de Snowflake, elige **Par de claves** como autenticador, introduce tu nombre de usuario y selecciona el archivo de tu clave privada RSA. Si la clave está cifrada, introduce la frase de contraseña. Se admiten claves PKCS#1 y PKCS#8 sin cifrar, así como claves PKCS#8 cifradas con una frase de contraseña; este es el formato que generan los pasos de generación de claves documentados por Snowflake. Para obtener más información, consulta [Autenticación con par de claves](xref:connect-snowflake#key-pair-authentication).

### Directivas empresariales para el Asistente de IA y el servidor MCP

Los administradores ahora pueden establecer una directiva para cada uno de los cinco permisos de IA, para controlar a qué pueden acceder y qué pueden hacer el Asistente de IA y el servidor MCP en el equipo de un usuario. Cuando se aplica un límite, las opciones de **Herramientas > Preferencias > Funciones de IA > Permisos** y del cuadro de diálogo **Herramientas > Servidor MCP...** incluyen solo los niveles permitidos, y el Asistente de IA ya no solicita permisos que la directiva bloquea. Si se bloquea **Metadatos del modelo**, no se comparte ninguna información sobre el modelo abierto.

Los administradores también pueden fijar del mismo modo el proveedor de IA, el punto de conexión, el nombre del modelo o de la implementación, así como la organización y el proyecto de OpenAI; además, pueden restringir estos ajustes a una lista de proveedores y hosts de puntos de conexión permitidos. Otras directivas publican una carpeta de Instrucciones personalizadas para toda la organización, bloquean las Instrucciones personalizadas que los usuarios guardan para sí mismos, eligen qué herramientas ofrece el servidor MCP a los agentes conectados y fijan el puerto del servidor.

Estas directivas requieren la Edición Enterprise de Tabular Editor 3 y se aplican a las licencias Enterprise, Consultancy y Trial. Sin una licencia Enterprise, el Asistente de IA y el servidor MCP no se inician mientras estas directivas estén configuradas, y un mensaje indica qué valores de directiva requieren la Edición Enterprise. Para obtener más información, consulta [Políticas Enterprise](xref:policies#enterprise-policies).

### Política de administrador para scripts inseguros

Los administradores también pueden restringir ahora los C# Scripts y las macros a operaciones sobre el propio modelo semántico. Con esta restricción activa, un script se bloquea antes de ejecutarse si lee o escribe archivos, accede a la red, inicia otro programa, carga código externo o envía comandos directamente al servidor. La directiva se aplica a todos los lugares donde se ejecutan scripts:

- El editor de scripts
- La opción **Aplicar corrección** del Best Practice Analyzer
- El **Asistente de IA**
- El **Servidor MCP**
- La herramienta de línea de comandos `te` (en Windows)

Una macro que haga cualquiera de estas cosas ya no aparece en ningún menú y queda marcada en **Ver > Macros**, donde aún puedes abrirla y editarla.

Esta restricción requiere la Edición Enterprise de Tabular Editor 3 y se respeta en las licencias Enterprise, Consultancy y Trial. Sin una licencia Enterprise, se bloquea toda la ejecución de scripts y macros mientras la directiva esté activa. Para obtener más información, consulta [Scripts y macros](xref:policies#scripts-and-macros) en la referencia de políticas.

### Serialización por archivo para las UDF de DAX

Al guardar un modelo en el formato de carpeta JSON, las funciones DAX definidas por el usuario (UDF) ahora pueden serializarse como archivos individuales, y cada UDF se escribe en su propio archivo `.json` en una subcarpeta `functions/` en la raíz del modelo. Las ediciones en paralelo de diferentes UDF ya no provocan conflictos de fusión en Git en el `Database.json` compartido. El nuevo interruptor **Funciones definidas por el usuario (UDFs)** se encuentra en **Herramientas > Preferencias > Formatos de archivo > Guardar en carpeta** y en **Modelo > opciones de serialización...**, y está habilitado de forma predeterminada para los nuevos guardados en carpeta. Los modelos existentes serializados en carpeta mantienen su disposición en línea hasta que actives la opción y guardes. Para obtener más información, consulta [Funciones definidas por el usuario (UDFs)](xref:save-to-folder#user-defined-functions-udfs).

### Semantic Analyzer señala las limitaciones de las columnas calculadas con contexto de usuario

El Semantic Analyzer ahora informa de un error cuando se hace referencia a una _columna calculada de contexto de usuario_ donde Power BI no permite usarla. Una columna calculada de contexto de usuario es una columna calculada cuya propiedad `ExpressionContext` está establecida en **Contexto de usuario** (**Contexto de expresión** en la vista **Propiedades**). Las referencias directas se notifican en el editor de DAX, en la vista **mensajes** y en el comando de la CLI `te validate`; las referencias indirectas y las infracciones en los puntos finales de las relaciones se notifican en la vista **mensajes**. Para obtener más información, consulta @user-context-calculated-columns.

### Mostrar la consulta DAX real en la Vista previa de tabla

La cuadrícula de **Vista previa de tabla** tiene una nueva opción, **Mostrar la consulta DAX real**, en su menú contextual, que abre un nuevo documento de consulta DAX editable con una consulta que refleja el filtro y la ordenación actuales de la vista previa. Para obtener más información, consulta [Mostrar la Consulta DAX real](xref:table-preview#show-actual-dax-query).

### Cambio incompatible: los C# Scripts usan las funciones auxiliares de consulta del script en lugar de Model.Database

Los C# Scripts ya no pueden llamar directamente a los miembros de consulta y comando `ExecuteCommand`, `ExecuteReader`, `ExecuteDax` y `EvaluateDax` en `Model.Database`. Para ejecutar consultas y comandos, usa las funciones auxiliares de script integradas `EvaluateDax(...)`, `ExecuteDax(...)`, `ExecuteReader(...)` y `ExecuteCommand(...)`, que se mantienen sin cambios. Otros miembros de `Model.Database`, como `Name`, `ID` y `CompatibilityLevel`, también se mantienen sin cambios. Para más detalles, consulta @script-helper-methods.

## Mejoras en la versión 3.27.0.0

- Las directivas ahora pueden configurarse en `Software\\Policies\\Tabular Editor ApS`, con las subclaves específicas del producto `TE3` y `TECLI` para una directiva que se aplique solo a un producto. Ahora las directivas también se leen desde el ámbito de todo el equipo, por lo que se aplican las directivas de grupo de Configuración del equipo y los usuarios no pueden sobrescribirlas. La clave anterior `Software\\Policies\\Kapacity\\Tabular Editor` sigue funcionando, y la herramienta de línea de comandos `te` respeta estas directivas en Windows. Tabular Editor 3 también instala un par de plantillas administrativas de Directiva de Grupo, para que puedas configurar cualquier directiva desde el editor de Directiva de Grupo sin editar el Registro. Consulta @policies y [Uso de las plantillas administrativas](xref:policies#using-the-administrative-templates).
- Un nuevo **Modo de daltonismo**, en el grupo **Accesibilidad** de **Herramientas > Preferencias > Tabular Editor > Interfaz de usuario**, marca en color verde azulado los objetos agregados desde el último guardado, que de otro modo aparecerían en verde. Con este modo, los objetos agregados, eliminados y modificados siguen siendo distinguibles en las formas más comunes de daltonismo. El modo se aplica a los indicadores de cambios del **Explorador TOM** y a los colores de la vista de comparación de modelos. Consulta @accessibility.
- Se ha añadido el nivel de compatibilidad 1706 de Power BI / Fabric al cuadro de diálogo **Nuevo modelo**, donde sustituye a 1702 como nivel más reciente. Ahora 1706 se trata como el nivel de compatibilidad más reciente en toda la aplicación, incluida la regla del Best Practice Analyzer "Power BI models should use latest compatibility level" y los nuevos modelos de Power BI creados con `te init`.
- El filtro de valores de la **Vista previa de tabla** muestra hasta 5.000 valores distintos. Para tablas grandes, aumenta el límite con **Máx. valores en el menú desplegable del filtro** en **Herramientas > Preferencias > Exploración de datos > Vista previa de tabla**. Un límite más alto puede aumentar los tiempos de carga.
- Se ha añadido la preferencia **Ordenar alfabéticamente las columnas de la vista previa de tabla**, desactivada de forma predeterminada, en **Herramientas > Preferencias > Exploración de datos > Vista previa de tabla**. Cuando está seleccionada, las columnas de la **Vista previa de tabla** se ordenan por nombre, en el mismo orden que en el **Explorador TOM**; cuando está desmarcada, las columnas aparecen en el orden en que las devuelve el motor. Consulta [Orden de columnas](xref:table-preview#column-order).
- De forma predeterminada, al seleccionar una columna en el **Explorador TOM**, la **Vista previa de tabla** se desplaza hasta esa columna y la resalta. El botón de la barra de herramientas **Seguir columna seleccionada** desactiva el seguimiento para una vista previa, y **Herramientas > Preferencias > Exploración de datos > Vista previa de tabla > Comportamiento** lo desactiva globalmente. Consulta [Buscar una columna en una tabla ancha](xref:table-preview#finding-a-column-in-a-wide-table).
- Al seleccionar **Seguir Explorador TOM** en la **vista de dependencias de DAX**, ahora se muestran de inmediato las dependencias del objeto seleccionado actualmente. Antes, la vista esperaba al siguiente cambio de selección.
- El **Explorador TOM** ya no parpadea ni salta después de editar una expresión DAX. Antes, el árbol podía volver a dibujarse brevemente y perder su posición de desplazamiento.
- Los diagramas del modelo ahora siguen la navegación programática del **Explorador TOM**. Cuando saltas a una tabla o columna mediante acciones de **Ir a** o resultados de búsqueda, todos los diagramas abiertos resaltan ese objeto, igual que cuando haces clic en él en el árbol.
- **Archivo > Revertir** ahora es **Archivo > Recargar desde disco** o **Archivo > Recargar desde el servidor**, según el origen del modelo abierto. La solicitud de confirmación, los mensajes de la barra de estado durante y después de la recarga, y el mensaje de error en caso de fallo usan la misma redacción.
- El editor DAX ahora reconoce el parámetro opcional `AssociatedColumnsBehavior` de la función [LOOKUP](https://dax.guide/lookup/). Antes, el parámetro aparecía subrayado como una referencia no resuelta. Ahora aparece en la información emergente como un argumento final opcional, y el autocompletado sugiere sus dos valores, `EXPLICIT` e `INFERRED`, con las mayúsculas/minúsculas definidas por tu preferencia **Uso preferido de mayúsculas y minúsculas en palabras clave**.
- Las acciones del menú y la barra de herramientas ya no hacen que los lectores de pantalla y otras herramientas de accesibilidad o automatización se queden bloqueados mientras hay un cuadro de diálogo abierto.
- Ahora puedes cambiar directamente el nombre de los objetos de Metric View. Antes, tenías que crear un objeto nuevo y eliminar el anterior. La importación de YAML de Metric View con nombres de objeto duplicados ahora falla con el error `Duplicate <kind> name '<name>'`, y los problemas en las expresiones de unión, campo y medida se notifican por separado, indicando en cada caso el tipo de objeto implicado.
- La página **Novedades** ha sido reemplazada por una nueva página **Primeros pasos**, disponible en el menú **Ayuda** y que aparece en el primer inicio y después de una actualización.
- Tabular Editor 3 ahora también está disponible como compilación de .NET 10, junto con la compilación existente de .NET 8, tanto para x64 como para ARM64. La descarga de .NET 10 es la recomendada y requiere el [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0), que el instalador te ofrece descargar e instalar. Los instaladores de .NET 8, los paquetes MSI y los archivos portátiles siguen publicándose para los equipos que todavía no pueden pasar al entorno de ejecución más reciente. Ambas compilaciones son funcionalmente idénticas y se pueden instalar en paralelo. La CLI de Tabular Editor ahora se distribuye solo en .NET 10, como una compilación autónoma que no requiere un entorno de ejecución aparte. Consulta @system-requirements.
- Se actualizaron los componentes de terceros en los que se basa Tabular Editor a sus versiones compatibles más recientes, incluidos [Microsoft.AnalysisServices](https://www.nuget.org/packages/Microsoft.AnalysisServices/) (Tabular Object Model/AMO) 19.117.0, [DevExpress WinForms](https://www.nuget.org/packages/DevExpress.Win.Design/) 25.2.9, [Roslyn](https://www.nuget.org/packages/Microsoft.CodeAnalysis.CSharp/) 5.9.0 para C# Script, [WebView2](https://www.nuget.org/packages/Microsoft.Web.WebView2/) 1.0.4129.50, [Microsoft.Extensions.AI](https://www.nuget.org/packages/Microsoft.Extensions.AI/) 10.9.0 y [Anthropic](https://www.nuget.org/packages/Anthropic/) 12.40.0 para el Asistente de IA, [Microsoft.Fabric.Api](https://www.nuget.org/packages/Microsoft.Fabric.Api/) 2.20.0, [Microsoft.PowerBI.Api](https://www.nuget.org/packages/Microsoft.PowerBI.Api/) 5.1.0, [Microsoft.Identity.Client](https://www.nuget.org/packages/Microsoft.Identity.Client.Desktop/) 4.87.0, [Microsoft.Data.SqlClient](https://www.nuget.org/packages/Microsoft.Data.SqlClient/) 6.1.5 y [Spectre.Console](https://www.nuget.org/packages/Spectre.Console/) 0.57.2 para la interfaz de línea de comandos. El componente de edición de código que usan los editores de DAX y M ([Scintilla](https://www.nuget.org/packages/Scintilla5.NET/)) se actualizó a la versión 7.0.0, que incluye componentes nativos firmados digitalmente tanto para ARM64 como para x64. Los componentes firmados son especialmente relevantes en dispositivos Windows on Arm y en entornos que aplican directivas de integridad del código. Con la actualización de Analysis Services, ahora se muestra la propiedad **String Indexing Behavior** de una columna en los modelos con nivel de compatibilidad 1706 o superior.

## Correcciones de errores en 3.27.0.0

- Se corrigió un problema por el que guardar un modelo en formato Tabular Model Definition Language (TMDL) podía destruir una tabla, un rol, una perspectiva o una configuración regional cuyo nombre de archivo difería del nombre del objeto solo por el uso de mayúsculas y minúsculas; una situación que puede producirse tras renombrar un objeto; por ejemplo, una tabla llamada `Sales` almacenada en `tables/sales.tmdl`. Antes, el guardado mostraba un Report de éxito, pero el archivo del objeto se eliminaba junto con su contenido, y el objeto ya no estaba la siguiente vez que se abría el modelo. Ahora ese modelo se guarda correctamente: se conserva el objeto, su archivo se guarda con el nombre del objeto y se aplica la edición que desencadenó el guardado.
- Se corrigió un problema por el que las columnas podían crearse en un orden arbitrario al importar o actualizar una tabla desde un origen de SQL Server, Fabric Lakehouse o Fabric Warehouse mediante **Modelo > Importar tablas...**, **Modelo > Actualizar esquema de tabla...** o la CLI. Las columnas ahora siguen el orden de las columnas de la tabla de origen.
- Se corrigió un problema por el que importar una tabla desde un Fabric Lakehouse o Warehouse mediante un Data source que ya incluía su punto de conexión de análisis SQL podía crear una tabla sin columnas y sin mostrar ningún error. Ahora las columnas se leen a través de ese punto de conexión y, si no se puede determinar ninguno, se muestra un error que indica que no se puede determinar el punto de conexión de análisis SQL para el origen OneLake.
- Se corrigió un problema por el que importar una tabla cuyo nombre de servidor, base de datos, esquema u objeto contiene una comilla doble generaba una expresión de Power Query que no se podía analizar. Ahora esos nombres se gestionan correctamente con caracteres de escape y, al importar desde Databricks o Snowflake, la propia consulta también se escapa correctamente.
- Se corrigió un problema por el que una conexión de Snowflake que usaba la autenticación **Navegador externo** no podía recuperarse después de que su inicio de sesión en caché expirara o fuera revocado por el proveedor de identidad. Anteriormente, todas las operaciones posteriores de Snowflake fallaban sin volver a abrir el navegador: el Asistente para importar tablas mostraba tablas y columnas vacías sin ningún error, y había que reiniciar Tabular Editor para recuperarse. Ahora el inicio de sesión en el navegador se vuelve a abrir cuando Snowflake rechaza el inicio de sesión en caché, y un inicio de sesión que agota el tiempo de espera o se abandona ahora cuenta como una cancelación que ya no bloquea operaciones posteriores. Consulta [Inicios de sesión con navegador externo](xref:connect-snowflake#external-browser-sign-ins).
- Se corrigió un problema por el que guardar un modelo en una carpeta o en un archivo `.bim` en macOS o Linux producía archivos distintos a los de Windows, incluidos nombres de objeto que no se podían extraer en Windows, finales de línea dependientes de la plataforma y un orden de tablas variable. Ahora los modelos guardados en cualquier plataforma generan una salida idéntica. Esto también corrige un problema antiguo por el que dos objetos cuyos nombres se traducían al mismo nombre de archivo escapado sobrescribían el archivo entre sí.
- Se corrigió un problema por el que mover una medida o una columna calculada a otra tabla, o duplicarla, eliminaba su indicador de error aunque la expresión seguía siendo inválida. Antes, el indicador solo reaparecía después de volver a editar la expresión.
- Se corrigió un problema por el que el **Explorador TOM** se plegaba y perdía la selección actual cuando se recargaba un modelo con una base de datos de Workspace conectada, ya fuera con **Archivo > Recargar desde disco** o mediante una recarga automática después de que los archivos cambiaran en disco. Ahora se conservan los nodos expandidos, el objeto con el foco, la selección y la posición de desplazamiento, y al recargar un modelo abierto desde un archivo también se conserva la selección.
- Se corrigió un problema por el que pegar un objeto en el **Explorador TOM** podía dejar seleccionados tanto el original como la copia pegada, y el árbol se desplazaba lejos del objeto pegado. Ahora el objeto pegado queda seleccionado, recibe el foco y se mantiene a la vista.
- Se corrigió un problema por el que seleccionar un objeto en el **Explorador TOM** mientras se trabajaba en otra vista podía cambiar el documento activo a un diagrama de modelo abierto.
- Se corrigió un problema por el que seleccionar en el **Explorador TOM** una partición de Direct Lake, o una partición generada por una política de actualización incremental, provocaba un error y abría el cuadro de diálogo del Report de fallo. El **Editor de expresiones** ahora muestra la expresión de definición de cobertura de datos de la partición si la tiene, y permanece vacío si no la tiene.
- Se corrigió un problema por el que abrir un modelo que contenía tablas calculadas cuyas columnas se infieren a partir de la expresión DAX podía fallar de forma intermitente con el error "Collection was modified; enumeration operation may not execute".
- Abrir un modelo ya no produce un error cuando el archivo de opciones de usuario del modelo (`.tmuo`) no contiene contenido legible. El archivo ahora también se escribe de forma atómica, por lo que una escritura interrumpida no puede dañarlo.
- Se corrigió un problema por el que, al guardar un modelo semántico PBIP creado con Power BI Desktop, se renombraba el elemento y se borraba cualquier descripción establecida en Fabric; luego, el cambio se propagaba al Workspace en la siguiente sincronización de Git de Fabric. Ahora, al guardar ese tipo de modelo en una nueva ubicación, la carpeta también toma el nombre del elemento.
- Se corrigió un problema por el que **Archivo > Guardar como...** podía sugerir un nombre de archivo que Windows no puede guardar, sobre todo cuando el título de la pestaña del documento contiene dos puntos. Los caracteres no válidos del nombre sugerido ahora se codifican con codificación porcentual, y aun así puedes editarlo.
- Se corrigió un problema por el que el texto de la barra de estado podía no ser legible cuando se elegía un **Color de la barra de estado** personalizado para una conexión. Los colores del texto y de los vínculos de la barra de estado ahora se derivan del color elegido. Antes, se derivaban del tema activo.
- Se corrigió un problema por el que la colección «Reglas para el usuario local» de Best Practice Analyzer podía aparecer como de solo lectura en un equipo en el que Tabular Editor aún no había creado su carpeta local de datos de la aplicación, por ejemplo, al ejecutarse por primera vez.
- Se corrigió un problema por el que el autocompletado de DAX sugería funciones definidas por el usuario, UDF, que no eran válidas en el contexto actual del argumento y omitía otras que sí lo eran. Ahora las UDF se filtran por el tipo de retorno inferido, y ya no se sugieren las que tengan un error semántico en su definición. Los argumentos de filtro, que antes omitían por completo las UDF, ahora sí las sugieren.
- Se corrigió un problema por el que **Insertar medida en línea** en el editor de DAX podía cambiar el resultado de un cálculo sin avisar cuando la referencia estaba dentro de un contexto de fila, por ejemplo dentro de `SUMX` o `FILTER`. Cuando puede afectar al resultado, la expresión insertada en línea ahora se envuelve en `CALCULATE( ... )` para preservar la transición de contexto que realiza una referencia de medida.
- Se corrigió un problema por el que **Medida en línea** podía convertir en comentario parte de la expresión circundante cuando la expresión de la medida expandida terminaba con una línea de comentario. Ahora, cualquier código que siga a la referencia de medida en esa línea se mueve a una línea nueva, con la sangría correspondiente.
- Se corrigió un problema por el que el **Asistente de IA** en la edición portátil (zip) a veces no estaba disponible tras iniciarse, aunque ya hubiera un proveedor de IA configurado. Antes, al enviar un mensaje se mostraba "AI client not initialized" y, al confirmar la configuración sin cambios, se producía el error "Method not found" hasta reiniciar la aplicación. El Asistente ahora se inicializa cada vez que se inicia la aplicación y, si falla la inicialización, el chat indica el motivo.
- Se corrigió un problema por el que el **Asistente de IA** no podía inicializarse cuando el proveedor se establecía en `Anthropic` u `OpenAI` y el nombre del modelo se dejaba en blanco. Ahora se permite dejar el nombre del modelo en blanco y los errores de inicialización, que antes no ofrecían ninguna información, ahora se notifican en el chat.
- Se corrigió un problema por el que el **Asistente de IA** podía fallar con el error "The requested operation requires an element of type 'Number', but the target element has type 'String'" cuando se le pedía revisar un script o una consulta que había escrito antes en la conversación. La respuesta ahora se completa y el script o la consulta existentes se actualizan en el mismo lugar.
- Se corrigió un problema por el que el botón **Detener** del **Asistente de IA** no hacía nada mientras una tarjeta de **Permiso requerido** esperaba una respuesta, dejando la conversación bloqueada. Al pulsar **Detener**, ahora finaliza el turno y puedes continuar la misma conversación con un mensaje nuevo.
- Se corrigió un problema por el que los bloques de código en el **Asistente de IA** resultaban ilegibles con un tema claro, ya que aparecían como texto casi negro sobre un bloque casi negro. Los bloques de código, su etiqueta de idioma, el botón **Copiar** y el resaltado de sintaxis ahora siguen el tema, y la franja de encabezado del bloque también se ha simplificado.
- Se corrigió un problema por el que el botón **Eliminar conversación** de la barra de herramientas del **Asistente de IA** eliminaba la conversación actual de inmediato, sin posibilidad de recuperarla. Ahora aparece un aviso de confirmación y el botón se ha alejado del botón de cerrar del panel, con el que era fácil confundirlo.
- Se corrigió un problema por el que el texto inmediatamente posterior a una tarjeta de script o consulta en una respuesta del **Asistente de IA** podía aparecer sin formato y mostrar caracteres sin procesar como `**` o comillas invertidas.
- Se corrigió un problema por el que el **Asistente de IA** podía crear un objeto duplicado cuando se le pedía actualizar uno existente que había cambiado de nombre, se había movido o editado después de que el Asistente lo creara por primera vez.
- Se corrigió un problema por el que el **Asistente de IA** mostraba un error y no respondía cuando estaba conectado a un proveedor personalizado (compatible con OpenAI) que usaba determinados modelos de pensamiento o de razonamiento. Las solicitudes que usan herramientas, como enumerar medidas o ejecutar una consulta DAX, ahora funcionan con estos modelos.

## ¿Vienes de Tabular Editor 2.x?

Para conocer las principales características de Tabular Editor 3, mira [este vídeo](https://youtu.be/O4ATwdzCvWc). Para empezar, consulta la [guía de inicio](https://docs.tabulareditor.com/onboarding/index.html).

**Características principales de Tabular Editor 3:**

- IDE personalizable con compatibilidad con varios monitores, Hi-DPI y temas
- Editor de código DAX con autocompletado, comprobación de sintaxis, plegado de código y formato
- \*Modo del área de trabajo, que guarda tus cambios en el disco y sincroniza los metadatos del modelo con Analysis Services al mismo tiempo
- \*Obtén una vista previa de los datos de las tablas con desplazamiento infinito, crea PivotGrids o escribe consultas DAX para explorar el modelo o probar la lógica de cálculo
- \*Programa actualizaciones de datos
- Actualizar el esquema de las tablas tanto en los Data source del proveedor como en los orígenes de datos estructurados, incluidas las consultas M
- Crear diagramas de Data model
- Crear scripts DAX que te permiten editar varias medidas u otros objetos calculados en un único documento
- Graba C# Scripts y guárdalos como macros (antes llamadas "Custom Actions")
- Integración del Analizador VertiPaq
- Depurador de DAX
- Integración del Optimizador de DAX
- Acciones de código para refactorizar tu DAX

\*=Solo cuando estés conectado a una instancia de Analysis Services o Power BI
