## Novedades en la versión 3.27.0.0

For an overview, see the [release blog](https://tabulareditor.com/blog/tabular-editor-3-september-2026-release).

### Servidor MCP

Tabular Editor 3 can now act as an MCP (Model Context Protocol) server. Agent harnesses such as Claude Code, GitHub Copilot, VS Code agent mode, Codex and Cursor connect to it and use the same features as the AI Assistant on the model you have open, without an AI provider or API key configured in Tabular Editor.

The agent works on the model through the same object model, scripting engine and safety checks as the AI Assistant, and its changes appear in your Tabular Editor session, where you can inspect, undo and save them. Choose **Tools > MCP Server...**, click **Start server** and paste the generated configuration into your agent tool once to connect an agent. A status bar indicator shows whether the server is running.

The AI permissions **Model metadata**, **Model data**, **Best Practice Analyzer**, **Documents** and **Macros** control what a connected agent can do. You set them in the server dialog before you start the server. Tools that your grants don't cover aren't offered to the agent, and no consent prompts appear while you work. The AI Assistant chat uses the same permissions, which you can edit from either place. Changes take effect the next time the server starts, and an agent that's already connected must reconnect to see them.

With **Model metadata > Write**, an agent changes your model through C# scripts, which Tabular Editor compiles, safety-checks and runs atomically. Each script is one undo step, named **C# script (MCP)**. A script that accesses files, the network or external assemblies doesn't run on its own. If **Documents > Write** is granted, such a script opens as a C# script document for review, and without that grant, it doesn't run at all.

For details, see the new @mcp-server article. The permission model is described in [Permissions and consent](xref:ai-assistant#permissions-and-consent).

### AI Assistant is generally available

El **Asistente de IA** ya está disponible de forma general. The **AI features** installer component is now selected by default. A standard installation includes the Assistant and the MCP server. You can still clear the component in the installer, and if your IT administrator has disabled AI features, they stay unavailable. Supported providers are OpenAI, Anthropic, Azure OpenAI and OpenAI-compatible endpoints, including local models. See @ai-assistant.

The Assistant can now run the C# scripts it writes to make the model changes you ask for. Previously, you had to run its scripts yourself. Turn this on by selecting **Allow AI assistant to run C# scripts directly** under **Tools > Preferences > AI Features > AI Assistant > Preferences**, with **Model metadata** set to **Read/Write** under **Tools > Preferences > AI Features > Permissions**. Only scripts that change the model itself run this way, and scripts that access files, the network or external assemblies still open in a script document to review. Each run is a single undo step, and a script that fails part-way leaves the model unchanged. **Preview changes** still applies: you see what changed before it's kept, and you can click **Cancel** to revert.

The **AI model name** dropdown and the model picker in the panel are now filled from an online list, which makes new models selectable without a Tabular Editor update. The context usage bar, the point at which a conversation is compacted and the maximum length of a reply now use the limits of the selected model. Previously, they used one fixed value. For **Azure OpenAI**, the model field is now labeled **Deployment**, matching Azure's term. Gracias a [edhans](https://github.com/edhans) por sugerir el selector de modelos en nuestro [foro de ideas de GitHub](https://github.com/TabularEditor/TabularEditor3/discussions/1580).

The Assistant now chooses Custom Instructions by each instruction's description, and an instruction it has loaded stays in effect for the rest of the conversation. If you maintain your own instruction files, keep each file's `description` accurate and specific. The `triggers` section is ignored and can be removed. Escribir `/instruction-id` sigue cargando una instrucción de forma explícita.

On Enterprise licenses, Tabular Editor 3 also keeps an [audit log](xref:ai-audit-log) of what the Assistant and the MCP server did. The log records permissions requested and answered, tools used and their outcome, and the full text of any script an agent ran or handed to you, but not prompts, replies or data values. It's written locally unless an administrator redirects it. **Open audit folder**, under **Tools > Preferences > AI Features** and in the **Tools > MCP Server...** dialog, opens its location. The policies an administrator can set are described in [Enterprise policies for the AI Assistant and MCP server](#enterprise-policies-for-the-ai-assistant-and-mcp-server).

Para obtener más información, consulta @ai-assistant y [Permitir que el Asistente cambie tu modelo](xref:ai-assistant#letting-the-assistant-change-your-model).

### Indicadores de cambios no guardados

The **TOM Explorer** and the **Properties** view now mark objects with unsaved changes, whether the change was made by hand, by a script or by an AI agent. In the **TOM Explorer**, an added object is tinted green with a **+** badge, a deleted object red with a **−** badge and an edited object orange with a dot badge, and the **Properties** view marks changed rows the same way. Both views have a **Show changes** toolbar toggle that shows only what changed. The indicators clear when you save or reload the model, or undo back to its saved state.

Right-click a marked object in the **TOM Explorer** and choose **Revert** to return the object and everything beneath it to their state at the last save. For a single property, right-click its row in the **Properties** view and choose **Revert**.

Deleted objects no longer disappear from the **TOM Explorer** right away. Until you save the model, they stay in place, struck through, and you can right-click one and choose **Restore** to bring it back in the state it had before it was deleted. In the **Unsaved changes** section under **Tools > Preferences > Tabular Editor > TOM Explorer**, you can turn off the markers, group a container's deleted objects under a single **Deleted objects** node and set how long deleted objects stay visible. C# scripts can use the new members `Revert()`, `HasUnsavedChanges`, `DeletedObjects` and `Selected.Deleted`, with a matching `Restore()`. Para más información, consulta el nuevo artículo @unsaved-changes.

### Recarga automática desde el disco

When the model metadata files it loaded change outside the application, for example through an AI agent, a script or another editor, Tabular Editor now reloads the open model. You don't need to use **File > Reload from disk** for these changes. For a model loaded from a `.bim` file, changes to that file trigger a reload, and for a model loaded from a folder, changes to any `.json` or `.tmdl` file below the model root trigger a reload.

If you have no unsaved changes, the model reloads without a prompt. If you have unsaved changes, an **External changes detected** prompt appears. **Reload** discards your local changes, and **Ignore** keeps them.

La recarga automática está habilitada de forma predeterminada. To turn it off, clear the new **Automatically reload from disk (hot reload)** checkbox under **Tools > Preferences > Tabular Editor > Miscellaneous**. Para más información, consulta el nuevo artículo @auto-reload.

### Autenticación con par de claves de Snowflake

Snowflake connections now support **key pair** authentication, the sign-in method for Snowflake service users, which can't sign in with a password. In the Snowflake connection dialog, choose **Key pair** as the authenticator, enter your username and browse to your RSA private key file. If the key is encrypted, enter its passphrase. Supported keys are unencrypted PKCS#1 and PKCS#8 keys and passphrase-encrypted PKCS#8 keys, which is the format Snowflake's documented key-generation steps produce. For details, see [Key pair authentication](xref:connect-snowflake#key-pair-authentication).

### Directivas empresariales para el Asistente de IA y el servidor MCP

Administrators can now set a policy for each of the five AI permissions to control what the AI Assistant and the MCP server can access and do on a user's machine. Where a limit applies, the options under **Tools > Preferences > AI Features > Permissions** and in the **Tools > MCP Server...** dialog include only the permitted levels, and the AI Assistant no longer requests permissions the policy blocks. If **Model metadata** is blocked, no information about the open model is shared.

Administrators can lock the AI provider, the endpoint, the model or deployment name and the OpenAI organization and project the same way, and they can restrict these settings to an allowlist of providers and endpoint hosts. Other policies publish a folder of Custom Instructions for the whole organization, block the Custom Instructions that users keep for themselves, choose which tools the MCP server offers to connected agents and fix the server's port.

These policies require Tabular Editor 3 Enterprise Edition and are honored on Enterprise, Consultancy and Trial licenses. Without an Enterprise license, the AI Assistant and the MCP server don't start while these policies are set, and a message names the policy values that require Enterprise Edition. Para obtener más información, consulta [Políticas Enterprise](xref:policies#enterprise-policies).

### Política de administrador para scripts inseguros

Administrators can also now restrict C# scripts and macros to operations on the semantic model itself. With the restriction in place, a script is blocked before it runs if it reads or writes files, accesses the network, starts another program, loads external code or sends commands directly to the server. The policy applies to every place that runs scripts:

- The script editor
- The Best Practice Analyzer's **Apply fix**
- The **AI Assistant**
- The **MCP server**
- The `te` command line (on Windows)

A macro that does any of these things no longer appears in any menu and is marked in **View > Macros**, where you can still open and edit it.

This restriction requires Tabular Editor 3 Enterprise Edition and is honored on Enterprise, Consultancy and Trial licenses. Without an Enterprise license, all script and macro execution is blocked while the policy is set. Para obtener más información, consulta [Scripts y macros](xref:policies#scripts-and-macros) en la referencia de políticas.

### Serialización por archivo para las UDF de DAX

When you save a model in the JSON folder format, DAX User-Defined Functions (UDFs) can now be serialized as individual files, with each UDF written to its own `.json` file in a `functions/` subfolder at the model root. Parallel edits to different UDFs then no longer cause Git merge conflicts in the shared `database.json`. The new **User Defined Functions (UDFs)** toggle is in **Tools > Preferences > File Formats > Save-to-folder** and in **Model > Serialization options...**, and it's enabled by default for new folder saves. Existing folder-serialized models keep their inline layout until you turn on the toggle and save. Para obtener más información, consulta [Funciones definidas por el usuario (UDFs)](xref:save-to-folder#user-defined-functions-udfs).

### Semantic Analyzer flags user-context calculated column limitations

The Semantic Analyzer now reports an error when a _user-context calculated column_ is referenced where Power BI doesn't allow it. A user-context calculated column is a calculated column whose `ExpressionContext` property is set to **User Context** (**Expression Context** in the **Properties** view). Direct references are reported in the DAX editor, the **Messages** view and the `te validate` CLI command, and indirect references and relationship-endpoint violations are reported in the **Messages** view. Para obtener más información, consulta @user-context-calculated-columns.

### Show actual DAX query in Table Preview

The **Table Preview** grid has a new **Show actual DAX query** option on its right-click menu, which opens a new, editable DAX query document with a query that reflects the preview's current filter and sort. Para obtener más información, consulta [Mostrar la Consulta DAX real](xref:table-preview#show-actual-dax-query).

### Cambio incompatible: los C# Scripts usan las funciones auxiliares de consulta del script en lugar de Model.Database

C# scripts can no longer call the query and command members `ExecuteCommand`, `ExecuteReader`, `ExecuteDax` and `EvaluateDax` directly on `Model.Database`. To run queries and commands, use the built-in script helpers `EvaluateDax(...)`, `ExecuteDax(...)`, `ExecuteReader(...)` and `ExecuteCommand(...)`, which are unchanged. Other `Model.Database` members, such as `Name`, `ID` and `CompatibilityLevel`, are also unchanged. Para más detalles, consulta @script-helper-methods.

## Mejoras en la versión 3.27.0.0

- Policies can now be set under `Software\Policies\Tabular Editor ApS`, with the product-specific subkeys `TE3` and `TECLI` for a policy that applies to one product only. Policies are now also read from the machine-wide hive, so Computer Configuration group policies apply and users can't override them. The previous `Software\Policies\Kapacity\Tabular Editor` key still works, and the `te` command-line tool honors these policies on Windows. Tabular Editor 3 also installs a Group Policy administrative template pair, which lets you set every policy from the Group Policy editor without editing the registry. Consulta @policies y [Uso de las plantillas administrativas](xref:policies#using-the-administrative-templates).

With it, added, deleted and changed objects stay distinct for the most common forms of color blindness. The mode applies to the **TOM Explorer** change indicators and the colors of the model comparison view. Consulta @accessibility.

- The DAX editor now recognizes the optional `AssociatedColumnsBehavior` parameter of the [LOOKUP](https://dax.guide/lookup/) function. Previously, the parameter was underlined as an unresolved reference. It now appears in the calltip as an optional trailing argument, and auto-complete suggests its two values, `EXPLICIT` and `INFERRED`, cased according to your **Preferred keyword casing** preference.
- Las acciones del menú y la barra de herramientas ya no hacen que los lectores de pantalla y otras herramientas de accesibilidad o automatización se queden bloqueados mientras hay un cuadro de diálogo abierto.
- You can now rename Metric View objects directly. Previously, you had to create a new object and delete the old one. Importing metric view YAML with duplicate object names now fails with a `Duplicate <kind> name '<name>'` error, and problems in join, field and measure expressions are reported separately, each naming the kind of object involved.

## Correcciones de errores en 3.27.0.0

- Fixed an issue where saving a model in Tabular Model Definition Language (TMDL) format could destroy a table, role, perspective or culture whose file name differed from the object's name only by letter case, a state that renaming an object can leave behind, for example a table named `Sales` stored in `tables/sales.tmdl`. Previously, the save reported success, but the object's file was deleted along with its contents, and the object was missing the next time the model was opened. Such a model now saves correctly: the object is kept, its file is saved under the object's name and the edit that triggered the save is applied.
- Fixed an issue where columns could be created in an arbitrary order when importing or updating a table from a SQL Server, Fabric Lakehouse or Fabric Warehouse source through **Model > Import tables...**, **Model > Update table schema...** or the CLI. Las columnas ahora siguen el orden de las columnas de la tabla de origen.
- Fixed an issue where importing a table from a Fabric Lakehouse or Warehouse through a data source that already carried its SQL analytics endpoint could create a table with no columns and no error. The columns are now read through that endpoint, and if no endpoint can be determined, an error states that the SQL analytics endpoint for the OneLake source can't be determined.
- Fixed an issue where importing a table whose server, database, schema or object name contains a double quote produced a Power Query expression that wouldn't parse. Such names are now escaped correctly, and when importing from Databricks or Snowflake, the query itself is also escaped correctly.
- Fixed an issue where a Snowflake connection using **External browser** authentication couldn't recover after its cached sign-in expired or was revoked by the identity provider. Previously, every later Snowflake operation failed without reopening the browser: the Table Import Wizard showed empty tables and columns with no error, and you had to restart Tabular Editor to recover. The browser sign-in now reopens when Snowflake rejects the cached sign-in, and a sign-in that times out or is abandoned now counts as a cancellation that no longer blocks later operations. Consulta [Inicios de sesión con navegador externo](xref:connect-snowflake#external-browser-sign-ins).
- Fixed an issue where saving a model to a folder or a `.bim` file on macOS or Linux produced different files than on Windows, including object names that couldn't be checked out on Windows, platform-dependent line endings and a varying table order. Ahora los modelos guardados en cualquier plataforma generan una salida idéntica. This also fixes a long-standing issue where two objects whose names map to the same escaped file name overwrote each other's file.
- Fixed an issue where moving a measure or calculated column to another table, or duplicating it, removed its error indicator even though the expression was still invalid. Antes, el indicador solo reaparecía después de volver a editar la expresión.
- Fixed an issue where the **TOM Explorer** collapsed and lost the current selection when a model with a connected workspace database was reloaded, either with **File > Reload from disk** or by an automatic reload after the files changed on disk. The expanded nodes, focused object, selection and scroll position are now kept, and reloading a model opened from a file also keeps the selection.
- Se corrigió un problema por el que pegar un objeto en el **Explorador TOM** podía dejar seleccionados tanto el original como la copia pegada, y el árbol se desplazaba lejos del objeto pegado. Ahora el objeto pegado queda seleccionado, recibe el foco y se mantiene a la vista.
- Se corrigió un problema por el que seleccionar un objeto en el **Explorador TOM** mientras se trabajaba en otra vista podía cambiar el documento activo a un diagrama de modelo abierto.
- Se corrigió un problema por el que seleccionar en el **Explorador TOM** una partición de Direct Lake, o una partición generada por una política de actualización incremental, provocaba un error y abría el cuadro de diálogo del Report de fallo. The **Expression Editor** now shows the partition's data coverage definition expression if it has one, and stays empty if it doesn't.
- Se corrigió un problema por el que abrir un modelo que contenía tablas calculadas cuyas columnas se infieren a partir de la expresión DAX podía fallar de forma intermitente con el error "Collection was modified; enumeration operation may not execute".
- Abrir un modelo ya no produce un error cuando el archivo de opciones de usuario del modelo (`.tmuo`) no contiene contenido legible. The file is now also written atomically, so an interrupted write can't damage it.
- Fixed an issue where saving a PBIP semantic model authored by Power BI Desktop renamed the item and cleared any description set in Fabric, and the change then propagated to the workspace on the next Fabric Git sync. Ahora, al guardar ese tipo de modelo en una nueva ubicación, la carpeta también toma el nombre del elemento.
- Fixed an issue where **File > Save As...** could suggest a file name that Windows can't save, most commonly for a document whose tab caption contains a colon. Invalid characters are now percent-encoded in the suggested name, which you can still edit.
- Fixed an issue where the status bar text could be unreadable when a custom **Status bar color** was picked for a connection. The status bar text and link colors are now derived from the chosen color. Previously, they were derived from the active theme.
- Fixed an issue where the Best Practice Analyzer's "Rules for the local user" collection could appear read-only on a machine where Tabular Editor hadn't yet created its local application data folder, such as on first run.
- Fixed an issue where DAX auto-complete suggested user-defined functions that aren't valid in the current argument context and omitted valid ones. UDFs are now filtered by their inferred return type, and UDFs whose definition contains a semantic error are no longer suggested. Filter arguments, which previously omitted UDFs entirely, now suggest them.
- Fixed an issue where **Inline measure** in the DAX editor could change the result of a calculation without warning when the reference was inside a row context, for example inside `SUMX` or `FILTER`. Where it can affect the result, the inlined expression is now wrapped in `CALCULATE( ... )` to preserve the context transition that a measure reference performs.
- Se corrigió un problema por el que **Medida en línea** podía convertir en comentario parte de la expresión circundante cuando la expresión de la medida expandida terminaba con una línea de comentario. Any code after the measure reference on that line now moves to a new line, indented to match.
- Se corrigió un problema por el que el **Asistente de IA** en la edición portátil (zip) a veces no estaba disponible tras iniciarse, aunque ya hubiera un proveedor de IA configurado. Previously, sending a message reported "AI client not initialized", and confirming the unchanged settings then failed with a "Method not found" error until the application was restarted. The Assistant now initializes on every launch, and if initialization fails, the chat reports the reason.
- Se corrigió un problema por el que el **Asistente de IA** no podía inicializarse cuando el proveedor se establecía en `Anthropic` u `OpenAI` y el nombre del modelo se dejaba en blanco. A blank model name now works, and initialization failures, which previously produced no feedback, are now reported in the chat.
- Se corrigió un problema por el que el **Asistente de IA** podía fallar con el error "The requested operation requires an element of type 'Number', but the target element has type 'String'" cuando se le pedía revisar un script o una consulta que había escrito antes en la conversación. The reply now completes, and the existing script or query is updated in place.
- Se corrigió un problema por el que el botón **Detener** del **Asistente de IA** no hacía nada mientras una tarjeta de **Permiso requerido** esperaba una respuesta, dejando la conversación bloqueada. Pressing **Stop** now ends the turn, and you can continue the same conversation with a new message.
- Se corrigió un problema por el que los bloques de código en el **Asistente de IA** resultaban ilegibles con un tema claro, ya que aparecían como texto casi negro sobre un bloque casi negro. Code blocks, their language label, **Copy** button and syntax coloring now follow the theme, and the block's header strip has also been cleaned up.
- Se corrigió un problema por el que el botón **Eliminar conversación** de la barra de herramientas del **Asistente de IA** eliminaba la conversación actual de inmediato, sin posibilidad de recuperarla. A confirmation prompt now appears, and the button has moved away from the panel's close button, which it was easily mistaken for.
- Fixed an issue where the text directly following a script or query card in an **AI Assistant** reply could appear unformatted, showing raw characters such as `**` or backticks.
- Fixed an issue where the **AI Assistant** could create a duplicate object when asked to update an existing one that had been renamed, moved or edited after the Assistant first created it.
- Fixed an issue where the **AI Assistant** showed an error and failed to respond when connected to a custom (OpenAI-compatible) provider using certain thinking or reasoning models. Requests that use tools, such as listing measures or running a DAX query, now work with these models.
