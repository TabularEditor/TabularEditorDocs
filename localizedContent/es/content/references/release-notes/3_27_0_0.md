## Novedades en la versión 3.27.0.0

Consulta nuestro [blog de lanzamientos](https://tabulareditor.com/blog/tabular-editor-3-september-2026-release) para obtener un breve resumen de las actualizaciones más importantes de esta versión.

### Servidor MCP

Tabular Editor 3 ahora puede actuar como servidor MCP (Model Context Protocol), de modo que el entorno de agentes que ya utilizas (Claude Code, GitHub Copilot, el modo agente de VS Code, Codex, Cursor y otros) pueda controlar las mismas funciones que el Asistente de IA sobre el modelo que tienes abierto, sin necesidad de configurar ningún proveedor de IA ni ninguna clave de API en Tabular Editor. Si sentías curiosidad por el desarrollo de modelos semánticos con agentes pero no querías otra suscripción de IA, o simplemente prefieres trabajar con tu propio agente, esta es la forma de empezar.

El agente trabaja sobre el modelo tal como lo ves en Tabular Editor 3, a través del servidor MCP y con el mismo modelo de objetos, motor de scripts y comprobaciones de seguridad que el Asistente de IA. Todo lo que hace queda en tu sesión de Tabular Editor, donde puedes revisarlo, deshacerlo y guardarlo cuando estés conforme. Elige **Herramientas > Servidor MCP...**, haz clic en **Iniciar servidor** y pega una sola vez la configuración ya preparada para tu herramienta de agente; un indicador en la barra de estado muestra si el servidor está en ejecución.

Decide desde el principio qué puede hacer un agente conectado mediante MCP configurando, en el cuadro de diálogo del servidor y antes de iniciarlo, los cinco permisos de IA (**Model metadata**, **Model data**, **Best Practice Analyzer**, **Documents** y **macros**); cualquier herramienta no cubierta por los permisos que concedas no se ofrece al agente, por lo que no aparecen ventanas emergentes de consentimiento mientras trabajas. Los mismos permisos regulan el chat del Asistente de IA y pueden editarse desde cualquiera de los dos lugares. Los cambios surten efecto la próxima vez que se inicie el servidor, y un agente que ya esté conectado debe volver a conectarse para verlos.

Con **Metadatos del modelo > Escritura**, un agente cambia tu modelo mediante C# Scripts que Tabular Editor compila, somete a comprobaciones de seguridad y ejecuta de forma atómica. Siempre puedes usar un solo **Ctrl+Z** para revertir todo lo que haya hecho un agente. Si un agente intenta usar Tabular Editor para realizar cambios fuera del modelo (archivos, red, ensamblados externos), nunca se permite; en su lugar, se abre como un C# Script para que lo revises.

Para obtener más información, consulta el nuevo artículo @mcp-server; el modelo de permisos se describe en [Permisos y consentimiento](xref:ai-assistant#permissions-and-consent).

### Disponibilidad general del Asistente de IA

El **Asistente de IA** ya está disponible de forma general. El componente de **AI features** está seleccionado de forma predeterminada en el instalador, así que el Asistente y el servidor MCP quedan listos nada más completar una instalación estándar (aunque puedes desmarcarlo, y si tu administrador de TI ha deshabilitado AI features, seguirá sin estar disponible). Puedes usar tu propia clave de API de OpenAI, Anthropic o Azure OpenAI, o apuntar a cualquier punto de conexión compatible con OpenAI, incluidos los modelos locales, o prescindir por completo de la clave y usar el servidor MCP con el agente que ya tengas.

Ahora el Asistente puede llevar a cabo los cambios en el modelo que le pidas, en lugar de limitarse a escribir un script para que lo ejecutes. Marca **Permitir que el Asistente de IA ejecute C# Scripts directamente** en **Herramientas > Preferencias > Funciones de IA > Asistente de IA** para activar esta opción. Para esto, debes establecer **Metadatos del modelo** en **Escritura** en **Herramientas > Preferencias > Funciones de IA > Permisos**. Solo se ejecutan así los scripts que modifican el propio modelo; cualquier cosa que intente acceder a archivos, a la red o a ensamblados externos se te sigue entregando para que lo revises en un documento de script. Cada ejecución se registra como un único paso de deshacer; si un script falla a mitad del proceso, el modelo queda intacto, y **Preview changes** se sigue respetando, de modo que puedas ver qué ha cambiado antes de confirmarlo y pulsar **Cancel** para revertirlo.

También hemos facilitado la elección de un modelo en el Asistente de IA. La lista desplegable **Nombre del modelo de IA** y el selector de modelos del panel se rellenan a partir de una lista en línea, de modo que puedas seleccionar nuevos modelos sin esperar a una actualización de Tabular Editor. La barra de uso del contexto, el punto en el que una conversación se compacta y la longitud máxima de una respuesta siguen ahora los límites reales del modelo en uso, en lugar de una sola cifra fija; y, con **Azure OpenAI**, el campo de modelo se etiqueta como **Deployment**, igual que en Azure. Gracias a [edhans](https://github.com/edhans) por sugerir el selector de modelos en nuestro [foro de ideas de GitHub](https://github.com/TabularEditor/TabularEditor3/discussions/1580).

Las instrucciones personalizadas ahora se eligen según la descripción de cada instrucción, y una instrucción que el Asistente haya detectado sigue en vigor durante el resto de la conversación. Si mantienes tus propios archivos de instrucciones, procura que la `description` de cada archivo sea precisa y específica; la sección `triggers` se ignora y puede eliminarse. Escribir `/instruction-id` sigue cargando una instrucción de forma explícita.

La Edición Enterprise de Tabular Editor 3 también mantiene un registro local de lo que hicieron el Asistente y el servidor MCP (los permisos solicitados y las respuestas dadas, las herramientas usadas y su resultado, y el texto completo de cualquier script que un agente ejecutó o te entregó). Nunca registra prompts, respuestas ni valores de datos, y se mantiene completamente local para el usuario. Lo encontrarás abriendo la carpeta de auditoría en **Herramientas > Preferencias > Funciones de IA**. Las directivas que puede establecer tu administrador se describen en la sección de directivas de la Edición Enterprise más abajo.

Para obtener más información, consulta @ai-assistant y [Permitir que el Asistente cambie tu modelo](xref:ai-assistant#letting-the-assistant-change-your-model).

### Indicadores de cambios no guardados

El **Explorador TOM** y el panel de **Propiedades** cuentan con una nueva función que marca, en todo el editor, los objetos con cambios sin guardar, para que puedas ver de un vistazo qué has tocado desde la última vez que guardaste. En el **Explorador TOM**, un objeto añadido se muestra en verde con un distintivo **+**; uno eliminado, en rojo con un distintivo **−**; y uno editado, en naranja con un distintivo en forma de punto. El panel de **Propiedades** marca las filas modificadas del mismo modo, y ambos paneles añaden un botón en la barra de herramientas que muestra solo lo que ha cambiado. Los indicadores cubren cualquier cambio sin guardar, ya sea realizado a mano, mediante un script o por un agente de IA, y se limpian en el momento en que el modelo se guarda, se recarga o se deshace hasta volver a su estado guardado.

Los cambios también pueden revertirse de forma selectiva. Haz clic con el botón derecho en una propiedad marcada y elige **Revert** para devolverla —junto con todo lo que cuelga de ella— al estado en que estaba en el último guardado; o selecciona una única propiedad para revertirla.

Esta función también hace que los objetos eliminados ya no desaparezcan simplemente del modelo. Hasta que se guarde el modelo, permanecen donde estaban, tachados, y con **Restore** en el menú contextual puedes recuperar uno exactamente como estaba justo antes de eliminarlo. En **Herramientas > Preferencias > Explorador TOM > Cambios no guardados** puedes desactivar los marcadores, agrupar los objetos eliminados de un contenedor bajo un único nodo **Objetos eliminados** y elegir cuánto tiempo permanecen visibles los objetos eliminados. Los C# Script también pueden usar nuevas funciones de esta característica: `Revert()`, `HasUnsavedChanges`, `DeletedObjects` y `Selected.Deleted`, junto con su correspondiente `Restore()`.

Para más información, consulta el nuevo artículo @unsaved-changes.

### Recarga automática desde el disco

Tabular Editor ahora detecta cuándo los archivos de metadatos del modelo que ha cargado cambian fuera de la aplicación (por un agente de IA, un script u otro editor) e incorpora esos cambios al modelo abierto sin que tengas que usar **Archivo > Recargar desde disco**. Un modelo cargado desde un archivo `.bim` supervisa ese archivo; un modelo cargado desde una carpeta supervisa todos los archivos `.json` o `.tmdl` que haya bajo la raíz del modelo.

Si no tienes cambios no guardados, el modelo simplemente se recarga en segundo plano. Si tienes cambios no guardados, aparece el aviso **Se detectaron cambios externos** y te pregunta si quieres **Recargar** (descartando tus cambios locales) o **Ignorar** (conservándolos).

Este comportamiento está habilitado de forma predeterminada y puede desactivarse con la nueva casilla **Recargar automáticamente desde disco (hot reload)** en **Herramientas > Preferencias > Varios**. Para más información, consulta el nuevo artículo @auto-reload.

### Autenticación con par de claves de Snowflake

Las conexiones a Snowflake ahora admiten autenticación con **par de claves**, en línea con la hoja de ruta de Snowflake para exigir MFA en las cuentas de servicio. En el cuadro de diálogo de conexión de Snowflake, elige **Par de claves** como autenticador, escribe tu nombre de usuario, selecciona el archivo de tu clave privada RSA y, si la clave está cifrada, introduce su frase de paso. Se admiten claves PKCS#1/PKCS#8 sin cifrar y claves PKCS#8 cifradas con frase de paso (el formato que generan los pasos documentados por Snowflake para crear claves). Para más información, consulta [Autenticación con par de claves](xref:connect-snowflake#key-pair-authentication).

### Directivas empresariales para el Asistente de IA y el servidor MCP

Ahora los administradores pueden elegir a qué pueden acceder y qué pueden hacer el Asistente de IA y el servidor MCP en el equipo de cualquier usuario, estableciendo directivas para cada uno de los cinco permisos de IA. Cuando se aplica un límite, las opciones de **Herramientas > Preferencias > Funciones de IA > Permisos** y del cuadro de diálogo **Herramientas > Servidor MCP...** solo ofrecen lo permitido, el Asistente deja de pedir permisos que no se le pueden conceder y no se comparte nada sobre el modelo abierto cuando no se permite acceder a los metadatos del modelo.

Del mismo modo, se pueden bloquear el proveedor de IA, el endpoint, el nombre del modelo o de la implementación, así como la organización y el proyecto de OpenAI, o restringirlos a una lista de proveedores y hosts de endpoint permitidos. Los administradores también pueden publicar una carpeta de instrucciones personalizadas para toda la organización (y excluir las que un usuario conserve para sí mismo), decidir qué herramientas ofrece el servidor MCP a los agentes conectados y fijar el puerto del servidor.

Estas políticas requieren Tabular Editor 3 Edición Enterprise. Mientras estas políticas estén establecidas, las demás ediciones no iniciarán el Asistente de IA ni el servidor MCP, y mostrarán qué valores requieren la Edición Enterprise. Para obtener más información, consulta [Políticas Enterprise](xref:policies#enterprise-policies).

### Política de administrador para scripts inseguros

Los administradores ahora también pueden permitir C# Scripts y macros solo cuando se limiten al modelo semántico. Con la restricción activa, cualquier script que lea o escriba archivos, acceda a la red, inicie otro programa, cargue código externo o envíe comandos directamente al servidor se rechaza antes de ejecutarse. Esta política se aplica a todas las superficies desde las que se pueden ejecutar scripts: el editor de scripts, la opción **Aplicar corrección** del Best Practice Analyzer, el **Asistente de IA**, el **servidor MCP** y la línea de comandos `te` (en Windows). Una macro que haga cualquiera de esas cosas ya no aparece en ningún menú y se marca en **Ver > Macros**, donde aún se puede abrir y editar.

Esta restricción requiere Tabular Editor 3 Edición Enterprise: mientras la política esté configurada, cualquier otra edición no permitirá en absoluto la ejecución de scripts ni macros. Para obtener más información, consulta [Scripts y macros](xref:policies#scripts-and-macros) en la referencia de políticas.

### Serialización por archivo para las UDF de DAX

Las funciones definidas por el usuario (UDFs) de DAX ahora pueden serializarse como archivos individuales al guardar un modelo con el formato de carpeta JSON. Cada UDF se escribe en su propio archivo `.json` dentro de la subcarpeta `functions/` en la raíz del modelo, por lo que las ediciones en paralelo de diferentes UDF ya no producen conflictos de fusión en Git en el `Database.json` compartido. El nuevo conmutador **Funciones definidas por el usuario (UDFs)** aparece en **Herramientas > Preferencias > Guardar en carpeta** y en **Modelo > Opciones de serialización**, y está habilitado de forma predeterminada para los nuevos guardados en carpeta; los modelos existentes serializados en carpeta conservan su diseño en línea hasta que lo actives y vuelvas a guardar.

Para obtener más información, consulta [Funciones definidas por el usuario (UDFs)](xref:save-to-folder#user-defined-functions-udfs).

### Semantic Analyzer señala limitaciones en columnas calculadas sensibles al contexto de usuario

El analizador semántico ahora notifica un error cuando se hace referencia a una **columna calculada sensible al contexto de usuario** (una columna calculada cuyo Contexto de expresión está establecido en Contexto de usuario) en lugares donde Power BI no lo permite. Las referencias directas se notifican en el editor de DAX, en la vista **mensajes** y en el comando de la CLI `te validate`; las referencias indirectas y las infracciones en los extremos de las relaciones se notifican en la vista **mensajes**.

Para obtener más información, consulta @user-context-calculated-columns.

### Mostrar la Consulta DAX real en Vista previa de datos

La cuadrícula de **Vista previa de datos** tiene una nueva opción del menú contextual: **Mostrar la Consulta DAX real**. Abre un nuevo documento de Consulta DAX editable, prellenado con una consulta que refleja el filtro y la ordenación actuales de la vista previa, para que puedas tomar la vista previa que estás viendo y seguir trabajando con ella como una consulta. Para obtener más información, consulta [Mostrar la Consulta DAX real](xref:table-preview#show-actual-dax-query).

### Cambio incompatible: los C# Scripts usan las funciones auxiliares de consulta del script en lugar de Model.Database

Los C# Scripts ya no pueden invocar directamente métodos de consulta o de comando en `Model.Database`. La forma de consultar el modelo en modo conectado desde scripts es (y siempre ha sido) mediante los asistentes de script integrados `EvaluateDax(...)`, `ExecuteDax(...)`, `ExecuteReader(...)` y `ExecuteCommand(...)`, que no han cambiado. Los scripts que usaban los asistentes documentados no se ven afectados. Para más detalles, consulta @script-helper-methods.

## Mejoras en la versión 3.27.0.0

- Ahora se pueden establecer directivas en `Software\Policies\Tabular Editor ApS`, con las subclaves específicas del producto `TE3` y `TECLI` para que una directiva afecte solo a un producto. Además, ahora también se leen desde la colmena de todo el equipo, por lo que las directivas de grupo de Configuración del equipo se aplican y el usuario no puede anularlas. La clave anterior `Software\Policies\Kapacity\Tabular Editor` sigue funcionando sin cambios, y la herramienta de línea de comandos `te` respeta estas directivas en Windows. Tabular Editor 3 también instala un par de plantillas administrativas de Directiva de grupo, de modo que cualquier directiva se puede configurar desde el editor de Directiva de grupo en lugar de editar el registro. Consulta @policies y [Uso de las plantillas administrativas](xref:policies#using-the-administrative-templates).
- Un nuevo **modo para daltónicos** en **Herramientas > Preferencias > Interfaz de usuario > Accesibilidad** marca en verde azulado los objetos añadidos desde el último guardado, en lugar de en verde, para que los objetos añadidos, eliminados y modificados sigan siendo fáciles de distinguir en las formas más comunes de daltonismo. Abarca los indicadores de cambios del **Explorador TOM** y los colores de la vista de comparación de modelos. Consulta @accessibility.
- Se ha añadido el nivel de compatibilidad 1706 de Power BI / Fabric al cuadro de diálogo **Nuevo modelo**, en sustitución de 1702 como nivel más reciente. Ahora 1706 se trata como el nivel de compatibilidad más reciente en toda la aplicación, incluida la regla del Best Practice Analyzer "Power BI models should use latest compatibility level" y los nuevos modelos de Power BI creados con `te init`.
- El filtro de valores de **Vista previa de datos** está limitado a 5,000 filas distintas. Una nueva preferencia permite aumentar ese límite si trabajas con tablas grandes, pero ten en cuenta que hacerlo puede incrementar los tiempos de carga.
- Se ha añadido la preferencia **Ordenar alfabéticamente las columnas de la vista previa de tabla** en **Herramientas > Preferencias > Exploración de datos > Vista previa de tabla**. Si la activas, las columnas de **Vista previa de datos** se ordenan por nombre, coincidiendo con el orden en que las muestra el **Explorador TOM** en lugar del orden en que las devuelve el motor. Desactivada de forma predeterminada. Consulta [Orden de columnas](xref:table-preview#column-order).
- Al seleccionar una columna en el **Explorador TOM**, ahora la **Vista previa de datos** se desplaza hasta esa columna y la resalta, por lo que ya no tienes que desplazarte por una tabla ancha para encontrarla. El seguimiento está activado de forma predeterminada y puede desactivarse para una vista previa concreta mediante el botón **Seguir la columna seleccionada** de la barra de herramientas, o de forma global en **Herramientas > Preferencias > Exploración de datos > Vista previa de tabla > Comportamiento**. Consulta [Buscar una columna en una tabla ancha](xref:table-preview#finding-a-column-in-a-wide-table).
- Al marcar **Seguir el Explorador TOM** en la **vista de dependencias de DAX**, ahora se muestran de inmediato las dependencias del objeto seleccionado actualmente, en lugar de esperar al siguiente cambio de selección.
- Se ha mejorado el **Explorador TOM** para que ya no parpadee ni salte después de editar una expresión DAX. Antes, el árbol podía volver a dibujarse brevemente y perder su posición de desplazamiento.
- Los diagramas del modelo ahora siguen la navegación programática en el **Explorador TOM**: al saltar a una tabla o columna mediante acciones de **Ir a** o resultados de búsqueda, ese objeto se resalta en todos los diagramas abiertos, exactamente igual que al hacer clic en él en el árbol.
- **Archivo > Revertir** ahora es **Archivo > Recargar desde disco** o **Archivo > Recargar desde servidor**, según el origen del modelo abierto, y todo lo que muestra el comando usa esa misma redacción: la confirmación que solicita, la barra de estado mientras se ejecuta y cuando termina, y el error si falla.
- El editor de DAX ahora reconoce el parámetro opcional `AssociatedColumnsBehavior` de la función [LOOKUP](https://dax.guide/lookup/), que antes aparecía subrayado como una referencia sin resolver. Aparece en la ayuda emergente de parámetros como un argumento opcional al final, y el autocompletado ofrece sus dos valores, `EXPLICIT` e `INFERRED`, con el estilo de mayúsculas definido por tu preferencia de **Capitalización preferida de palabras clave**.
- Las acciones del menú y la barra de herramientas ya no hacen que los lectores de pantalla y otras herramientas de accesibilidad o automatización se queden bloqueados mientras hay un cuadro de diálogo abierto.
- Los objetos de la vista de métricas ahora se pueden cambiar de nombre directamente, sin tener que crear un objeto nuevo y eliminar el anterior. Al importar YAML de la vista de métricas con nombres de objeto duplicados, ahora se produce un error con un diagnóstico claro; además, los problemas en las expresiones de unión, campo y medida se notifican por separado, indicando en cada caso el tipo de objeto implicado.
- La página **Novedades** se ha sustituido por una nueva página **Primeros pasos**, disponible en el menú **Ayuda** y que se muestra en el primer inicio y después de una actualización.
- Tabular Editor 3 ahora también está disponible como compilación de .NET 10, junto con la compilación existente de .NET 8, tanto para x64 como para ARM64. La descarga de .NET 10 es la recomendada y requiere el [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0), que el instalador puede descargar e instalar automáticamente. Los instaladores de .NET 8, los paquetes MSI y los archivos portátiles se siguen publicando sin cambios para los equipos que todavía no pueden pasar al runtime más reciente. Ambas compilaciones son funcionalmente idénticas y pueden instalarse en paralelo, y la CLI de Tabular Editor ahora se distribuye solo para .NET 10; es autocontenida, por lo que no hace falta instalar ningún runtime para usarla. Consulta @system-requirements.
- Se actualizaron a sus versiones compatibles más recientes los componentes de terceros sobre los que se basa Tabular Editor, incluidos [Microsoft.AnalysisServices](https://www.nuget.org/packages/Microsoft.AnalysisServices/) (TOM/AMO) 19.117.0, [DevExpress WinForms](https://www.nuget.org/packages/DevExpress.Win.Design/) 25.2.9, [Roslyn](https://www.nuget.org/packages/Microsoft.CodeAnalysis.CSharp/) 5.9.0 para scripting en C#, [WebView2](https://www.nuget.org/packages/Microsoft.Web.WebView2/) 1.0.4129.50, [Microsoft.Extensions.AI](https://www.nuget.org/packages/Microsoft.Extensions.AI/) 10.9.0 y [Anthropic](https://www.nuget.org/packages/Anthropic/) 12.40.0 para el Asistente de IA, [Microsoft.Fabric.Api](https://www.nuget.org/packages/Microsoft.Fabric.Api/) 2.20.0, [Microsoft.PowerBI.Api](https://www.nuget.org/packages/Microsoft.PowerBI.Api/) 5.1.0, [Microsoft.Identity.Client](https://www.nuget.org/packages/Microsoft.Identity.Client.Desktop/) 4.87.0, [Microsoft.Data.SqlClient](https://www.nuget.org/packages/Microsoft.Data.SqlClient/) 6.1.5 y [Spectre.Console](https://www.nuget.org/packages/Spectre.Console/) 0.57.2 para la interfaz de línea de comandos. El componente de edición de código en el que se basan los editores de DAX y M (el paquete [Scintilla](https://www.nuget.org/packages/Scintilla5.NET/)) se actualizó a la versión 7.0.0, que incluye componentes nativos firmados digitalmente para Arm64 además de x64, algo relevante en dispositivos Windows on Arm y en entornos que aplican directivas de integridad de código. Como resultado de la actualización de Analysis Services, la propiedad **Comportamiento de indexación de cadenas** de una columna ahora se muestra en modelos con nivel de compatibilidad 1706 o superior.
- Se actualizaron las dependencias de paquetes NuGet para corregir vulnerabilidades de seguridad conocidas: [System.Security.Cryptography.Xml](https://www.nuget.org/packages/System.Security.Cryptography.Xml/) a 10.0.11 (GHSA-g8r8-53c2-pm3f, GHSA-cvvh-rhrc-wg4q) y [SQLitePCLRaw](https://www.nuget.org/packages/SQLitePCLRaw.bundle_e_sqlite3/) a 2.1.13 (GHSA-2m69-gcr7-jv3q).

## Correcciones de errores en 3.27.0.0

- Se corrigió un problema por el que, al guardar un modelo en formato TMDL, podía destruirse una tabla, un rol, una perspectiva o una configuración regional cuyo nombre de archivo solo se diferenciaba del nombre del objeto por el uso de mayúsculas/minúsculas; por ejemplo, una tabla llamada `Sales` almacenada en `tables/sales.tmdl`, que es lo que queda tras renombrar un objeto. Antes, se informaba de que el guardado se había realizado correctamente, pero el archivo del objeto se eliminaba junto con todo su contenido, y el objeto simplemente no aparecía la siguiente vez que se abría el modelo. Ese modelo ahora se guarda correctamente: el objeto se conserva, su archivo se mantiene con el propio nombre del objeto y se aplica el cambio que provocó el guardado.
- Se corrigió un problema por el que las columnas podían crearse en un orden arbitrario al importar o actualizar una tabla desde una fuente de SQL Server, Fabric Lakehouse o Fabric Warehouse, tanto en **Modelo > Importar tablas** como en **Modelo > Actualizar esquema de tabla**, así como en la CLI. Las columnas ahora siguen el orden de las columnas de la tabla de origen.
- Se corrigió un problema por el que, al importar una tabla desde un Fabric Lakehouse o Warehouse a través de un Data source que ya incluía su punto de conexión de análisis SQL, podía crearse una tabla sin columnas sin avisar. Ahora se muestra un error claro cuando no hay columnas disponibles.
- Se corrigió un problema por el que, al importar una tabla cuyo nombre de servidor, base de datos, esquema u objeto contenía una comilla doble, se generaba una expresión de Power Query que no se podía analizar. Ahora se aplican correctamente los caracteres de escape a esos nombres y a la propia consulta al importar desde Databricks o Snowflake.
- Se corrigió un problema por el que una conexión de Snowflake con autenticación de **Navegador externo** no podía recuperarse una vez que el inicio de sesión en caché expiraba o el proveedor de identidades lo revocaba. Antes, todas las operaciones posteriores de Snowflake fallaban si no se volvía a abrir el navegador; el asistente para importar tablas mostraba silenciosamente tablas y columnas vacías en lugar de un error, y la única forma de recuperarlo era reiniciar Tabular Editor. Ahora, el inicio de sesión en el navegador se vuelve a abrir en cuanto Snowflake rechaza el que está en caché, y un inicio de sesión que agota el tiempo de espera o se abandona se trata como una cancelación, en lugar de como un error que bloquea operaciones posteriores. Consulta [Inicios de sesión con navegador externo](xref:connect-snowflake#external-browser-sign-ins).
- Se corrigió un problema por el que guardar un modelo en una carpeta o en un archivo `.bim` en macOS o Linux generaba archivos distintos a los de Windows, incluidos nombres de objeto que no se podían recuperar con un check-out en Windows, finales de línea dependientes de la plataforma y un orden de tablas variable. Ahora los modelos guardados en cualquier plataforma generan una salida idéntica. Esto también corrige un problema antiguo por el que dos objetos cuyos nombres daban lugar al mismo nombre de archivo tras aplicar el escape sobrescribían el archivo del otro.
- Se corrigió un problema por el que, al mover una medida o columna calculada a otra tabla, o al duplicarla, su indicador de error desaparecía aunque la expresión seguía siendo inválida. Antes, el indicador solo reaparecía después de volver a editar la expresión.
- Se corrigió un problema por el que el **Explorador TOM** se plegaba y perdía la selección actual al recargar un modelo con una base de datos de Workspace conectada, ya fuera a través de **Archivo > Recargar desde disco** o mediante una recarga automática después de que los archivos cambiaran en el disco. Ahora se conservan los nodos expandidos, el objeto con el foco, la selección y la posición de desplazamiento, y al recargar un modelo abierto desde un archivo también se conserva la selección.
- Se corrigió un problema por el que pegar un objeto en el **Explorador TOM** podía dejar seleccionados tanto el original como la copia pegada, y el árbol se desplazaba lejos del objeto pegado. Ahora el objeto pegado queda seleccionado, recibe el foco y se mantiene a la vista.
- Se corrigió un problema por el que seleccionar un objeto en el **Explorador TOM** mientras se trabajaba en otra vista podía cambiar el documento activo a un diagrama de modelo abierto.
- Se corrigió un problema por el que seleccionar en el **Explorador TOM** una partición de Direct Lake, o una partición generada por una política de actualización incremental, provocaba un error y abría el cuadro de diálogo del Report de fallo. Ahora el **Editor de expresiones** muestra la expresión de definición de la cobertura de datos de la partición si existe, y en caso contrario permanece vacío.
- Se corrigió un problema por el que abrir un modelo que contenía tablas calculadas cuyas columnas se infieren a partir de la expresión DAX podía fallar de forma intermitente con el error "Collection was modified; enumeration operation may not execute".
- Abrir un modelo ya no produce un error cuando el archivo de opciones de usuario del modelo (`.tmuo`) no contiene contenido legible. Además, el archivo ahora se escribe de forma atómica, por lo que una escritura interrumpida no puede dañarlo.
- Se corrigió un problema por el que guardar un modelo semántico PBIP creado en Power BI Desktop cambiaba el nombre del elemento y borraba cualquier descripción establecida en Fabric, lo que luego se propagaba al Workspace en la siguiente sincronización de Git de Fabric. Ahora, al guardar ese tipo de modelo en una nueva ubicación, la carpeta también toma el nombre del elemento.
- Se corrigió un problema por el que **Archivo > Guardar como...** podía sugerir un nombre de archivo que Windows no permitía guardar, sobre todo en un documento cuyo título de pestaña contiene dos puntos. Los caracteres no válidos del nombre sugerido ahora se codifican como porcentaje, y el nombre sigue siendo totalmente editable.
- Se corrigió un problema por el que el texto de la barra de estado podía resultar ilegible al elegir un **Color de la barra de estado** personalizado para una conexión. Los colores del texto y de los enlaces de la barra de estado ahora se derivan del color elegido, y no del tema activo.
- Se corrigió un problema por el que la colección "Reglas para el usuario local" de Best Practice Analyzer podía aparecer en modo de solo lectura en un equipo donde Tabular Editor aún no había creado su carpeta local de datos de aplicación, por ejemplo, en la primera ejecución.
- Se corrigió el autocompletado de DAX, que sugería funciones definidas por el usuario no válidas en el contexto actual de argumentos y omitía otras que sí lo eran. Las UDF ahora se filtran por su tipo de retorno inferido; los argumentos de filtro ahora sugieren UDF (antes se omitían por completo), y ya no se ofrecen las UDF cuya definición contenga un error semántico.
- Se corrigió un problema por el que **Medida en línea** del editor de DAX podía cambiar silenciosamente el resultado de un cálculo cuando la referencia estaba dentro de un contexto de fila, por ejemplo, dentro de `SUMX` o `FILTER`. La expresión insertada en línea ahora se envuelve en `CALCULATE( ... )` para conservar la transición de contexto que realiza una referencia a una medida, pero solo cuando esa envoltura puede suponer una diferencia.
- Se corrigió un problema por el que **Medida en línea** podía convertir en comentario parte de la expresión circundante cuando la expresión de la medida expandida terminaba con una línea de comentario. Ahora, todo lo que seguía a la referencia a la medida en esa línea se mueve a una línea nueva, con la sangría correspondiente.
- Se corrigió un problema por el que el **Asistente de IA** en la edición portátil (zip) a veces no estaba disponible tras iniciarse, aunque ya hubiera un proveedor de IA configurado. Antes, al enviar un mensaje se mostraba "AI client not initialized", y al confirmar la configuración sin cambios se producía el error "Method not found", que persistía hasta reiniciar la aplicación. Ahora el asistente se inicializa de forma consistente en cada inicio y, si la inicialización falla, el chat muestra el motivo real.
- Se corrigió un problema por el que el **Asistente de IA** no podía inicializarse cuando el proveedor se establecía en `Anthropic` u `OpenAI` y el nombre del modelo se dejaba en blanco. Ahora, un nombre de modelo en blanco funciona como se espera, y los fallos de inicialización se muestran en el chat en lugar de no ocurrir nada.
- Se corrigió un problema por el que el **Asistente de IA** podía fallar con el error "The requested operation requires an element of type 'Number', but the target element has type 'String'" cuando se le pedía revisar un script o una consulta que había escrito antes en la conversación. Ahora se completa la respuesta y el script o la consulta existentes se actualizan en el mismo lugar.
- Se corrigió un problema por el que el botón **Detener** del **Asistente de IA** no hacía nada mientras una tarjeta de **Permiso requerido** esperaba una respuesta, dejando la conversación bloqueada. Ahora, al pulsar **Detener** se finaliza el turno, y la misma conversación puede continuarse con un mensaje nuevo.
- Se corrigió un problema por el que los bloques de código en el **Asistente de IA** resultaban ilegibles con un tema claro, ya que aparecían como texto casi negro sobre un bloque casi negro. Los bloques de código, su etiqueta de idioma, el botón **Copiar** y el resaltado de sintaxis ahora siguen el tema, y la franja de encabezado del bloque se ha pulido.
- Se corrigió un problema por el que el botón **Eliminar conversación** de la barra de herramientas del **Asistente de IA** eliminaba la conversación actual de inmediato, sin posibilidad de recuperarla. Ahora pide confirmación y se ha movido lejos del botón de cierre del panel, con el que se confundía fácilmente.
- Se corrigió un problema por el que el texto inmediatamente posterior a una tarjeta de script o consulta en una respuesta del **Asistente de IA** podía aparecer sin formato, mostrando caracteres sin procesar como `**` o comillas invertidas en lugar de texto con formato.
- Se corrigió un problema por el que el **AI Assistant** podía crear un objeto duplicado en lugar de actualizar uno existente, cuando ese objeto se había renombrado, movido o editado después de que el asistente lo hubiera creado por primera vez.
- Se corrigió un problema por el que el **AI Assistant** mostraba un error y no respondía al conectarse a un proveedor personalizado (compatible con OpenAI) mediante determinados modelos de razonamiento. Las solicitudes que dependen de herramientas, por ejemplo, listar medidas o ejecutar una Consulta DAX, ahora funcionan con estos modelos.

## ¿Vienes de Tabular Editor 2.x?

Mira [este vídeo](https://youtu.be/O4ATwdzCvWc) para hacer un recorrido rápido por las principales funcionalidades de Tabular Editor 3. Además, asegúrate de consultar nuestra [guía de inicio](https://docs.tabulareditor.com/onboarding/index.html).

**Resumen de las principales funciones de Tabular Editor 3:**

- IDE totalmente personalizable, con soporte para varios monitores, HiDPI y temas
- Nuevo y potente editor de código DAX con autocompletar, comprobación de sintaxis, plegado de código y mucho, mucho más
- \*Modo del área de trabajo, que permite guardar los cambios en disco y sincronizar simultáneamente los metadatos del modelo con Analysis Services
- \*Obtén una vista previa de los datos de las tablas con desplazamiento infinito, crea PivotGrids o escribe consultas DAX para explorar el modelo o probar la lógica de cálculo
- \*Programa actualizaciones de datos
- Actualiza los esquemas de tablas tanto en los Data source del proveedor como en los orígenes de datos estructurados (sí, ¡incluso para consultas M!)
- Crear diagramas de Data model
- Crear scripts DAX que te permiten editar varias medidas u otros objetos calculados en un único documento
- Grabar C# Scripts y guardarlos como macros (antes conocidos como "Custom Actions")
- Integración del Analizador VertiPaq
- Depurador de DAX
- Integración del Optimizador de DAX
- Acciones de código para refactorizar tu DAX fácilmente.

\*=Solo cuando estés conectado a una instancia de Analysis Services o Power BI
