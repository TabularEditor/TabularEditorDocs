## Mejoras en la versión 3.27.1.0

- El [asistente de IA](https://docs.tabulareditor.com/en/features/ai-assistant.html) y los agentes conectados a través del [servidor MCP](https://docs.tabulareditor.com/en/features/mcp-server.html) ahora reciben los errores de DAX de tu modelo y de los documentos abiertos:
  - Ahora enumera los errores, las advertencias y los mensajes de Analysis Services que muestra la vista **Mensajes**.
  - Los errores y las advertencias del documento activo (consulta DAX, script DAX, script C# o Pivot Grid) se añaden al contexto del asistente.
  - Después de que se ejecute un script de C#, el resultado enumera los errores que el script ha introducido o resuelto.

  El texto de error devuelto por Analysis Services puede contener datos del modelo y solo se comparte cuando el permiso **Datos del modelo** está establecido en **Lectura**.

- Los documentos **Consulta DAX** y **Pivot Grid** ahora permanecen abiertos cuando abres un modelo diferente y se conectan al nuevo modelo. Una consulta DAX conserva su texto y los cambios sin guardar. Un Pivot Grid conserva su estructura y elimina los campos que no tiene el nuevo modelo. Desactive esta opción con **Mantener las consultas DAX abiertas cuando se abra un modelo diferente** y **Mantener los Pivot Grids abiertos cuando se abra un modelo diferente** en **Herramientas > Preferencias > Exploración de datos**. Consulte [Consultas DAX: cambio de modelos](https://docs.tabulareditor.com/en/features/dax-query.html#switching-models) y [Pivot Grids: cambio de modelos](https://docs.tabulareditor.com/en/features/pivot-grid.html#switching-models).
- **Modelo > Implementar...** tiene una nueva opción, **Implementar metadatos lingüísticos (sinónimos de preguntas y respuestas, instrucciones de IA y esquema de datos de IA)**, seleccionada de forma predeterminada. Desmárcala para conservar las instrucciones de la IA, el esquema de datos de la IA y los sinónimos de preguntas y respuestas ya configurados en el modelo semántico de destino. Consulte [Opciones de implementación](https://docs.tabulareditor.com/en/features/deployment.html#deployment-options).
- Haga clic con el botón derecho en un servidor de la lista **Servidor** de **Archivo > Abrir > Modelo desde BD...** o del asistente de implementación para **Anclarlo**, **Desanclarlo** o **Eliminarlo**. Los servidores anclados permanecen en la parte superior de la lista y no se eliminan con **Borrar servidores recientes**. Consulte [Servidores recientes y anclados](https://docs.tabulareditor.com/en/how-tos/xmla-as-connectivity.html#recent-and-pinned-servers).
- El título de la ventana ahora comienza con el nombre del modelo. La preferencia **Detalles de origen del modelo** en **Herramientas > Preferencias > Tabular Editor > Interfaz de usuario** sustituye a **Ocultar detalles de origen del modelo** y establece qué parte de la ubicación del modelo se muestra en la barra de título, la barra de estado, las descripciones emergentes de las pestañas y las listas de elementos recientes. La barra de estado muestra la conexión como `<database>@<server>`. Consulta [Preferencias de la interfaz de usuario](https://docs.tabulareditor.com/en/references/preferences.html#tabular-editor--user-interface) e [Interfaz de usuario de Tabular Editor 3](https://docs.tabulareditor.com/en/features/views/user-interface.html#basic-user-interface-elements).
- La vista **Mensajes** tiene una columna **Causado por** que muestra el objeto que causa un error en cascada y **+N errores dependientes** en el objeto que causa errores en otros objetos. Haga clic con el botón derecho en un error para desactivar **Mostrar errores en cascada** o para elegir **Ir a la causa raíz**. Consulte [Errores en cascada y causas raíz](https://docs.tabulareditor.com/en/features/views/messages-view.html#cascading-errors-and-root-causes).

## Correcciones de errores en la versión 3.27.1.0

- Se ha solucionado un problema por el que, al establecer el **Ordinal** de un elemento de cálculo para moverlo hacia el final de su grupo de cálculos, se colocaba una posición antes de lo debido.
- Se ha solucionado un problema por el que **Archivo > Nuevo > Modelo...** aplicaba el nombre elegido solo al modelo y dejaba la base de datos con el nombre `SemanticModel`.
- Se ha solucionado un problema por el que se aceptaba un nombre de configuración regional no válido para la propiedad **Culture** (Configuración regional) de un modelo y para la propiedad **Language** (Lenguaje) de una traducción. Ahora estos valores se rechazan con un error como `'en US' is an invalid culture specifier`.
- Se ha solucionado un problema por el que la comparación de dos modelos fallaba con el mensaje `Object reference not set to an instance of an object` cuando diferían en los miembros de los roles, los grupos de consultas u otros elementos de la colección sin nombre.
- Se ha corregido un problema por el que no se informaba de un carácter de espacio en blanco no estándar en una expresión DAX, como un espacio sin separación. Ahora se informa como un error que indica el carácter y le dice que ejecute **Formatear DAX**.
- Se han solucionado problemas en el **Metadata Translation Editor**:
  - Borrar una celda de traducción no tenía ningún efecto; ahora elimina la traducción.
  - La celda **Mostrar carpeta** de una tabla, un nivel de jerarquía, una perspectiva o el modelo era editable y el valor se descartaba; ahora estas celdas son de solo lectura.
  - El menú contextual de la cabecera de la columna ofrecía la opción **Mostrar fila de filtro automático**, que no funcionaba en las columnas de traducción.
- Se ha solucionado un problema por el que, al cerrar el **Asistente para importar tablas** mientras mostraba una lista de tablas, podía aparecer un cuadro de diálogo de informe de errores o faltar objetos en el árbol.
- Se ha solucionado un problema por el que al cancelar el cuadro de diálogo **Cargar modelo semántico desde base de datos** o la solicitud de credenciales del origen de datos se podía cerrar Tabular Editor y perder el trabajo no guardado.
- Se han solucionado problemas por los que **Depurar este valor** en un valor de **Pivot Grid** ignoraba o invertía algunos de los filtros de la cuadrícula, de modo que el depurador mostraba un valor diferente al de la cuadrícula.
- Se ha solucionado un problema por el que un documento abierto por un cliente MCP cuando Tabular Editor no era la ventana activa mostraba la barra de herramientas y el menú del documento anterior. Informado en [debate de GitHub n.º 1590](https://github.com/TabularEditor/TabularEditor3/discussions/1590).
- Se ha corregido un problema por el que al duplicar o pegar una medida, columna o jerarquía que aparecía en varias carpetas de visualización, la copia se colocaba en una sola carpeta con el nombre de todas ellas, como `folder_01;folder_02`. La copia ahora aparece en todas las carpetas de visualización del original.
- Se han solucionado problemas en el editor de **Consultas DAX** por los que, al ejecutar una de varias consultas de un documento, se utilizaba el bloque `DEFINE` de la primera consulta, y al ejecutar una columna seleccionada en una cláusula `ORDER BY` se producía un error con el mensaje `A single value for column ... cannot be determined`.
- Se ha corregido un problema por el que la vista **Mensajes** dejaba de mostrar los errores de los documentos que permanecían abiertos después de abrir un modelo diferente.
- Se han solucionado problemas que podían provocar el cierre inesperado de Tabular Editor 3 o la aparición de un cuadro de diálogo de error:
  - Mientras la vista **Propiedades** mostraba una medida o cuando se eliminaba su objeto seleccionado.
  - al abrir un modelo semántico, con un error de «No se puede acceder a un objeto eliminado»
  - después de una edición que eliminaba un objeto con una expresión DAX y renombraba o añadía otro objeto
  - Mientras se editaba una expresión DAX, con un error del tipo «El índice estaba fuera de los límites de la matriz».
- Se ha solucionado un problema por el que un origen de datos heredado que utilizaba un nombre de proveedor OLE DB específico de una versión, como `Provider=MSOLEDBSQL19.1`, aparecía como no instalado y el cuadro de diálogo **Propiedades del vínculo de datos** se abría sin el proveedor original. Este problema era una regresión desde la versión 3.25.0.
- Se ha solucionado un problema por el que **Analizador VertiPaq > Recopilar estadísticas** no devolvía ninguna estadística cuando no se podían analizar los datos del modelo. Ahora las estadísticas se recopilan a partir de los metadatos del modelo con una advertencia, y si se desactiva **Leer estadísticas de datos** en **Herramientas > Preferencias > Formatos de archivo > Analizador VertiPaq**, se omite la lectura de datos.

## ¿Viene de Tabular Editor 2.x?

Para ver un repaso de las principales características de Tabular Editor 3, mira [este vídeo](https://youtu.be/O4ATwdzCvWc). Para empezar, consulte la [guía de incorporación](https://docs.tabulareditor.com/onboarding/index.html).

**Principales funciones de Tabular Editor 3:**
- IDE personalizable con soporte para múltiples monitores y Hi-DPI, y temas
- Editor de código DAX con autocompletado, comprobación de sintaxis, plegado de código y formateo
- *Modo de espacio de trabajo, que guarda sus cambios en el disco y sincroniza los metadatos del modelo con Analysis Services al mismo tiempo
- *Vista previa de datos de tabla con desplazamiento infinito, creación de PivotGrids o escritura de consultas DAX para explorar el modelo o probar la lógica de cálculo
- *Programar actualizaciones de datos
- Actualización del esquema de tabla tanto en los orígenes de datos de proveedor como en los estructurados, incluidas las consultas M
- Crear diagramas de modelos de datos
- Crear scripts DAX para editar varias medidas u otros objetos calculados en un solo documento
- Grabar scripts de C# y guardarlos como macros (antes «Acciones personalizadas»)
- Integración con el analizador VertiPaq
- Depurador DAX
- Integración con el Optimizador de DAX
- Acciones de código para refactorizar tu DAX

*=Solo cuando se está conectado a una instancia de Analysis Services o Power BI
