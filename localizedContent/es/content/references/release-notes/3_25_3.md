## Novedades de la versión 3.25.0

Consulta nuestro [blog de lanzamiento](https://tabulareditor.com/blog/tabular-editor-3-january-2026-release) para ver un breve resumen de las actualizaciones más importantes de esta versión.

- Tabular Editor ahora está disponible en [**chino y español (versión preliminar)**](xref:references-application-language). Todas las traducciones se han realizado inicialmente con IA, con revisión humana. También están disponibles el japonés, el alemán y el francés como idiomas experimentales, que aún no se han revisado.
- Tabular Editor ahora incluye un conjunto de [**reglas integradas del Best Practice Analyzer (BPA)**](xref:built-in-bpa-rules) que abarcan prácticas recomendadas clave en formato, metadatos, diseño del modelo, expresiones DAX y traducciones.
- Tabular Editor ahora incluye la funcionalidad **Semantic Bridge**, que permite crear fácilmente modelos semánticos a partir de [Metric Views](https://docs.databricks.com/aws/en/metric-views/) de Databricks (_solo en la Edición Enterprise de Tabular Editor 3_).
- Se ha añadido una opción para guardar modelos semánticos con [**archivos complementarios para Fabric**](xref:save-with-supporting-files). Cuando se habilita, Tabular Editor puede crear y actualizar los archivos .platform y definition.pbism junto con los metadatos del modelo para ajustarse a la estructura del repositorio de Fabric.
- Esta versión también incorpora un nuevo **Editor de calendario**, que facilita la administración de los objetos de calendario usados para la inteligencia temporal basada en calendario.
- Por último, pero no por ello menos importante, hemos añadido un cuadro de diálogo de [**Actualización avanzada**](xref:advanced-refresh), desde el cual puedes configurar opciones avanzadas de actualización, como el paralelismo y la fecha efectiva de la actualización incremental. También puedes especificar [perfiles de sobrescritura de actualización](xref:refresh-overrides) (_solo para Tabular Editor 3 Edición Business y Edición Enterprise_).

## Mejoras en la versión 3.25.0

- Ahora puedes establecer la propiedad CustomData de la cadena de conexión directamente desde el cuadro de diálogo de Impersonation.
- La vista del Administrador de paquetes de DAX ahora descarga y muestra los iconos de los paquetes de DaxLib.
- El Administrador de paquetes de DAX ahora almacena en caché los metadatos de los paquetes, lo que permite mostrar la información del paquete sin necesidad de conexión a Internet.
- Hemos actualizado la biblioteca cliente de AS a la versión más reciente del paquete [19.108.5](https://www.nuget.org/packages/Microsoft.AnalysisServices/19.108.5). Esta actualización te permite controlar la nueva propiedad [UnicodeCharacterBehavior](https://learn.microsoft.com/en-us/dotnet/api/microsoft.analysisservices.tabular.database.unicodecharacterbehavior?view=analysisservices-dotnet#microsoft-analysisservices-tabular-database-unicodecharacterbehavior) del objeto Database.
- Hemos agregado las categorías de datos de columna específicas de Power BI: Longitud, Latitud y Lugar.
- Ahora mostramos un mensaje de error en el panel de mensajes si intentas establecer el nivel de compatibilidad de un modelo en un valor que el servidor no admite. Esto evita errores inesperados más adelante al guardar cambios en el modelo. Si necesitas establecer un nivel de compatibilidad no admitido con fines de migración, guarda los metadatos del modelo en disco (en formato .bim o TMDL) y luego abre los metadatos sin ninguna base de datos de Workspace asociada.
- Los archivos de opciones de usuario (.tmuo) ahora también se guardan cuando abres un modelo directamente desde un servidor o un extremo XMLA. Los archivos se almacenan en la carpeta %LocalAppData%\TabularEditor3\UserOptions.
- Hemos agregado la opción "Actualizar completamente (ignorar política)" al menú contextual de actualización de datos, para que puedas actualizar fácilmente los datos en particiones existentes sin desencadenar operaciones de adición/eliminación/combinación de particiones en el servidor cuando una tabla esté gobernada por una política de actualización incremental.
- Hemos reorganizado las opciones del menú contextual de actualización de datos para llevar las opciones más usadas a la parte superior.
- Hemos agregado "Hora de inicio" al panel de actualización, lo que te permite ordenar las actualizaciones por el momento en que se iniciaron; por ejemplo, ver primero la más reciente.
- Hemos agregado un panel de búsqueda al cuadro de diálogo de Preferencias para buscar rápidamente preferencias individuales.
- Hemos agregado "Funciones definidas por el usuario" y "Calendarios" a la lista del editor de reglas de prácticas recomendadas.
- Hemos agregado la propiedad `UsedInCalendars` a las columnas, lo que facilita comprobar dentro de un C# Script si una columna se usa en algún objeto de calendario.
- La acción de menú "Archivo > Cerrar" pasa a llamarse "Cerrar documento" y ahora permite cerrar cualquier panel o documento del área principal de documentos. **Ctrl + W** se asigna como acceso directo predeterminado.
- Hemos agregado compatibilidad del Analizador semántico con la nueva palabra clave `ENDALIGNED` del parámetro <extension> de [`DATEADD`](https://dax.guide/DATEADD). [Más información](https://learn.microsoft.com/en-us/dax/dateadd-function-dax#extension-parameter-for-small--large-period-shifts).
- Al guardar en un archivo model.bim o en una estructura de carpetas TMDL con la opción de serialización **Ignorar particiones de actualización incremental** habilitada, ahora agregamos una partición ficticia para reemplazar las particiones PolicyRange. Esto garantiza que el modelo pueda seguir cargándose en Power BI Desktop, ya que no se guarda ninguna tabla sin particiones.

## Correcciones de errores en 3.25.0

- Se corrigió un problema crítico que impedía que algunos clientes se conectaran a la API REST de Power BI o a Databricks usando la autenticación de Azure AD.
- Se corrigió una excepción no controlada que se producía al eliminar una columna que también se usaba en un objeto de calendario.
- Se corrigió la lista desplegable de columnas del editor de relaciones para que muestre automáticamente los nombres completos de las columnas.
- Al duplicar una tabla que contiene uno o varios calendarios, ahora los calendarios se renombran automáticamente para garantizar nombres únicos en todo el modelo.
- Varios errores o advertencias detectados durante una operación de actualización de datos ya no deberían desencadenar una excepción no controlada.
- Se corrigió que la lista de paquetes DAX mostrara información desactualizada después de ejecutar "Actualizar todo".
- Se corrigió un error por el que la propiedad `SchemaName` de las particiones de entidad no se podía deshacer.
- La acción de código [DI005 - Reescribir el filtro de tabla como predicado escalar](https://docs.tabulareditor.com/kb/DI005.html) ya no se sugiere cuando se produce la [expansión de tablas](https://www.sqlbi.com/articles/expanded-tables-in-dax/), ya que reescribir un filtro de este tipo como un filtro de columna no necesariamente produciría el mismo resultado.
- Al hacer clic en el botón de puntos suspensivos junto a la propiedad Cadena de conexión, ya no debería producirse una excepción no controlada cuando la cadena de conexión especifica un proveedor OLE DB que no está instalado en el sistema actual.
- Las exportaciones de TMDL ahora excluyen correctamente las particiones de actualización incremental cuando la preferencia correspondiente está habilitada, igual que en JSON.
- Se corrigió un problema por el que, al hacer clic en el botón "Iniciar sesión..." al intentar actualizar o importar desde Dataflows, se mostraba el siguiente mensaje de error en la lista de mensajes: `This page is not normally shown and could be a sign of a phishing attempt.`

## Correcciones de errores en 3.25.1

- Se corrigieron algunas cadenas que indicaban incorrectamente que las reglas BPA integradas solo estaban disponibles para la Edición Enterprise.

## Correcciones de errores en 3.25.2

- Se eliminó la dependencia de PowerShell del instalador .exe (lo que en algunos casos impedía la instalación de Tabular Editor 3)

## Correcciones de errores en 3.25.3

- Se corrigió un error por el que las instrucciones EVALUATE vacías en una consulta DAX provocaban una excepción no controlada.
- Se corrigió un error por el que aparecían excepciones no controladas al pasar el cursor sobre varias referencias de objetos en el editor de expresiones DAX.

## ¿Vienes de Tabular Editor 2.x?

Mira [este vídeo](https://youtu.be/O4ATwdzCvWc) para ver un recorrido rápido por las principales funciones de Tabular Editor 3. Además, asegúrate de consultar nuestra [guía de inicio](https://docs.tabulareditor.com/onboarding/index.html).

**Descripción general de las principales funciones de Tabular Editor 3:**

- IDE totalmente personalizable, con soporte para varios monitores, Hi-DPI y temas
- Nuevo y potente editor de código DAX con autocompletado, comprobación de sintaxis, plegado de código y mucho más
- \*Modo del área de trabajo, que te permite guardar los cambios en el disco y sincronizar los metadatos del modelo con Analysis Services al mismo tiempo
- \*Obtén una vista previa de los datos de las tablas con desplazamiento infinito, crea PivotGrids o escribe consultas DAX para explorar el modelo o probar la lógica de cálculo
- \*Programa actualizaciones de datos
- Actualiza los esquemas de las tablas tanto en Data sources de proveedor como en orígenes de datos estructurados (sí, incluso para consultas M)
- Crear diagramas del Data model
- Crea scripts DAX que te permiten editar varias medidas u otros objetos calculados en un único documento
- Graba C# Scripts y guárdalos como macros (antes conocidas como "Custom Actions")
- Integración con el Analizador VertiPaq
- Depurador de DAX
- Integración con el Optimizador de DAX
- Acciones de código para refactorizar fácilmente tu código DAX.

\*=Solo mientras estés conectado a una instancia de Analysis Services o Power BI
